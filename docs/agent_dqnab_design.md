## 1. 为什么要这个 agent

### 1.1 现状：神经 agent 对 AB 连和棋都拿不到

`docs/agents_design.md` §5.1 / §18.7 记着三组实测：

| agent | 对 ABAgent 深度 4 | 备注 |
|---|---|---|
| PPO+MCTS（80 模拟，等时间 477 模拟） | **0 胜 6 负 0 和**，38 局全被将死 | 加 20 局自对弈热身更差 |
| PPO+MCTS + 2 万局面行为克隆（对 AB 一致率 28%） | **0 胜 19 负 1 和**，得分率 2.5% | 与未训练的 5.0% 同在噪声带内 |
| SAC+AZ-MoE（16 模拟） | **0 胜 8 负 0 和**，全是 mate、平均 28.8 手 | 本仓库本轮实测 |

原因不是"训练不够"这一条就能说完的（见 §6 的缺陷清单），其中最结构性的一条是：

> **这些 agent 的"搜索"是一次性前向的**。PPO/SAC+AZ 的 MCTS 每次模拟只展开一个孩子、
> 用网络直接估叶子；DQN 根本不搜；而 AB 深度 4 是"带静态搜索（吃子序列算到底）+
> 位置价值表的对抗展开"。象棋是尖锐的战术博弈，**一手算漏就掉子**。

### 1.2 反过来看 EVAB：它赢了，靠的不是学习

EVAB（`docs/agent_evab_design.md`）与 AB 同深度 2 胜 2 和 2 负、深一层 1 胜 5 和 0 负。
但它的增益**几乎全部来自搜索**（TT + 迭代加深 + 杀手/历史 + 静态搜索，同深度比 ABAgent
快 21 倍），评估一开始就是**手工评估**（`blend=0` 时它字面上就是"更强的 ABAgent"）。
网络只是叶子评估的一个修正项，而且被 `netHandGap` 门控 + `blend` 阶梯严格约束。

**所以有一条现成的、被实测证明能赢的配方**：

```
强搜索（保证棋理正确） + 手工评估当锚（保证不会比 AB 差） + 神经网络当修正项（门控引入）
```

### 1.3 本 agent 的目标：把"学习"接到这个配方上

EVAB 的网络只学**评估**，而且学到的就是手工评估的近似（实测 `|net−hand| ≈ 0.02`）——
**手写评估的上限就是它的上限**。DQN+AB 想换掉这一点：

* 让网络学 **Q(s,a)**（不只是 V），于是它能表达"某个着法比另一个好多少"；
* 让 **Alpha-Beta 用网络的 Q 排序、用网络的 V 当叶子**去展开 —— 不再需要手工 PST；
* 让 **AB 的展开结果反过来当 DQN 的 TD 目标**（"搜索即目标"），于是搜索改进策略、
  策略改进搜索，而不是"网络模仿手工评估"。

一句话定位：**EVAB 是"强搜索 + 学出来的评估"，DQN+AB 是"强搜索 + 学出来的评估与着法排序，
并且搜索本身是学习目标"**。

## 2. 三个组件各司其职（这是最容易串位的地方）

| 组件 | 正确的角色 | 常见误用（本 agent 刻意避免） |
|---|---|---|
| Dueling DQN | 学 `Q(s,a)`；给 AB 提供**走法排序先验** + **叶子值**；自己**不**决定落子 | 用 ε-greedy 采样当探索（确定性搜索没有熵）；用 Q 的 argmax 直接选根动作（那就是纯 DQN） |
| Alpha-Beta | 推理/采集时的**对抗展开器**：根全宽（带温度采样），内部按 Q 先验选择性展开；顺便产 TD 目标 | 当探索噪声源；用**手工 PST** 当叶子（会和 DQN 的目标打架） |
| 动态棋子价值 | 由**网络条件化输出**：状态里带阶段平面，网络自己学"中局马炮值钱、残局兵升值" | 手工 if-else 改子力权重 |

**AB 本身零探索**：同深度、同排序必出同一手。探索因此有两个来源，都在根节点上：
① 训练/采集时按 `softmax(v_a / T)` 采样（T 从 0.25→1.0 退火，前 8 手）；② 线上探索只做
一次前向取 Q 分布采样（不展开 —— 探索的目的是收集状态分布，不是找最强着法）。

## 3. 编码：规范视角 + 规则上下文（**状态必须严格 Markov**）

| 平面 | 内容 |
|---|---|
| `plane 0..13` | 7 类棋子 × {己方, 对方} one-hot，**规范视角**（轮到谁走，谁的子就在 `x` 大的那一侧） |
| `plane 14` | **子力阶段**：双方非将子力 / 满子（`7.0`），全局标量铺满 90 格 |
| `plane 15` | **回合阶段**：`history.size() / REWARD_MAX_PLIES`，全局标量铺满 90 格 |
| `plane 16` | **无吃子进度**：`halfMoveClock / 120`（60 回合判和的风险） |
| `plane 17` | **重复次数**：`min(repetitionCount,3)/3`（≥3 次就是判和；0.67 = 再重复一次就和） |
| `plane 18` | **将军**：`isInCheck(取景方)`（将军链 / 长将上下文的入口） |

`STATE_DIM = 19 × 90 = 1710`。

**为什么 §3 是"规则上下文"而不是"再加两个特征"**：象棋不是单 agent MDP，而是
**双人零和、完全信息、交替行动的 Markov Game**，而它的**裸棋盘 + 轮到谁并不构成
Markov 状态** —— 下面这些规则全都依赖历史，而它们决定"终局是什么"：

| 依赖历史的规则 | 只看棋盘会怎样 |
|---|---|
| 三次重复判和 | 「本局面第 1 次出现」与「第 3 次出现」棋盘逐位相同、轮次相同，但**价值一个是继续下、一个是 0 和棋** |
| 60 回合无吃子判和 | 同一棋盘、`halfMoveClock` 120 与 0 的价值完全不同 |
| 长将/长捉判负 | 由连续将军/循环段决定（本引擎把它并进"三次重复"判定） |

把这三样（外加"总手数"提供的局面阶段信号）铺成常数平面之后，**状态 → 终局/回报/合法集
是一次函数映射**，Markov 性立刻恢复：V(s) 才真的是 s 的函数，`P(s'|s,a)` 才真的只依赖 s。

**这不是"多喂了点东西"，而是修掉了一个会让 Bellman 备份失效的建模错误**。
`test_dqnab [10]` 把它写成了断言：走一个 4 手可逆循环回到原来的局面，**14 个棋子平面逐位
完全相同**（棋平面差 0.0e+00），但重复平面从 **0.000 → 0.333**；再循环两轮之后
`repetitionCount` 走到 3，`getResult` 判和。同时断言
`repetitionCount() >= 3 ⇔ Chess::isRepetition()` —— 特征的判据必须和引擎的判和判据
**逐字一致**（窗口都取最近 `halfMoveClock` 步），否则网络学的是另一个游戏。

> 顺带记一个"测试工具自己会骗人"的坑：`test_dqnab` 里原来那个 `mirrorBoard`（只交换
> `color` 字段）对**引擎函数**是不成立的 —— `Chess::isInCheck` 是拿
> `&redJiang / &blackJiang` 这两个**对象**取将帅的，只改 color 字段的话镜像之后
> `isInCheck(BLACK)` 看的还是原来那个帅。第一版镜像断言因此"看起来通过了"（局面恰好
> 没人被将军，将军平面两边都是 0），而一旦加上将军平面立刻差 1.0。现在镜像局面改用
> `setupSparse` 按交换后的颜色重摆（id 与 color 自洽），并且**在同一个棋盘对象上用
> 同一个 agent 编码两次**（否则比的是两套随机权重，而不是编码）。

**动作编码**：`fromCell*90 + toCell`（规范格），`ACTION_DIM = 8100`。
与 PPOMCTS 同一套，**双射无碰撞**。对比：DQN / PG / DQN+MCTS / SACAZ 用的
`(id*37+x*13+y*7)%128` 把 2880 种走法挤进 128 格（平均 22 个/槽）。

### 3.1 规范视角给的是**"同一个函数"**，符号在递推里

因为状态是规范视角，`V(s)` 永远表示"**走子方**视角的期望结果"，于是**红黑共用一套
权重**，零和性体现在 negamax 递推的那个负号上：

```
V(s)   = max_a [ −γ·V(s'_a) ]  + r        ← 负号 = "对手会挑对他最好的"
V(C(红, P)) = V(C(黑, flip(P)))            ← 同一个局面换种说法 -> 同一个数
TD 目标 = r − γ·max_a' Q(s',a')            ← 不是单 agent 的 r + γ·max Q
```

**注意这里**：`Q_red(s,a) + Q_black(flip(s), a) = 0` 那种"同一局面两个视角相加为零"的
写法在**本 agent 的规范编码下并不适用**（本 agent 每个状态只有一个视角，就是走子方），
它的正确形式是 `V(C(红,P)) = V(C(黑,flip(P)))`（同一个数）**加上**递推里的负号 ——
设计文档的早期版本把这条写错了，写成了前一种。**实测断言**（`test_dqnab [1] [10]`）：

* 镜像 + 换色后规范编码**逐位不变**（最大逐元素差 `0.000e+00`，含"被将军"的局面）；
* 同一个 agent 对原局面/镜像局面的 V **完全相等**（实测 `-0.285557 == -0.285557`），
  按动作下标对齐后的 Q 最大差 `0.000e+00`；
* **TD 目标的符号是可判定的**：把 A 头清零、V 头钉成 `tanh(20)=+1`（于是 `qStar ≡ +1`），
  `computeTarget` 实测 **`-0.9905`**，而 negamax 口径是 `r − γ = −0.99`、
  单 agent 口径 `r + γ = +0.99` —— 差一个符号的两条路被这个实验**分开了**
  （负号写错照样训练、照样不报错，只能这样测）。

> 这一条也是与"草案"最大的简化：草案里 `leaf = -ab_negamax(...)` 那些符号翻转，
> 在规范视角下就是"对手视角取负"这一件事，写一次就够了。

## 4. 网络与目标

### 4.1 Dueling 双头（V + A）

```
state(1710) → SparseMoE<TB<16,360>, E=4, top-1> → Tanh(64)      [主干 trunk]
                     ↓                      ↓
        [Tanh(64→64) → Tanh(64→1)]   [Tanh(64→64) → Linear(64→8100)]
                 V(s) ∈ (−1,1)                A(s,·) 无界
                     ↓                      ↓
        Q(s,a) = V(s) + A(s,a) − mean_{a ∈ 合法}(A(s,·))
```

* **V 头用 `Tanh`**：奖励是"终局 ±1 + 每步 −0.001 + 至多吃车 0.05"，真值 `|V| ≲ 1.02`，
  有界头顺带挡住"初始 Q 落在 ±8、比奖励尺度大一个数量级"那类缺陷。
* **A 头用 `Linear`**：优势要能取负、也不该被夹住；它支持 `sparseLogits`，于是搜索里
  **每个节点只算合法列**（8100 列里只算 ~44 列，R1 那条捷径）。
* **均值取合法集上的均值**（不是全部 8100 槽）：非法槽位的 A 没有意义，算进基线只会给
  所有 Q 加一个与局面无关的偏移。
* **解析梯度**（写反了不会报错、只会学不动，所以用中心差分钉住）：

```
Q_a = V + A_a − (1/n)Σ_j A_j
∂L/∂V   = dQ                       dL/dQ_a = 2(Q_a − y)
∂L/∂A_a = dQ·(1 − 1/n)             ∂L/∂A_j = −dQ/n  (j ≠ a, 合法)
```

**实测**：与中心差分的最大相对差 **1.7e-05**；非法列的头权重梯度**恰好为 0**。

### 4.2 叶子的两种口径

| `leafEval` | 叶子返回 | 说明 |
|---|---|---|
| `Value`（默认） | `V(s)` | "局面价值"，与 negamax 备份同源，也是用户草案指定的形式 |
| `MaxQ` | `max_a Q(s,a)` | TD 意义上的值，与 DQN 目标完全一致；与 V 差一个 `max_a A` |

### 4.3 TD 目标的两种口径

| `targetMode` | 目标 | 成本 |
|---|---|---|
| `Planned`（默认） | `y = r − γ(1−done)·clamp(planValue(s'), −1, 1)`，其中 `planValue` 是用**目标网**从 `s'` 展开 `trainPlanDepth` 层的结果 | 在**采集时刻**算（每条样本 `1+k` 次前向），**批更新里没有搜索** |
| `OneStepDouble` | 教科书 Double DQN：`a* = argmax_a Q_online(s',a)`（带掩码），`y = r − γ·Q_target(s',a*)` | 训练时 1~2 次前向 |

**为什么标签在采集时刻算**（一个必须讲清楚的取舍）：本工程的稀疏 MoE + TB 专家在
`d=1710`（16 平面时是 1440）上一次前向实测 **2.8~3.3 ms**。若在批更新里现算 planned 目标，每条样本要
`1+k ≈ 6` 次前向 = ~18 ms，batch 32 就是 ~0.6 s **额外**；而采集时刻算，一批更新的成本
就只剩 forward+backward。代价是标签相对当前权重有一点滞后（由目标网每
`targetSyncEvery=64` 次硬拷贝 + 回放池 FIFO 共同界定）。

**帧的一致性**（最易错、也最值钱的一处）：因为 `V(s)` 是"走子方视角"，
`negamax(s', d)` 返回的是"**s' 的走子方**（= 对手）"的值，所以原来的走子方在 `s'` 的值
是它的**相反数** —— 代码里就是那一句 `y = r − γ·planValue`。实测（`test_dqnab` [4]）：
一步杀局面下搜索 8/8 命中，说明这条符号链在"能杀就杀"这个方向上是对的。

## 5. 搜索：Alpha-Beta，深度是**预算**的函数

### 5.1 算法

```
negamax(color, depth, α, β):
    终局 → ±MATE ∓ ply（getResult 覆盖 将杀/困毙/吃将/重复/60 回合）
    命中置换表 → 直接返回（同一棵树内复用）
    合法着法 → 空 → −MATE
    **一次前向** → (V, 每个合法着法的 Q)
    depth == 0 → 返回 V(s)          （leafEval=MaxQ 时返回 max Q）
    按 Q 降序排序 → 只展开前 branch 个（branch 随合法着法数自适应）
    标准 α-β 窗口 + β 截断；预算耗尽则软中止
```

根节点**全宽 + 全窗口**：每个合法着法都拿到一个有意义的搜索值 `v_a`。
* 不做 α 截断，是因为 `v_a` 还要供 `softmax(v_a/T)` 采样与诊断用 —— 被截断的
  fail-low 值全都退化成 ≈α，那个分布就废了；
* 深度由 `nodeBudget` 控制（迭代加深，搜不完的那层不用）。

### 5.2 为什么深度不能写死（与草案的偏差）

草案假设"小网络做叶子推理微秒级 → 可以搜 6~12 层"。本工程的**稀疏 MoE + TB 专家**
一次前向是 **2.8~3.3 ms**，而 AB 每个节点都要一次前向，于是：

| 骨干 | 每节点 | `nodeBudget` | 实测节点/步 | 实测到达深度 | ms/步 |
|---|---|---|---|---|---|
| **稀疏 MoE + TB（默认）** | 2.8–3.3 ms | 256 | 257 | **2.5** | 867 |
| 稀疏 MoE + TB | 2.8–3.3 ms | 512 | 513 | 2.5–3.0 | ~1700 |
| MLP（对照） | ~0.03 ms | 4096 | 3684 | **4.4** | 93 |

"开局宽分支浅、残局窄深"由**分支数随合法着法数自适应**实现（`branch = clamp(2, legal/8, 5)`）：
宽局面只展开前几个，窄局面相对展开更多，于是同一个预算下残局自然更深。
**深度不再是常量，而是预算的函数**，并且随骨干自动伸缩（换 MLP 骨干能搜 4~6 层）。

## 6. 训练流程

```
自对弈一局:
  每手:
    根全宽搜索 → softmax(v_a/T) 采样落子 (T 退火; 前 8 手探索, 之后贪心)
    落子后立刻用**目标网**从 s' 展开 trainPlanDepth 层 → 算出这条样本的 TD 标签
    样本进回放池 (稠密 state/nextState + 合法集 + 奖励 + done + 标签)
    每 learnEveryMoves 手: 批更新
批更新 (learnBatch):
  每个 epoch 重新抽 batchSize 条 (与 RL::PPO::learnFromReplay 同一做法)
  逐样本: 主干一次前向 + V 头 + A 头稀疏列 → 解析梯度累积 (P3)
  批末: 一次 RMSProp + 一次 MoE 负载均衡辅助损失 + 目标网每 64 次硬拷贝
```

* **掩码**：合法集贯穿始终 —— Q 只在合法集上算、softmax 只在合法集上归一（Z≡1）、
  非法列梯度恰好为 0。
* **目标网硬拷贝**（不是 `tau=0.01/每 256 次` 那种"事实上冻结"的软更新，
  见 `issues_review.md` 的 2.7）。
* **稀疏 MoE 的负载均衡辅助损失**（系数 0.1）必须接上，否则 top-1 路由会在几轮内坍缩。
* **探索**：训练时根节点按 `softmax(v_a/T)` 采样；线上探索只取一次前向的 Q 分布采样
  （不展开）。

### 6.1 为什么**不做**势能塑形（PBRS）

PPO 用 `Φ = tanh(evaluatePositional/2)` 做势能塑形，把 `|value target| > 0.1` 的样本占比
从 0% 抬到 55–63%。**但这里不能用**：要求是"叶子是纯终局预期"，而 PBRS 的作用正是把 Φ
平移进价值目标（`V+Φ`）——"叶子纯"与"目标里含 Φ"不可能同时成立，叶子 V 学成什么样它就
评估什么。所以奖励就是 `stone.h` 的 `stepReward + 终局 ±1`（与其它 agent 同量纲），
中期的位置信息由**规划器**（AB 展开）提供，而不是由奖励塑形提供。

## 7. 实测（全部可复现）

### 7.1 机制（`test/test_dqnab_main.cpp`，**115 项断言**，24.5 s）

| 断言 | 实测 |
|---|---|
| 镜像（左右翻转 + 交换红黑）后规范编码逐位不变 | 最大差 **0.000e+00**（含"被将军"的局面） |

### 7.2 对局（`test/bench_dqnab_vs_ab_main.cpp`，随机权重、同 seed、交换先后手）

| 配置 | 比分 | 得分率 | 平均手数 | ms/步 |
|---|---|---|---|---|
| 关掉搜索（`--pure-q`，纯 Q-argmax） | 0 胜 4 负 0 和 | 0% | 22.0 | 4 |
| **TB 骨干 + 256 节点（深度 2.5）** | **0 胜 2 负 2 和** | **25%** | **44.2** | 867 |
| MLP 骨干 + 4096 节点（深度 4.4） | 0 胜 4 负 0 和 | 0% | 24.0 | 93 |

**三条结论**：

1. **规划头确实有用**：同一个网络、同一个 seed，只把搜索关掉就从"2 和 2 负"变成"4 负"。
   这是本工程**第一个对 AB 拿到和棋的神经 agent**。
2. **但"搜得更深"在随机价值函数下反而更差**：MLP 骨干搜到 4.4 层却 0 胜 4 负，
   比只搜 2.5 层的 TB 骨干差 —— 叶子是**没训练过的** V，深搜把它的误差放大了
   （搜索放大评估误差，经典现象）。**"深度 6~12 层"的前提是叶子已经准了。**
3. 权重是随机初始化的，所以这些数字**不是棋力**。

### 7.3 已实现的第一级：手工锚 + 门控（`pretrainValueFromHand` / `netHandStats`）

第 2 条结论直接指出该做什么：**先把 V 训准，再谈深度**。照 EVAB 那条被实测证明有效的
配方做了三件事（实现见 `src/dqnabagent.cpp` 的 "手工评估锚" 一节）：

1. **手工锚**：`handEval(color) = tanh((红方 ? −evaluate() : evaluate()) / 3.0)`。
   `evaluate()` 是**黑方视角**，而本 agent 的 V 是**走子方视角**，所以要按走子方取号；
   `/3.0` + tanh 与 EVAB 的 `EVAL_SCALE` 完全同一口径，两边的手工锚可以直接互换对照。
2. **探针尺子** `netHandStats(n)`：从当前局面随机走子取 n 个局面（走完**逐字段还原棋盘**），
   给出 `gap = mean|V − 锚|`、`corr = Pearson(V, 锚)`、`anchorStd`、`vStd`。
3. **预训练 + 门控**：
   * `pretrainValueFromHand(positions, maxPlies, batchSize, epochs, pretrainTrunk)`：
     造 positions 个局面，标签就是锚，MSE 回归 V（可选是否连主干一起训）。
     结束时若 gap 比训练前更差（> `pretrainTolerance=0.01`）就**整段回滚**。
   * `learnBatch` **每次在线更新前后各测一次 gap**，单次更新把 gap 顶高超过
     `gateToleranceNow()` 就回滚权重（并重新同步目标网）。这是 EVAB 的
     `netHandGap > gapBefore + 0.05` 机制的直接移植。

**这一节的绝大部分内容不是设计出来的，是量出来的 —— 而且第一版几乎全错。**
按发现顺序记下来（每一条都有数字）：

1. **阈值不能照抄 EVAB 的 0.05**：照抄的结果是 `test_dqnab [5]` 的固定目标学习被
   **整体冻结** —— 60 次更新全被回滚，Q 一动不动（误差 0.909 → 0.909）。
2. **阈值不能是固定值**：改成固定 0.25 之后仍然回滚了 **59/60** 次，因为
   `Optimize::RMSProp` 的 clipGrad 把每个张量的梯度整成单位 L2 范数
   （`optimize.h:52` `dw /= dw.norm2()+1e-8`），于是**每次更新的位移 ≈ lr** ——
   "一次更新合法能顶多高"与 lr 成正比。现在的 `gateToleranceNow()` 按 `lr/0.001` 缩放，
   同一测试变成**回滚 0 次**。
   门控的正确语义是"**单次**更新不许把 V 打飞"，**不是**"V 不许离开手工锚" ——
   后者会永久禁止 V 变得比手工锚更好，而那正是 RL 存在的意义。
3. **造数据的入口也必须还原棋盘**：EVAB 的 `pretrainFromHandEval` 直接 `chess.reset()`
   并把棋盘留在初始局面（它只被独立的预训练脚本调用）。本 agent 的预训练可能在任何时候
   被触发，所以内部走"快照 → 随机走子 → 逐字段还原"（棋子 alive/pos/type/color、
   `m_map`、`sideToMove`、`halfMoveClock`、`history`），并把这条写成了断言。
4. **⚠ 最严重的一条：第一版的"进步"是假的，因为标签几乎没有信号。**
   照抄 EVAB 的造数据方式（从初始局面**纯随机**走 ≤12 手）时，双方几乎永远吃不到子，
   所有局面的 `evaluate()` 几乎一样 —— 实测**手工锚的标准差只有 0.0074**（≈ 常数）。
   在这种标签上训练网络只能学到"输出均值"：MLP 骨干 gap **0.1698 → 0.0262**（看起来
   进步 6.5 倍！），而同一批探针上的 **corr 从 −0.504 到 −0.547** ——
   **一点点都没学到**，只是把 V 的方差收缩掉了。
   修法：造数据时加**吃子偏置**（`probeCaptureBias=0.5`，有吃子就以 50% 概率走吃子）。
   修完（MLP，512 局面 × 3 遍，0.33 s）：锚标准差 **0.0074 → 0.2228**，
   **corr −0.305 → 0.938**，V 的标准差 0.0294（不再是常数）。
5. **gap 本身不能单独用**：把 V 头的输出层直接清零（= 什么都没学到的常数 V），
   它的 gap 是 **0.0740**，而"训练过的"网络是 **0.0710** —— 差 0.003，
   单看 gap 完全分不出来。corr 在常数 V 上**恰好等于 0**。所以 bench 的 VERDICT 行
   同时打 gap 与 corr（`test_dqnab [9]` 把这条写成了断言）。
   还要一起看 `vStd`：实测 MLP 骨干随机初始化时 **corr 0.951 而 vStd 只有 0.0072** ——
   依赖方向对、幅度几乎没有 ⇒ 叶子值近乎常数 ⇒ 搜索照样是瞎的。**高 corr 不等于有用**。
6. **12 个探针太少**：同一句"12 个随机局面"，锚标准差在不同 seed 下是 0.0365 ~ 0.2228
   （差 6 倍），于是"这次更新让 gap 变差了吗"是在噪声上判的 —— TB 骨干的一次预训练
   就因此被误判而回滚。现在门控用 **24** 个、预训练用 **64** 个。
7. **骨干越大，手工锚预训练越难**：MLP 骨干 512 局面 × 3 遍 = corr **0.938**（0.33 s），
   而 TB 骨干 512 局面 × 2 遍（1024 个样本喂 37.45 M 参数的主干）= 根本没动，
   被 `pretrainTolerance` 拦下并整段回滚（35.3 s 白跑）。
   同一 TB 骨干换成**冻结主干只训 V 头**（`pretrainTrunk=false`）：
   512 局面 × 3 遍 = corr **−0.199 → 0.893**，只要 **6.8 s**。
   ⇒ **TB 骨干上的正确用法是 `--pretrain-head-only`**（见 §10 的复现命令）。

| 2 | TB + 1024 节点（**只把搜索加深**） | 0 胜 4 负 0 和 | 0% | 51.5 | **4.10** | gap 0.0410 |
| 3 | TB + 256 + 预训练（**坏标签那一版**，没回滚） | 0 胜 4 负 0 和 | 0% | 31.5 | 2.55 | gap **0.0814** |
| 4 | TB + 256 + 预训练（冻结主干，512×3，corr 0.136） | 0 胜 4 负 0 和 | 0% | 37.0 | 2.32 | gap 0.0757 |

| 6 | MLP + 4096 + **真正训成的** V（8192×3，corr 0.869，vStd 0.091） | 0 胜 4 负 0 和 | 0% | 24.0 | 4.81 | gap 0.0671 / corr 0.869 |

| 9 | MLP + 4096 + 预训练，**8 局**（corr 0.474） | **0 胜 8 负 0 和** | 0% | 19.2 | 4.37 | gap 0.0860 |

**第 7/8 行是一次干净的消融**：`--no-rule-planes` 把 3 个规则平面**置零**而不是省掉 ——
输入维度 1710 与随机初始化**逐位相同**，唯一变量就是"状态里有没有规则上下文"。
（对比 1440 与 1710 两种维度是**不干净**的：那同时换了输入维与初始化。）
结果：**比分一模一样（都是 0 胜 8 负），只有存活手数不同（48.5 vs 25.8）**。
也就是说 —— **补全 Markov 状态修的是"建模错误"，不是"棋力"**；在这个网络还随机初始化
的场景下，规则上下文唯一看得见的后果是它对**搜索深度**的影响（3.06 层 vs 2.21 层：
同样的节点预算下，V 的差异会改变分支排序，从而改变到达的深度）。
一局棋的存活手数是混沌轨迹上的**单个样本**，不能当成"规则平面让棋力提升 88%"。

> "手工锚"那一列**只有同一块内的数字互相可比**：第 1–4 行是 **12 个探针**时量的
> （那会儿还没发现"12 个太少"），第 5–6 行是 **24 个**。比分/手数/深度不受影响 ——
> 搜索与探针无关，同 seed 复跑第 1 行得到逐位相同的 `0 胜 3 负 1 和 / 54.2 手 / 2.99 层`
> （探针虽换成 24 个，搜索仍然确定）。

**五条结论（都不该过度解读）**：
1. **"深搜"在叶子没训准之前是负收益 —— 这次是同一骨干内的配对证据**：
   第 1 行 256 节点（2.99 层）拿到 12.5%（1 和），第 2 行 1024 节点（**4.10 层**）
   变成 0%（0 和）。唯一的变量是 `nodeBudget`。这与 §7.2 里"MLP 4.4 层输得更多"
   相互印证，也解释了为什么草案里"搜 6~12 层"的假设在本工程不成立。
2. **V 偏离手工锚的代价是直接的**：第 3 行把 V 从 gap 0.041 推到 0.081（那一版
   没有回滚阈值），同一 seed 下从"1 和"变成"0 和"，平均手数 54.2 → **31.5**
   （死得更快）。这是"叶子质量 → 棋力"最直接的一次对照。
3. **"corr 高"也救不了**：第 5 行 MLP 骨干的 V 与锚 corr 0.951，却 0 胜 4 负、
   只撑 24 手 —— 因为 **vStd 只有 0.0072**（叶子值几乎是常数，搜索没有区分度）。
   ⇒ 尺子必须同时看 gap / corr / vStd 三个数，任何单看一个都会骗人（见 §7.3 第 5 条）。
4. **⚠ 即使 V 真的训成了（corr 0.869、vStd 0.091），也赢不了 AB —— 这是本次优化最
   重要的负面结论**：第 6 行把 V 训到"与手工评估高度一致"，MLP 深搜（4.81 层）
   依然是 0 胜 4 负 0 和，与随机权重时的第 5 行**一模一样（都是 24.0 手）**。
   道理其实很硬：**蒸馏手工评估的上限就是手工评估本身**，而对手 ABAgent 深度 4
   用的是**同一个** `evaluate()`，并且是**全宽**搜索。一个"手工评估的有损模仿"
   （网络回归只能做到 corr 0.87）+ 选择性展开（每个内部节点只展开 2~5 个分支）
   当然赢不过"同一个评估 + 全宽 + 4 层"。
   ⇒ **手工锚只能当起点（避免叶子是垃圾），它不是棋力的来源。**
   要超过 AB，网络必须学到手工评估**没有**的东西（终局胜负的真实概率、
   吃子序列、位置性知识），也就是必须走自对弈 + TD 那条路。
5. 权重仍然是**随机初始化 + 手工锚预训练**（没有自对弈、没有 TD 更新），
   所以这些数字**不是棋力** —— 它们量的是"叶子质量对搜索的影响"。
6. **汇总一句（回答问题"与 AB 对弈有没有提升"）**：到目前为止，DQN+AB 对
   ABAgent 深度 4 打了约 50 局（多种配置、两个骨干、两种维度），**0 胜 / 1 和**；
   唯一那一和来自第 1 行（1440 维、随机权重、4 局的那个样本，12.5%）。
   本轮的每一项改动（手工锚、门控、补全 Markov 状态）都**没有**在这张表上产生
   可测量的提升 —— 而且这是**可以被预测的**：这些对局里网络**从来没有从胜负里学过**
   （权重要么随机、要么是从手工评估蒸馏来的），于是天花板就是手工评估本身，
   而对手用的是同一个 `evaluate()`、而且是**全宽**搜索。
   ⇒ 要谈"提升"，前提是让 V 从终局信号里学（自对弈 + TD + 对手池），
   而不是继续改编码/锚。

**样本量与"假进步"的实测（同一 seed、同一批 64 个探针）**：

| MLP 预训练规模 | 结果 | 说明 |
|---|---|---|
| 512 局面 × 3 遍 | **回滚** | 被拒的那次：gap 0.0746 → **0.1442**（变差），corr 0.433 → 0.529（略升），**vStd 0.0070 → 0.0960（涨 13 倍）** |
| 2048 局面 × 3 遍 | **回滚** | 同上（1.5 s） |
| **8192 局面 × 3 遍（≈25k 样本）** | **接受** | gap 0.0746 → **0.0671**，corr 0.433 → **0.869**，vStd 0.0070 → **0.0907**（6.4 s） |
| TB 骨干（冻结主干）4096 局面 × 3 遍 | **回滚** | 被拒的那次：gap 0.1536 → 0.2132，corr 0.161 → **−0.171**（方向都错了），40.4 s |

读法：**样本不够时的失败模式不是"没学到"，而是"幅度膨胀"** —— corr 甚至略微上升，
但 vStd 涨了一个数量级，于是叶子值被放大成搜索里的主导项。这正是 gap 回滚要拦的东西
（它拦的是"离锚太远"，不管方向对不对）。而**接受**的那一档是 corr 与 gap **同时**改善。

**下一步的杠杆（按证据强度排序）**：

1. **让 V 学到锚之外的东西**（第 4 条的直接推论）：自对弈 + planned/TD 目标
   （`--warmup-games`）—— 手工锚只保证起点不瞎，棋力必须来自终局信号。
2. **quiescence**：叶子接一段"吃子到底"的静态搜索。AB 的优势有一半来自它不在
   吃子序列中间停手（叶子是静止局面），而本 agent 的叶子直接调 V。
3. **尺度校正的回归目标**（第 3 条）：既然失败模式是幅度膨胀，把预训练目标按锚的
   标准差归一化（或直接对 z-score 回归），可以让小样本也训得稳。
4. **然后才是深度**：在 (1)(2) 之后重做 §7.4 第 1 行/第 2 行那种配对，看深度收益
   是否翻正。

## 8. 已知限制与未做的事

1. **没进后台训练线程**：与 EVAB / SAC+AZ 一样只走"走子前探索 + 在线更新"
   （TB 骨干建网 ~0.9 s、每步 0.8 s，塞进"每轮 1 局"的后台循环会把单轮拖到分钟级）。
2. **没有对手池 / league**：`--pure-q` 只是配对对照，不是 league。
3. **planned 标签在采集时刻算**：批更新里没有搜索（成本取舍，见 §4.3），代价是标签滞后。
4. **回滚只回权重、不回优化器状态**（RMSProp 的 `v` 不跟着回退）—— 与 EVAB 同样的限制。
   （实测影响：回滚后紧接着那一两步的步长偏小，不是方向性错误。）
5. **手工锚预训练目前还不够可靠**：同一个 MLP 骨干、同一个 seed，
   512 局面 × 3 遍和 2048 × 3 遍都被回滚，要到 **8192 局面 × 3 遍（≈25k 个样本）**
   才在**留出的探针集**上被接受（corr 0.433 → 0.869）—— 也就是说"手工锚回归"
   是一个**样本量敏感**的机制，小样本看起来在降 gap，其实只是把 V 压成常数。
   `pretrainValueFromHand` 的回滚把这种假进步挡住了（不会悄悄留下更差的 V），
   但"怎么用更少的样本训出 V"这个问题**还没解决**，见 §7.4 的下一步。
6. **没有 quiescence（静态搜索）**：叶子是纯 `V(s)`。这在"叶子已经准"之后是下一个该做的
   战术补强（吃子序列算到底），但在叶子没训准之前加它只会更贵。
7. **没有换位表复用跨步**：TT 每步清空（保守；跨步复用的收益与失效条件需要单独验证）。
8. **没有时间控制**：预算固定，不按局面/时间自适应。
9. **门控只在 `learnBatch` 上生效**：预训练自己有独立的回滚判据（`pretrainTolerance`），
   但 `trainSelfPlay` 里的自对弈采集不经过门控（它不更新权重）。

## 11. Markov 性 / 零和性检查清单（逐条对照代码）

| # | 要求 | 状态 | 证据 |
|---|---|---|---|
| 1 | 状态里要有重复栈 / 无吃子计数 / 将军上下文，不能只喂 90 格 | ✅ **已做** | `PLANE_HALFMOVE` / `PLANE_REPEAT` / `PLANE_CHECK`（§3）；`test_dqnab [10]` 断言"棋平面相同、重复平面不同" |
| 2 | V 输出**当前方视角**标量；对另一方要取负 | ✅ 已做（编码层面） | 规范视角 + `test_dqnab [1][10]`：镜像+换色后编码逐位相同、V 完全相等（`-0.285557`） |
| 3 | DQN 目标 = `r − γ·max_a' Q(s',a')`，不是单 agent 的 `max` | ✅ **已做且有符号实验** | `computeTarget` 的 `OneStepDouble` 分支；`test_dqnab [10]`：`Q≡+1` 时实测 **−0.9905**（对照单 agent 口径 +0.99） |
| 4 | PBRS 势能要零和对称（`Φ_red(s) = −Φ_black(flip(s))`），终局 z 按当前方视角 | ✅ 适用但**本 agent 不用 PBRS** | §6：奖励只有 `stepReward + 终局 ±1`，终局用 `outcomeForMover`（`stone.h`）；没有 Φ，也就没有 Φ 的符号问题 |
| 5 | 探索要翻译成"根噪声"，不是单步 ε-greedy | ✅ 已做 | `selectMove(color, temperature)`：**根全宽**评估后按 `softmax(v_a/T)` 采样，温度沿对局退火（`exploringTempRoot/Final`）；`exploreAndTrain` 的 pick 用根 `softmax(Q/0.7)` |
| 6 | 值迭代 / Bellman 备份适用 | ✅ 已做 | `negamax()`（`val = −child`、`-beta/-alpha` 传递）；planned 目标用目标网从 s' 展开后再取负 |
| 7 | 动作掩码 = 受限动作集，非法位不许进 softmax/Q 基线 | ✅ 已做 | `legalMoves` 只生成合法着法；Dueling 的 `mean_A` 只在**合法集**上取均值；非法列的头权重梯度**恰好 0**（`test_dqnab [3]`） |

**清单之外、本轮暴露出却仍未做的事**（不许含糊过去）：
1. **self-play 的非平稳性没有对策**：`targetMode=Planned` 的标签由**目标网**算，而目标网
   每 `targetSyncEvery=64` 次更新硬拷贝一次 —— 这是"对手在变"的唯一缓冲。
   **回放池没有任何对手池/重要性修正**，池里最老的样本（4096 条 FIFO）可能来自几百次
   更新之前的策略。按 Markov Game 的说法，这违反的不是 Markov 性而是**平稳性**：
   需要"近期数据优先采样 + 按策略版本加权"，本 agent 都还没有。
2. **`Planned` 目标里的折扣是单步的**：`y = r − γ·planValue(s')`，而 `planValue` 是
   `trainPlanDepth` 层搜索的值。搜索内部已经按 negamax 翻号，所以口径自洽；
   但**用搜索值当单步 TD 目标**在理论上是 TD(λ) 的一个粗糙近似（把多步回报塞进一步），
   偏差与 `trainPlanDepth` 强相关，这一点没有量过。
3. **门控只保护"V 不被打飞"，不保证 V 变准**：§7.3 第 5 条已经量到
   "corr 高 + vStd ≈ 0"这种假象；目前没有"vStd 必须非零"的守门人。

```bash
# 机制测试（进 ctest）
cmake --build <build> --target test_dqnab && <build>/test_dqnab

# 对局 + planning head 的配对 A/B   (全部同 seed=20240901 / 4 局 / ≤100 手 / 交换先后手)
cmake --build <build> --target bench_dqnab_vs_ab
<build>/bench_dqnab_vs_ab --games=4 --plies=100 --budget=256                        # 第 1 行基线 (0/3/1)
<build>/bench_dqnab_vs_ab --games=4 --plies=100 --budget=1024                       # 第 2 行: 只把搜索加深 (0/4/0)
<build>/bench_dqnab_vs_ab --games=4 --plies=100 --budget=4096 --backbone=mlp       # 第 5 行: MLP 深搜 (0/4/0)
<build>/bench_dqnab_vs_ab --games=4 --plies=60 --budget=256 --pure-q                # 关掉搜索的对照
<build>/bench_dqnab_vs_ab --games=4 --plies=100 --budget=4096 --backbone=mlp \
        --pretrain=8192 --pretrain-epochs=3                                         # 第 6 行: 真正训成的 V

# 手工锚预训练本身的量法 (只跑 2 局、2 手, 目的是读它打印出来的 gap / corr / 锚标准差)
<build>/bench_dqnab_vs_ab --games=2 --plies=2 --budget=8 --backbone=mlp \
        --pretrain=8192 --pretrain-epochs=3     # MLP: 8192 局面才被接受 (corr 0.433 -> 0.869)
<build>/bench_dqnab_vs_ab --games=2 --plies=2 --budget=8 --backbone=tb \
        --pretrain=4096 --pretrain-epochs=3 --pretrain-head-only   # TB: 用冻结主干这条路
```

**怎么读这些输出**（三个数必须一起看）：`gap` 是"离手工锚多远"（**常数 V 的 gap 也小**，
所以它不能单独证明 V 学到了东西）；`corr` 是尺度无关的相关性（**常数 V 恒为 0**，
但"corr 高 + vStd ≈ 0"说明依赖方向对、幅度没有）；`锚标准差` 是这把尺子本身有多少信号
（**只有 0.0074 时整个测量都是噪声**，见 §7.3 第 4 条）。
`[已回滚]` 后面那行"被拒的那次"是**回滚前**的数值 —— 它才是诊断"样本量够不够"的关键。

## 12. 这套设计的公共化与推广（2026-09，第四轮）

§3 的那套东西（规范视角、规则上下文、动作双射、终局口径）已经**抽成一份公共实现**
`src/chessstate.h`，并被推广到其它 agent（PPO+MCTS、SAC+AZ、EVAB），
推广过程、证据、以及"哪些**没有**推广（连同理由）"都在
**`docs/agents_design.md` §20**。本文件只留三条与本 agent 直接相关的结论：

1. 本 agent 的编码/镜像/规则口径现在**调用公共件**（不再自带一份）—— 语义没变，
   `test_dqnab` 的 115 条断言是这次重构的回归网（含棋子平面约定的显式钉住：
   下标 = `type*2 + (是己方?0:1)`，与 PPO 和公共件一致）。
2. 改任何 agent 的 `STATE_DIM` 之前先看权重格式的**维度守卫**（`src/rl/net.hpp`）：
   v2 的"结构指纹"只哈希层类型、不含维度，没有守卫的话旧文件会被**静默换成另一个形状**。
3. `test_dqnab [5]` 的学习判据改成"默认 lr 下的两臂配对 + 收敛"，并把量到的
   **lr=0.02 会进入周期 2 极限环**（loss 在 0.006 与 1.31 之间逐次跳）写进注释 ——
   原来那条"训练后 Q 靠近目标"的断言就是靠运气通过的（换一次平面排列就翻脸）。
