# EVAB Agent 设计：学会评估的 Alpha-Beta（EV + AB）

> 目标：在现有代码已支持的模型范围内，做一个**比现有 6 个 agent 都强**的象棋 AI。

---

## 一、先看现有 agent 为什么都不强

| Agent | 模型 | 决策方式 | 结构性瓶颈 |
|-------|------|----------|------------|
| `ABAgent` | 无（手工评估） | Alpha-Beta + MVV-LVA + 静态搜索 | 评估是**线性求和**（材质 + PST），学不到子力配合；无置换表、无迭代加深；叶节点口径不全 |
| `MCTS` | 无 | UCB1 + **随机**回放 | 随机回放的方差极大，800 次模拟的信息量远不如同代价的 alpha-beta |
| `PGEagent` | `DPG`（REINFORCE + baseline） | 单步策略网络，**不搜索** | 90 维"子力值"状态 + 128 维**哈希**动作空间；无搜索 → 一步看不清 |
| `DQNAgent` | `DQN`（`MOE`+`TransformerBlock`） | argmax Q，**不搜索** | 同上；且 Q 头是 `Sigmoid`，无法表示负 Q（见 issues_review B18） |
| `PPOMCTSAgent` | `PPO` + MCTS | PUCT，价值头替代随机回放 | 策略/价值来自 90 维状态；动作是哈希索引 |
| `DQNMCTSAgent` | `DQN` + MCTS | 同上 | 同上，且探索率恒为 1.0 时退化成随机走子 |

两个共同的、**根本性**的问题：

1. **状态表达太弱**：`state[i*9+j] = ±棋子值/7`，90 个数。棋子**类型**被压成一个标量值，
   车和马在某些编码里数值相同（`PIECE_VALUES` 里 `TYPE_MA=2`、`TYPE_PAO=3` 倒是有区分），
   但同一格上"谁在哪"的棋盘结构、以及"哪一方的哪个兵过了河"这类信息被挤在一个通道里。
2. **动作空间是哈希**：`actionIdx = (id*37 + x*13 + y*7) % 128` —— 象棋几百种走法被塞进
   128 个桶，**必然碰撞**。策略网络学的是"桶"，不是"走法"。这一条几乎单独解释了为什么
   PG/DQN 训练很久也没有起色。

所以"更强"不该继续在这个框架里加层数，而要换一个**结构正确**的骨架。

## 二、设计主张：把学习放在"评估函数"上，而不是放在"走子策略"上

这是经典棋类引擎（Giraffe、以及后来 AlphaZero 的"策略先验只用于剪枝排序"）给出的结论：

> 在算力有限的前提下，**同一份算力花在"更深的搜索 + 更准的叶子评估"上，比花在
> "端到端学一个策略网络"上回报高得多。**

因此 EVAB 的骨架是：

```
        ┌─────────────────────── 搜索 (博弈论保证正确性) ───────────────────────┐
        │  迭代加深 → 置换表 → 杀手/历史启发排序 → Alpha-Beta → 静态搜索          │
        └───────────────────────────────┬──────────────────────────────────────┘
                                        │ 叶子
                     ┌──────────────────┴───────────────────┐
                     │  学习评估: tanh(手工评估/S) 与 价值网络 的加权混合  │
                     │  v = blend·net(s) + (1-blend)·hand(s)              │
                     └────────────────────────────────────────────────────┘
                                        │ 训练信号
                     ┌──────────────────┴───────────────────┐
                     │  自对弈 + TD-leaf: 标签 = 自身搜索的根评分        │
                     │  （终局用真实胜负做无偏锚点）                  │
                     └───────────────────────────────────────┘
```

三个要点：

1. **搜索负责"不出错"**：合法性、将杀、困毙、重复局面、和棋都由引擎和搜索保证，
   这些是不需要学的、也不该让网络去猜的东西。
2. **网络负责"看得准"**：把线性求和换成一个小型非线性网络，让它学材质/PST 之外的
   **子力配合**（例如"双车同线""马炮配合""缺士怕车"这类交互项）—— 这是线性评估在
   原理上学不到的部分。
3. **blend 让"更强"可验证、可回退**：`blend = 0` 时叶子评估就是原来的手工评估，
   于是 EVAB 退化成"ABAgent + 置换表 + 迭代加深 + 更好的排序"，**天然不弱于 ABAgent**；
   `blend` 随训练从 0 爬到 1，网络接管评估。任何一步变差都能通过调回 blend 定位。

## 三、状态编码：14×90，规范视角（Canonical Perspective）

```
input: 14 个平面 × 90 格 = 1260 维
plane 0..6   : 当前走棋方  的 车 马 炮 兵 将 仕 相
plane 7..13  : 对手        的 车 马 炮 兵 将 仕 相
cell (x,y)   : x*9 + y
```

* **规范视角**：轮到黑方时把棋盘上下镜像（`x → 9-x`）并交换"己方/对手"两组平面。
  这样网络只需要学**一个**函数：`v(s) ∈ (-1,1)` 恒等于"当前走棋方视角的价值"。
  直接好处是训练样本翻倍（同一局面的红方视角与黑方视角互为镜像样本），
  而且搜索里的视角转换不再需要网络自己处理。
* 与旧的 90 维相比：棋子类型从"一个标量值"变成**独立通道**，双方也分开 ——
  网络能区分"我的兵"和"对方的兵"，能学到"过河兵"和"没过河兵"的不同价值。

## 四、网络结构（只用现有 `RL::` 组件）

```cpp
valueNet = RL::Net(
    RL::Layer<RL::Tanh>::_(1260, 48, true, true),   /* 隐藏层, 学交互项 */
    RL::Layer<RL::Tanh>::_(48, 1, true, true));     /* 输出 ∈ (-1,1) */
```

* 1260→48 = 60k 权重的 GEMV，正好走上一轮加好的 **SIMD GEMV 快路径**（0.1 ns/MAC，
  一次评估约 6 µs），比一个卷积/Transformer 评估便宜两个数量级 —— 这是"评估网络能
  塞进 alpha-beta 内层循环"的前提。
* 训练用 `RL::Loss::MSE::df` + `Net::RMSProp`（mini-batch：逐个样本 forward/backward
  累积梯度，最后一次 `RMSProp` 更新）。
* 评估值空间与搜索值空间统一为 `(-1,1)`，终局用 `±MATE(=1000)` 表示，
  这样 alpha-beta 的"将杀优先于一切"仍然成立（`MATE - ply` 保证越早将杀越好）。

物品评估的归一化：`hand(s) = tanh(evaluate()/S)`，`S = 3.0`。理由：手工评估里
帅=1000 是"输棋"的量级，`tanh` 会把它压到 1；而正常的子力差（车 0.5）压到约 0.16，
量级与网络输出一致，两者才能线性混合。

## 五、搜索（比 ABAgent 多出来的四样东西）

| 机制 | 作用 | 为什么值得 |
|------|------|------------|
| **Negamax 形式** | 统一视角，只有一套边界逻辑 | ABAgent 的 MIN/MAX 双函数 + "形参名与实际含义相反"是它出过多次 bug 的地方 |
| **置换表（TT）** | 同局面不同路径只算一次 | 象棋里换位极多；实测节点数下降明显 |
| **迭代加深（ID）** | 每层用上一层的根走法先试 | 排序质量提升 + 天然时间控制（超时就用上一层结果） |
| **杀手 + 历史启发** | 安静走法也有排序依据 | ABAgent 只对吃子排序，安静走法的顺序等于随机 |
| **静态搜索** | 叶子继续搜吃子 | ABAgent 已有，这里保持，并统一在 negamax 框架里 |

**TT 的正确性保障**：`Chess::computeHash()` 是异或哈希，强度不足以单独信任，所以
TT 里存的是**具体走法**（`id/from/to/nextId`），使用前必须在新生成的合法走法列表里
匹配上才用；匹配不上就当没有。这样哈希碰撞最多损失一点排序质量，不会产生非法走法。

对杀棋的 TT 分数要做 `ply` 修正（否则同一局面在不同深度被当作等价的"杀"）。

## 六、训练算法：TD-leaf 自对弈 + 引导阶梯

```
blend = 0                        # 初始: 纯手工评估 (= ABAgent 的能力下限)
repeat round = 1..R:
    # 1) 自对弈采样, 每步记录 (状态, 走子前搜索的根评分)
    for game in 1..G:
        重置棋盘
        for move in 1..maxMoves:
            if 探索掷骰命中: 随机选一个合法走法      # 保证数据多样性
            else:           search(depth = D_play)
            记录 (canonical_state, 根评分, 行棋方)
    # 2) 生成标签
    for 每个样本:
        target = outcomeWeight * 对局结果(从该样本行棋方视角) +
                 (1-outcomeWeight) * 搜索根评分
        # 根评分本身已经 ∈ (-1,1) (或 ±MATE → 截断到 ±1), 所以无需再归一化
    # 3) 训练一轮 (mini-batch MSE)
    net.train(samples)
    # 4) 引导阶梯: 让网络逐步接管评估
    blend = min(1, blend + blendStep)
```

为什么标签用**自身搜索的根评分**（TD-leaf）而不是纯对局结果：

* 对局结果是**无偏但高方差**的稀疏信号 —— 一局棋只有末尾 1 个 bit 的信息量，
  中间几十步的好棋和坏棋拿到同一个标签，这正是 REINFORCE 类方法在这里学得慢的原因。
* 搜索根评分是**低方差、稠密**的信号：它是"以当前评估为叶子、搜 d 层之后"的估计，
  比叶子评估本身更准。用 `V ← search_d(V)` 迭代，就是值迭代/策略迭代的标准做法
  （TD-Gammon、TD-leaf 用的就是它）。`labelDepth > playDepth` 时它会把更深的
  信息"蒸馏"回网络。
* 两者混合（`outcomeWeight`，默认 0.5）兼顾"不偏离真实胜负"和"稠密可学"。

`blend` 从 0 爬到 1 的意义：网络一开始只看过"手工评估"这一种信号，直接让它接管
评估会把引擎拉低；阶梯式接管保证每一步都建立在"不比上一步差"的基础上。

## 七、为什么它应该更强（可检验的预测）

| 对手 | 预测 | 依据 |
|------|------|------|
| `ABAgent(d4)` | **≥ 50%（blend=0 时就不该输）** | 同一套手工评估 + 置换表 + 迭代加深 + 更好的排序 ≈ 相同时间下搜得更深；blend>0 后评估也开始变好 |
| `MCTS(800)` | 明显占优 | 随机回放 vs 静态搜索，同代价下信息量差距很大 |
| `DQNAgent` / `PGEagent`（未训练） | 压倒性 | 它们不搜索，且动作空间是哈希 |
| `PPOMCTSAgent` / `DQNMCTSAgent`（未训练） | 明显占优 | 它们的价值头来自 90 维状态、无自举、无置换表 |

**验证方式**（`test_evab`）：同一进程内交替先后手打 N 局，统计 胜/和/负，
并报告搜索节点数、TT 命中率、每步耗时。**不训练**（blend=0）也跑一次，
用来说明"增益来自哪里"。

## 八、实测结果（`test_evab`）

### 8.1 搜索部分：验证通过，而且快得多

同一台机器（i5-10400F，AVX2），`blend=0`（纯手工评估，只看搜索）：

| 深度 | 耗时 | 节点数 | 置换表命中率 |
|------|------|--------|--------------|
| 2 | 5 ms | 1 280 | 0.0% |
| 3 | 26 ms | 13 233 | 8.8% |
| 4 | 62 ms | 21 949 | 15.0% |
| 5 | **146 ms** | 158 572 | 31.1% |

对照 `ABAgent` 的实测（`test_ab`）：深度 5 = **3 133 ms**。也就是**同深度约 21 倍** ——
差距全部来自置换表 / 迭代加深 / 杀手 + 历史启发，评估函数是同一个。

**对称性验证**（这条比速度更重要）：象棋初始局面在 `(x,y) → (9-x,y)` 且交换红黑之后
完全对称，所以红方的每个走法与黑方的镜像走法必须得到**相同**的搜索分数。实测：

```
depth 1: 可比对走法 42 对, 最大镜像分数差 = 0.000000000
depth 2: 可比对走法 42 对, 最大镜像分数差 = 0.000000000
depth 3: 可比对走法 42 对, 最大镜像分数差 = 0.000000000
```

精确为 0，说明搜索里没有任何颜色相关的偏差。（这个测试是**必需的**：对局统计会把
这类偏差淹掉，而它会让 AI 执一方时明显变弱。）

### 8.2 对抗：随机开局、交替先后手，每项 6 局

| 对手 | 结果 | 说明 |
|------|------|------|
| `MCTS`（600 次模拟） | **6 胜 0 平 0 负（100%）** | 随机回放 vs 静态搜索，符合预期 |
| `DQNAgent`（未训练） | **6-0-0** | |
| `PGEagent`（未训练） | **6-0-0** | |
| `ABAgent`（同深度 d4） | 1 胜 1~2 平 3~4 负（25~33%） | 见下面的说明 |
| `ABAgent`（d5）**等时对抗**：EVAB 限时 200 ms | **1 胜 4 平 1 负（50%）**，另一次跑出 3 胜 2 平 1 负（66.7%） | ← 引擎之间正确的比法 |

（每项只有 6 局，一局就是 16.7 个百分点，所以 50% 与 66.7% 的差别在噪声范围内；
可以确定的结论是"等时对抗不落下风"，而不是"强多少"。）

关于"同深度只剩 33%"这件事，值得单独说明，因为它暴露了一个真问题：
**手工评估在开局阶段几乎没有分辨力** —— 44 个开局走法的评分都在 ±0.01 量级，
于是"选哪个"完全由排序的随机性决定。谁先在开局白丢一个先手（走一步没有意义的
横移），后面就被对方一路积累优势（实测自对弈里分数从 0.007 单调爬到 0.35，
红方一路退让）。所以：

* 同深度、无随机开局的比赛，测的是"谁的排序运气好"，不是强弱；
* 测试里因此加了**随机开局**（前 6 步随机），并用**等时间**而不是等深度来比较。

**这也正是"学习评估"要解决的问题**：一个非线性评估网络原则上可以学到
"这一步有没有发展子力/争夺要道"，而线性 PST 求和学不到。

### 8.3 学习部分：模仿能成功，TD-leaf 精修还不够

* **模仿（引导阶梯第 0 级）成功**：让网络去拟合 `tanh(手工评估/3)`，600 局面 × 12 epoch
  之后平均 |net − hand| 从 **1.23 降到 0.05~0.06** —— 网络确实学会了手工评估。
* **TD-leaf 精修（第 1 级）目前会把棋力拉低**：4 局/轮、每轮几百个样本，
  而网络有 1260×48 ≈ 60k 个权重，样本量差了几个数量级；实测拟合误差从 0.35 涨到 0.70
  （在**发散**），blend 爬到 1.0 之后对局 0 胜 6 负。

因此加了**接受门槛**（`acceptNet`）：候选网络必须在对局里不输给"当前采用的配置"
（同一份权重、blend=0，即手工评估）才被采用，否则保留手工评估。这是设计上必须有的
一环 —— 目标函数（拟合得更准）和真实目标（下得更好）不是一回事。

实测门槛的工作情况：

```
[接受门槛] 候选(blend=1) vs 现行(blend=0), 6 局
  候选 vs 现行                   W 0 D 0 L 6   得分率 0.0%
  => 拒绝新网络, 保留手工评估 (得分率 0.0%)
```

也就是说：**当前这个训练配方产出的网络确实不如手工评估，门槛正确地拒绝了它**，
agent 于是停在"手工评估 + 强搜索"这个基线上。设计允许并预期这种结果 ——
比"悄悄把棋力换差"好得多。

要让第 1 级真正work，缺的是**数据量**和**调参**：几十~几百局而不是 4 局、
更小的学习率、更小的网络（或先线性后非线性），以及把"接受门槛"做成训练循环的一部分
（只有通过才把 blend 往上抬）。

### 8.4 过程中发现并修掉的四个真问题

1. **测试夹具把 agent 绑到了另一个棋盘上**（我自己犯的，和 `test_main.cpp` 里
   `static ABAgent abAI(chess, 8)` 是同一类错误）：agent 持有 `Chess&`，如果它不是
   对局用的那个棋盘，agent 会一直对同一个初始局面思考、反复给出同一步棋。
   修好后结果才可信。
2. **训练一轮只走一步梯度**：原实现把整轮几百个样本的梯度累积起来只调用一次
   `RMSProp` —— 三轮训练总共 3 步梯度，什么也学不到。改成真正的小批量更新。
3. **`Chess::computeHash()` 不能当置换表键**：原来的 `(id | x<<8 | y<<12)` 结构化异或
   相关性太强，碰撞会让 TT 返回**别的局面**的分数，搜索直接出错。改成标准 Zobrist
   随机键表（`Chess::zobrist()`）。这条对所有 agent 都有好处。
4. **等深度 ≠ 公平比较**：EVAB 的搜索快 21 倍，等深度比较相当于让 EVAB 只用 1/21 的
   时间。引擎之间的正确比法是等时间。

### 8.5 决策前探索：接入 GUI 并统一 5 个 agent 的协议

按"仿照 snakeAI：先探索环境预先训练，再决策"的要求，EVAB 与另外 4 个 RL agent 现在
都实现了 `AgentBase::exploreAndTrain(color, steps)`，GUI 走子前统一经过
`ChessBoard::preTrainThenDecide()` 调用它（细节与实测数据见
`docs/issues_review.md` 的"零之二点七"）。EVAB 的实现要点：

- 展开时用 `exploreEps`-greedy 而不是纯 argmax，否则永远采不到没走过的分支；
- 样本来自**树搜索的叶节点**（TD-leaf），而不是随机回放的即时奖励；
- 更新前后用 `acceptNet`（`netHandGap` 是否下降）做门控，不通过就整体回滚 ——
  这正对应 §8.3 里"TD-leaf 精修在样本量不足时会发散"的实测结论：
  网络能拒绝坏更新，就不会因为 GUI 里每步只探索几十局而越训越差。

顺带修掉了一个会影响所有 agent 的 bug：`exploreAndTrain` 传入的 `color` 与棋盘
`sideToMove` 不一定一致，第一版实现探索完把 `sideToMove` 留在了 rollout 末尾，
调用方随后从错误的走棋方开始搜索。现在入口保存、出口恢复，
`test_pretrain` 会用"连续 5 次探索后棋盘逐字段不变"守住这条不变量。

## 九、后续可加（本版未做，接口已留）

1. **策略先验用于排序**：把动作空间从哈希改成**结构化的 (from, to) 对**
   （90×90，用合法走法掩码），让网络输出"走法先验"，作为 alpha-beta 的第一排序键。
   这是 AlphaZero 里策略网络真正高效的地方（好排序 ≈ 更多有效深度），
   而且完全避开了现有 128 维哈希碰撞的问题。
2. **PUCT + 价值网络**：把现有 `MCTS` 的随机回放换成价值网络评估（现有
   `PPOMCTSAgent` 已经这么做了，但用的是 90 维状态；换成 1260 维 + TD-leaf 训练的价值头）。
3. **残差/卷积评估**：`Concat`/`Conv2d`/`ResNet` 风格的评估网络（现有 `Conv2d`、
   `TransformerBlock` 可用），把棋盘当 14 通道图像处理。代价是评估变贵，
   需要配合"评估缓存"（按局面哈希缓存叶子值）。
4. **开局库 / 置换表持久化**：TT 落盘，跨进程复用。
