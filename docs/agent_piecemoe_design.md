## 0. 一页结论（先看这段）

问题原话："每个棋子配一个小决策网络，最后通过稀疏 MOE 集成是否有效果？"

把它变成可在**本仓库**验证的形态之后，逐条结论如下：

| # | 结论 | 依据 | 反例 / 代价 |
|---|---|---|---|
| 1 | **作为"中心化条件计算"是可行的，不是 MARL**。一个优化器、一个 `logp_total`、一个 V，梯度经 router 回流 —— 上一轮说的"多 agent 非平稳"在这里不存在 | `SparseMoE::backward` 只把梯度给被选中的专家，全部经同一个 `Net`；`addAuxGradient` 只写门控参数 | —— |
| 2 | **"每个棋子一个网络"必须降成"每类棋子一个专家"**：16/32 个专家在参数、推理、权重文件上全是白交的钱，而且同类子（双车/双马）没有理由学两套（规范视角下红黑早已共用一套权重） | `agents_design.md` §11.3（规范视角）、`D §3.1` | 见 §2.4 |
| 3 | **"容量不按算力付费"只对专家数 E 成立，对 token 数不成立**。逐 token 路由后 计算量 ∝ N_token × k × expert，token 数直接乘在算力上 | `sparse_moe.hpp` 注释："参数量 ~ E×专家，计算量 ~ k×专家" —— 那条是对**一次**路由说的 | 见 §2.2 成本模型 |
| 4 | **"省策略头带宽"这条动机已经被 R1/R2 吃掉大半**：推理侧"只算合法列"把每模拟权重流量从 5.81 → 3.75 MB，剩下的 3.75 MB 里 MoE 专家 1.50 MB、critic 1.87 MB，策略头已经**不是**大头 | `training_optimization.md` §9.4、`issues_review.md` P2 第 10 条 | 所以本方案的卖点**不能**是"省 2 MB 策略头" |
| 5 | **硬绑定类型的专家 = 块对角网络，不含"学出来的专门化"**。这一步只剩结构先验（参数隔离 + 动作因子化），"专家特化"这个卖点必须先有**内容路由**才成立 | `agents_design.md` §11.4.2（专家在 top-k 下学会了按局面分流，`usage=[97,96,114,176,120,62,50,53]`） | 见 §2.3 |
| 6 | **本仓库目前无法回答"有没有效果（棋力）"**。四个骨干（MLP / 稀疏MoE-MLP专家 / 稀疏MoE-TB专家 / 稠密MoE-TB）对 AB 全是 0 胜，`bench_moe` 连自我对照都是和棋 —— 参赛的都是随机权重 | `issues_review.md` P2 第 9/18 条 | 要有棋力结论 = 自对弈几千局 + 预训=0 对照，**本方案不承诺** |
| 7 | **能测的是三类结论**：机制（掩码/梯度/合法性）、代价（ms/模拟、MB/模拟、ms/样本、内存）、学习信号（能否拟合访问分布 / 手工锚 / 一步杀探针 / 与 AB 一致率）。这三类**不需要**大规模训练预算，且仓库里都有现成仪器 | `test_ppomcts` [9]、`bench_policy_agreement`、`bench_ppo_distill`、`agent_dqnab_design.md` §19.4 | 见 §5 |
| 8 | **因此建议的路线是分阶段的**：A0 微基准 → **A1 因子化头（安全，与 MoE 无关）** → A2 类型专家（块对角对照） → A3 自由内容路由（研究性） → A4 棋力（需预算，本方案不覆盖） | §4 | 每一阶段都带 kill 条件 |

**一句话**：这个方案**值得做，但值得做的是它的"便宜那一半"**（按子因子化的动作头 + token 化的
局面表示 + 共享主干），而"每子一个专家 + 稀疏路由"那一半在当前仓库里既**得不到棋力结论**，
又会把算力从"模拟次数"挪到"专家计算"上 —— 而实测反复显示，**模拟次数本身就是棋力**
（`xiangqi_capacity.md`：参数每 ×10，每步模拟次数 ÷10；`bench_moe`：28.7 M 的多专家骨干在
60 ms 预算下只能跑 6 次模拟，输给能跑 64 次的 MLP）。

## 1. 方案原文 → 仓库里的对应物

原方案（上一轮讨论）落成一句可执行的话：

> 局面上**自己的每个棋子**生成一个 token；该 token 经门控在 **E 个小专家**里选 top-k；专家输出
> **该棋子的 from 分数与 to 分布**；把所有棋子的候选着法拼成统一 logits，再掩码 softmax 得到
> **唯一**的 P(a)；V 由共享主干给出；训练是 PPO 的单一目标（+ MoE 负载均衡辅助损失）。

| 讨论里的概念 | 本仓库是否已有 | 现状 / 缺什么 |
|---|---|---|
| 稀疏路由 MoE 层 | ✅ `src/rl/sparse_moe.hpp`（`SparseMoE<Expert,E,TopK>`） | **一次前向只有一次路由**（`gate = softmax(Wg·x)`，x 是整盘状态）—— 逐 token 路由**没有** |
| 多种专家模板 | ✅ `src/rl/expert.hpp`：`TransformerBlock<H,DFF>` / `MlpExpert`(d→h→h→d) / `Layer<Fn>`(d→d) | 专家都是 **d→d 同维**（要做门控加权和）；"token→(分数,90 个 to 分数)"这种**异构输出**要新写 |
| 负载均衡辅助损失 | ✅ `ISparseMoE::addAuxGradient(coef)`；**实测系数 0.1**（不加时 8 个专家饿死 3 个；0.01 太弱） | 逐 token 路由后批统计口径要重算（见 §3.4） |
| 坍缩诊断 | ✅ `usageSnapshot()` / `resetUsage()` / `resetBatchStats()` | 直接可用；A3 还要加"路由 ↔ 棋子类型"的对齐度 |
| 动作空间 | ✅ `fromCell*90 + toCell = 8100`，双射无碰撞；R1（推理只算合法列）、R2（训练只算合法列、**非法列梯度恰好 0**） | 因子化头要生成的正是这 8100 个 logits，形状兼容（见 §2.3） |
| 规范视角 / 镜像 | ✅ `PPO`/`SACAZ` 用 16×90=1440；`DQNAB` 用 **19×90=1710**（补了无吃子进度 / 重复次数 / 将军，**Markov 完备**） | 本方案建议直接用 1710 那套（§3.6） |
| 走子前探索 / 自对弈 / 回放 / 梯度累积 | ✅ P3–P7（`accumulateGradSparse`、`learnFromReplay`、`replayEpochs`、镜像增广、`ppo_selfplay_mt.hpp`） | 直接复用，不用改 |
| MCTS（PUCT + 子树复用） | ✅ B-5 置换表 + 换根复用 | 接口不变：只吃 π 与 V |
| 手工评估锚 / 一步杀探针 / 一致率尺子 | ✅ EVAB 的 `tanh(±evaluate()/3)`、`bench_policy_agreement`、`bench_ppo_distill`、`bench_dqnab_vs_ab --pure-q` | 直接当**学习信号探针**用（§5） |
| **逐 token 门控 + 异构专家输出 + 8100 logits 拼装** | ❌ **没有** | 这是本方案**真正要写的新代码**（一个新层，§3） |
| **路由的监督目标**（MCTS 访问质量按棋子聚合） | ❌ 没有 | A3 才需要；是本方案相对"通用 MoE"的**唯一新意**（§3.4） |

## 2. 方案评估

### 2.1 与实测事实的对照：哪些有依据、哪些没有

| 主张（原方案） | 本仓库的证据 | 判定 |
|---|---|---|
| 中心化集成 = 单优化器、无非平稳、无信用分配问题 | 代码结构如此（`Net` 内一层）；与 `agents_design.md` §10 对"多 agent 会炸"的分析一致 | **成立** |
| 稀疏路由能"容量不按算力付费" | 实测：同 28.70 M 参数，top-1 37.675 → 9.918 ms/模拟（4.1×；`test_sacaz` 里 4.14×） | **成立，但只对 E** |
| 专家会专门化（不同子/阶段分工） | 间接：8 专家 top-2 的 `usage` 分布明显不均（`[97,96,114,176,120,62,50,53]`），说明确实在分流；但**没有任何"分流 = 更强"的证据** | **未验证** |
| 专家会坍缩，需要辅助损失 | 实测：`coef=0` 时 8 个饿死 3 个（max/mean 4.00）；`0.1` → 0 个饿死、max/mean 2.91 | **成立**（系数取 0.1，不是论文的 0.01） |
| 因子化头（from/to 拆开）能提先验质量 → 同 sims 更强 | 无直接证据；可用的替代证据：R1 的"只算合法列"带来先验归一化口径变化 → 选点变化 ~2%（`bench_policy_agreement` 97.5–98%） | **未验证，但便宜可测** |
| 每子一个小网络 → 参数量换棋力 | 反例：`xiangqi_capacity.md` + `bench_moe`（28.7 M 专家骨干在等时预算下只有 6 次模拟，全和棋） | **方向存疑** |
| 本仓库能判断"有没有效果" | ❌ `issues_review.md` P2 第 9/18 条：四个骨干、两个算法，**零棋力结论** | **不能** |

### 2.2 成本模型（实测锚点 → 估算 → A0 要量的数）

**实测锚点**（`agents_design.md` §18.1，单网络 `state→MoE→Tanh(64)→头`，d=1440，AVX2）：

| 配置 | 参数量 | 前向 | 前向+反向 | w/g/v/m 缓冲 |
|---|---:|---:|---:|---:|
| `MlpExpert` E=8 top-2（d→h→h→d，h = d/16 = 90） | 2.15 M | **0.139 ms** | 1.94 ms | 34 MB |
| `TB<16,360>` E=4 top-1 | 38.0 M | **3.59 ms** | 32.1 ms | 608 MB |

由第一行得到一个可外推的**单位成本**：单个 MlpExpert = 1440→90→90→1440 = 267.3 k MAC /
1.07 MB 权重，top-2 前向 0.139 ms ⇒ **≈ 0.26 µs/kMAC（≈ 3.8 GMAC/s，单列 GEMV 口径）**、
**≈ 0.065 µs/KB 权重**（139 µs / 2140 KB）。

**本方案估算**（d_token = 64(trunk 上下文) + 7(类型 one-hot) + 90(格子 one-hot) = 161；
专家按**两层**口径 161 → h_e → 91，输出 [1 个 from 分数 ; 90 个 to 分数]）：

| 项 | h_e=96 | h_e=256 | 说明 |
|---|---:|---:|---|
| 单专家-token 的 MAC | 24.2 k | 64.5 k | 161·h + h·91（**两层**） |
| 单专家-token 前向（估算） | **6.3 µs** | 16.8 µs | 按 0.26 µs/kMAC |
| 16 个 token / 局面（估算） | **0.10 ms** | 0.27 ms | 每 token top-1 |
| 按类型聚合（≤7 次专家调用） | 0.044 ms | 0.12 ms | "type-pool + 每子廉价投影"变体 |
| trunk（1710→64）+ critic（1710→64→64→1） | ≈ 0.06 ms | 同 | 与骨干无关 |
| **每模拟合计（估算）** | **≈ 0.16 ms** | ≈ 0.33 ms | 对照：现役 TB 骨干 **6.9 ms/模拟**（实测 686 ms @100 sims） |
| 每模拟权重流量（估算） | ≈ 2.5 MB | ≈ 3.6 MB | 对照：现役 **3.75 MB**（MoE 1.50 + critic 1.87 + trunk） |

四条必须说清楚的：

0. **口径说明**：上表按"两层专家"算。若照现役 `MlpExpert` 的**三层**口径（`in→h→h→out`），
   要多一项 `h_e²`：h_e=96 时 24.2 k → 33.4 k MAC（+38%），h_e=256 时 64.5 k → 130 k（+100%）。
   两种都在 A0 里量，别在纸上选。
1. **千万别把 token 放进 d=1440 空间**。逐 token 专家在 161 维上是 6 µs，在 1440 维上是
   70 µs（MlpExpert 口径）—— 16 个 token 就是 1.1 ms/模拟，比现役 TB 骨干还贵。这就是
   `agents_design.md` §11.4 那条"MOE 能不能用取决于输入维度"的同一个道理。
2. **"省带宽"不是自动的**：16 个 token × top-1 就是 16 次专家权重读取（1.55 MB），比现役
   1.50 MB 的 MoE 流量**并没有少**。真正省下来的是 trunk/critic（1710→64 而不是 1440→TB）。
   所以 A0 必须**先量** `MB/模拟`，再谈这条收益。
3. **A0 的三个必量数**（不进 ctest 的微基准，仿 `.r1build/bench_ppo_expert.cpp`）：
   ① 单专家-token 前向/前向+反向；② 1/4/8/16 token 的整层前向、以及 **MB/模拟**；
   ③ `learnBatch` 的 ms/样本。三个数里任一个比现役便宜配置（MLP-expert）差 2× 以上，
   就应该在 A0 停住（kill 条件见 §4）。

### 2.3 三个必须先想清楚的技术点

**(1) 路由粒度：1 route/position → N routes/position 是新代码，不是配置开关。**
仓库里所有 MoE 都是"整盘状态一次路由"。逐 token 路由要新写一层，而这一层必须自己实现
`iLayer` 的全套契约（`forward / backward / SGD / RMSProp / Adam / clamp / copyTo /
softUpdateTo / write / read`），并且要进权重 v2 的**结构指纹**与 `LAYER_*` 类型表
（新层 = 新前缀、旧权重不可载，和 `SACAZ_MOE` 当年一样）。

**(2) 硬绑定 vs 自由路由 —— 这一步决定"这是不是 MoE"。**
如果专家下标 = 棋子类型（车专家只算车），那路由是输入的**确定性函数**，网络就是"块对角权重
+ 共享主干"：
* 好处：便宜、稳定、可解释，参数量小；
* 代价：**没有"学出来的专门化"**，而一个"共享的 to 头 + 把 类型/格子 拼进输入"在同等参数下
  是**严格更省参数**的表达（共享结构比块对角省参数）。也就是说：硬绑定换来的不是容量，
  而是**参数隔离**（多任务/持续学习有用，棋力上无证据）。
⇒ 结论：硬绑定只能当 **A2 的对照**，不能当"MoE 有效果"的证据。要谈 MoE 就必须让 router
按**内容**选（token 里含全局上下文），然后**量它会不会漂移**（见 §3.8：路由-类型对齐度）。

**(3) 动作空间的加性因子化 —— 与本仓库 8100 编码天然兼容，这是本方案最漂亮的一处。**
令 `s_p` = 棋子 p 的 from 分数、`t_p[to]` = 它的 to 分数，则

```
logits[from_p * 90 + to] = s_p + t_p[to]
```

于是：
* **掩码语义不变**：非法格子在拼装时就不写入（或写 −1e9），R1/R2 的"只算合法列"路径照旧；
* **归一化是全局的**（在合法着法集合上 softmax），所以"选哪个子"与"走到哪"共享同一把尺子，
  不需要额外的 P(piece) 归一化 —— 这正是"步"的概率本来就该有的定义；
* **R2 的"非法列梯度恰好为 0"自动继承**：`g` 只在合法项非零 ⇒ `ds_p` 只来自该子的合法 to、
  `dt_p[to]` 只来自合法的 (from,to)；
* **镜像增广（P6）仍然成立**：格子按 `y → 8−y` 镜像，`from*90+to` 与镜像下标一一对应，
  因子化后的 `s_p / t_p` 只是同一张表的另一种写法。

**一个必须写进测试的正确性陷阱**：token 里的类型/格子 one-hot 是**从输入 x 的平面读出来的**，
所以它们是计算图的一部分 —— `dL/dx` 必须包含"沿着 token 特征回到对应平面"的那条路。
漏掉它，解析梯度会**静默地错**（只在含子的平面上错），而这类错误正是 `test_grad` /
`test_sparse_moe` 那套有限差分存在的理由。要么把这条路实现对，要么显式 detach 并**在测试里
把"那部分导数为 0"写成断言**（两种都可以，但不能不说）。

### 2.4 "每个棋子一个网络"字面做法的否证

| 做法 | 参数 | 推理（每模拟） | 权重文件 | 判定 |
|---|---:|---:|---:|---|
| 32 个物理位置各一个网 | 32 × 专家 | 32 次专家调用 | ×32 | ❌ 双车/双马/红黑对称全在重复学同一件事 |
| 16 个"我方棋子槽"各一个网 | 16 × 专家 | 16 次 | ×16 | ❌ 同上（且 id 会随吃子回收，槽位不是身份） |
| **7 类棋子（红黑共用，规范视角）** | 7 × 专家 | ≤7 次（或按类型聚合后 7 次） | ×7 | ✅ 最小可用 |
| **E 个内容路由专家（top-k）** | E × 专家 | k 次/token | ×E | ✅ 这才是"MoE"；容量按 E 走，算力按 k 走 |

规范视角（`DQNAB` §3.1：镜像后规范编码逐位不变、镜像着法给同一个动作下标）已经保证了
红黑共用一套权重，所以"32 个网络"里有一半是纯浪费。

### 2.5 风险清单

| # | 风险 | 严重度 | 现有的应对 / 缓解 |
|---|---|---|---|
| R1 | **A0 的代价估算不成立**（每 token 开销被 GEMV 呼叫开销吃掉） | 高 | 先做微基准，A0 kill 条件；token 维数压到 161 |
| R2 | 专家输出是**异构形状**（1+90），与 `SparseMoE` 的"d→d 才能门控加权和"不兼容 | 中 | 新写一层，不复用 `SparseMoE` 的门控-加权和路径；门控语义与 `test_sparse_moe` 的等价性检查对齐 |
| R3 | 逐 token 路由后**辅助损失的批口径**错（把 token 当样本还是把局面当样本） | 中 | 明确：`batchForwardCount` 按 token 累加（现有实现天然支持），`f_i = usage_i/(batch·k)`；用 `test_sparse_moe` 同样的"人工压塌 → 看方向"测法验 |
| R4 | 路由**坍缩**（少数专家吃满） | 高 | 实测有效系数 0.1；A3 另加"棋子的监督目标"（§3.4），但要先证明它不与辅助损失打架 |
| R5 | 路由**抖动** → 同一局面换专家 → 对自举目标是新的非平稳源 | 中 | 记录路由熵；与 `agents_design.md` §11.4.2 里"路由漂移"的担忧同源，A3 的对照必须含"冻结 router"组 |
| R6 | 新层写错（拷贝构造漏拷贝、缓冲只读不写、`withGrad=false` 分支漏配） | 高 | `agents_design.md` §11.4.2 (2) 就是这一类：`iFcLayer` 拷贝构造只复制标量 → 15615 个非有限梯度。新层必须写"拷贝/存取/有限差分"三件套断言 |
| R7 | 与现役权重/界面不兼容 | 低 | 新 `LAYER_*` 类型 + 新权重前缀 + 启动预加载清单加一行（`verify_eager_load.ps1` 的 [2] 会抓"首次使用又弹沙漏"） |
| R8 | **做完拿不到结论**（没有训练预算 → 只有机制/代价/信号） | 高 | 本文 §0-6 与 §7 把"不声称"写死；A4 明确不承诺 |

### 2.6 不能声称的东西（诚实条款）

1. **不能**声称"稀疏 MoE 因子专家提升了棋力" —— 除非有 A4 的对照（自对弈几千局、等时间、
   预训=0、交换先后手、几十局以上）。当前仓库对 AB 的最好成绩是 DQNAB 的
   **0 胜 2 负 2 和**（且是随机权重，`§19.4`）。
2. **不能**把"和棋变多"当成变强（`bench_moe` 的四组全和棋就是这么来的）。
3. **不能**用"损失下降 / gap 降低"单独当进步（`agent_dqnab_design.md` §19.5：把 V 压成常数
   就能降 gap；必须同时看 corr 与 vStd）。
4. **不能**拿"专家使用分布不均"当"专家特化了"的证据 —— 不均也可能是路由塌了的前兆，
   必须同时看熵、对齐度与性能对照。

## 3. Agent 设计

**名字**：`PieceMoEAgent`（GUI 下拉框：`Piece-MoE + MCTS (AZ)`）
**文件**：`src/piecemoe_agent.{h,cpp}`、新层 `src/rl/piece_moe.hpp`
**权重前缀**：`weights/piecemoe_agent_{actor,critic}`（**与现役任何前缀都不共用**）
**算法**：PPO+MCTS（AlphaZero 风格），复用 R1/R2/P3–P7。

### 3.1 三件套

| 组件 | 输入 | 输出 | 备注 |
|---|---|---|---|
| 共享主干（每网一份） | 状态 s（1710） | h = Tanh(W_t s) ∈ R^64 | actor / critic 各一份（**先不跨网共享**，与现役结构一致，少一处改动） |
| **PieceMoE 头**（新层，actor 的最后一层） | s | 8100 维 logits（只填合法项） | 内部做：扫描我方棋子 → 建 token → 门控 → top-k 专家 → 拼装 |
| critic | s | V ∈ R^1（Tanh 有界，TD 目标夹到 [-1,1]） | 与 `DQNAB` §19.2 同口径 |

### 3.2 前向（伪代码，可直接对着写）

```cpp
// 入参 x: 1710 维规范视角状态; 掩码/合法着法表由 agent 传入(与现役 getLegalActions 一致)
h = tanh(Wt * x + bt);                       // 64

for each 我方棋子 p:                          // 扫 planes 0..6 的 90 格 ⇒ N <= 16
    u_p = [ h ; onehot7(type_p) ; onehot90(cell_p) ];            // 161, 由 x 的平面读出
    g_p = softmax(Wg * u_p + bg);                                // E
    S_p = topk(g_p, k);                                          // 默认 k = 1（A3 试 2）
    for e in S_p:
        (s_pe, t_pe) = Expert_e(u_p);                            // (1, 90)
    s_p = Σ_{e∈S_p} g_pe * s_pe;
    t_p = Σ_{e∈S_p} g_pe * t_pe;
    for each 合法终点 `to` of p:
        logits[cell_p * 90 + to] = s_p + t_p[to];

legal = 并集_{p}(p 的合法终点)
π = maskedSoftmax(logits, legal)             // R1/R2 口径: 只在合法集上归一化
```

反向（给定 `g = dL/dlogits`，只在合法项非零）：

```cpp
for each 我方棋子 p:
    ds_p   = Σ_{to ∈ dest(p)} g[cell_p*90 + to];
    dt_p[to] = g[cell_p*90 + to];
    for e in S_p:
        d(s_pe) = g_pe * ds_p;  d(t_pe) = g_pe * dt_p;  dg_pe = ds_p*s_pe + dt_p·t_pe;
        Expert_e.backward(u_p, du_p);                 // 累加
    dz_p = SoftmaxJac(g_p, dg_p);                     // dL/dz_c = g_c(d_c - Σ d_i g_i)
    Wg.grad += dz_p * u_pᵀ;  bg.grad += dz_p;  du_p += Wgᵀ * dz_p;
    dh += du_p[0..63];
    x.grad[读出的 7 个类型平面与 90 格] += du_p[64..160];   // ← §2.3 那条陷阱
dh *= (1 - h*h);                                      // tanh 反向
Wt.grad += dh * xᵀ;  bt.grad += dh;  e_x = Wtᵀ * dh;
```

### 3.3 变体（A2 / A3 的差别只在这三行）

| 变体 | 门控 | 专家 | 每局面专家调用次数 | 定位 |
|---|---|---|---|---|
| **A1** 单一共享专家 | 无 | 1 个（161→h'→h'→91） | 1 | 隔离"因子化头"本身的收益 |
| **A2** 类型绑定 | 无（`e = type_p`） | 7 个 | ≤7（或按类型聚合） | 块对角对照 |
| **A3** 内容路由 | `softmax(Wg·u_p)`，top-1/2 | E=8~14 | N × k ≤ 16~32 | **真正的 MoE** |

### 3.4 训练目标

沿用 PPO 现有口径，**只加一项可选的**：

```
L = CE(π ‖ π_MCTS)              // P5: 根的访问分布, 稀疏存储; R2: 只在合法列
  + MSE(V, z)                   // P4: 回放池 + 多 epoch
  + coef_aux * E * Σ_i f_i P̄_i   // 逐 token 路由时的负载均衡（A3，coef 从 0.1 起扫）
  [+ coef_piece * CE(softmax_p(s_p/T) ‖ q_p)]   // A3 可选: q_p = 该子合法着法的访问质量占比
```

最后那一项是本方案相对"通用 MoE"的**唯一新意**：通用 MoE 的路由没有任务梯度（所以要靠辅助
损失硬撑），而这里**"该走哪个子"本身有搜索给的监督信号**。它有两个待验证的疑点，都必须做
对照：① 它会不会与辅助损失打架（一个要均衡、一个要集中）；② `RMSProp` 的 `clipGrad` 下
每次位移 ≈ lr（`agents_design.md` §18.7(3) 实测），所以**不能用"跑 N 步后 π 应该变大"这种
断言**，只能用配对 A/B + 轨迹统计量。

### 3.5 与 MCTS 的接口

* PUCT 不变：`Q + c_puct·P·√N_parent/(1+N_child)`，`c_puct = 1.414`（重扫无落点，见 R2 记录）；
* **根先验的取值方式变了**：R1 的 `actionMasked` 是"先算合法列的子集"，这里是"只拼装合法
  项" —— 语义等价、代价更低，但要**逐元素**证明等价（`test_ppomcts` 测试 11 的做法）；
* 子树复用（B-5）不变（Zobrist 换根）。

### 3.6 编码：建议直接用 `DQNAB` 的 19 平面（1710）

| 编码 | 维数 | Markov 完备？ | 现役 |
|---|---:|:---:|---|
| `PPO` / `SACAZ` | 1440（16 平面） | ❌ 缺 无吃子进度 / 重复次数 / 将军 | PPOMCTS、SACAZ |
| **`DQNAB`** | **1710（19 平面）** | ✅（`agent_dqnab_design.md` §3 有断言） | DQNAB |

理由是硬的：三次重复与 60 回合判和**决定终局**，只喂棋盘时"同一局面第 2 次与第 3 次出现"
编码成同一个向量，`V(s)` 就不是 `s` 的函数（`test_dqnab [10]` 把它钉成了断言）。既然是新
agent，没有理由继承这个建模缺陷。代价：trunk 输入 1710 vs 1440（+19% trunk 流量，估算 <0.01 ms）。

### 3.7 权重 / GUI 接线清单

1. `src/rl/piece_moe.hpp`：新层 + `LAYER_PIECEMOE` 类型常量 + 权重 v2 指纹登记；
2. `src/chessboard.cpp`：`AGENT_PIECEMOE` + `defaultWeightPath()` 表里加一行 + 启动预加载清单；
3. `src/mainwindow.cpp`：下拉框加一项；

5. `tools/verify_eager_load.ps1` 会自动覆盖"启动加载了它、首次使用不弹沙漏"。

### 3.8 诊断（必须能在界面上/日志里看见，否则调不动）

| 指标 | 来源 | 判读 |
|---|---|---|
| 每专家被选中次数 | `usageSnapshot()` | 严重偏斜 = 塌（配合辅助损失系数扫） |
| 路由熵 `H(g_p)` 均值 | 新层统计 | 趋 0 = 塌；恒为 lnE = 没学 |
| **路由-类型对齐度** | 统计"token 被派给 `type_p` 那个专家"的比例 | A2 = 100%（定义如此）；**A3 若稳定偏高，说明"按子专家"是网络的真实需求**；若接近 1/E，说明路由没学到东西 |
| 平均 token 数 N | 棋盘 | 残局便宜（N 小），这本身是这套结构的一个附带好处 |

## 7. 明确不做的事

1. **不追求参数量**。本方案总参 ≈ 0.3–1.5 M（trunk 0.11 M + 专家 E×(161·h + h·91)），
   远小于现役 TB 配置的 75 M —— 定位是**结构**，不是容量。要容量就把 `h_e` 调大（A0 有单价）。
2. **不把 8100 维动作表示换掉**（`issues_review.md` P2 第 10 条 (c) 已判定不作为选项）。
   本方案是那条待办里**缺的第 (d) 项**：动作空间不动，但 logits 由因子化生成 —— 这才是它的
   正确位置（附注：R1/R2 之后策略头已不是带宽大头，所以这条只算"小幅帮到访存墙"，不是解药）。
3. **不做批量叶子前向 / virtual loss**（P2 第 10 条 (a)，独立的大改动），也不做 fp16/int8 (b)。
4. **不做对手池 / league**、不做后台训练线程接线（与 `DQNAB` §19.7 的取舍一致）。
5. **不声称棋力**（§2.6）。

## 10. 这份评估的一句话总结

原方案**在算法上是干净的**（中心化、单目标、掩码正确、与 PPO/MCTS 天然兼容），
**在工程上是可行的**（一个新层 + 若干接线，9–17 天），**在证据上是不够的**：
它承诺的"专家专门化 → 更强"在本仓库里既没有先例、也没有能下结论的测量条件，而它要付的代价
（每 token 一次专家计算、路由稳定性风险、新层的一整轮正确性工作）是**当下就要付**的。

所以正确的做法是**把它拆成"能拿确定收益的一半"和"研究性的一半"**：先把因子化头 + token 化
表示 + Markov 完备编码做出来（A1，风险最低、收益可测），把 MoE 路由放在 A2/A3 并用等参数、
等时间、配对 A/B 严格对照；**在任何情况下都不把"机制通了"说成"有效果"**——
这正是 `agents_design.md` §11.4.2(6) 与 `issues_review.md` P2 第 9/18 条反复记下的那条教训。
