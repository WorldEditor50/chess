### 11.2 一致性断言（都进 `test_sacaz` / `test_ppomcts` / `test_grad`）

| 断言 | 实测 |
|---|---|

| 稀疏头 vs 全量口径：π 逐元素、Q 逐元素、软价值 | 最大偏差 **1.1e-08 / 7.5e-08 / 1.9e-08** |

| PPO：非法行梯度恰好为 0（稀疏） vs 非 0（全量） | 0.000e+00 vs 2.8e-04 |
| PPO：给出 `p_old` 后策略项换成裁剪代理目标；收紧裁剪的位移 ≤ 放松裁剪 | `test_ppomcts` [13d]：141.79 / 156.85 / 164.29（无 `p_old`） |
| **PPO 稀疏头的解析梯度 == 中心差分** | 最大相对误差 **3.2e-05**（修复前是 **8.8e-01**，见下） |

**这一轮改动里被抓到并修掉的一个真 bug（值得记下来）**：

给 PPO 加裁剪时，我把策略项从"直接算 `dL/dlogit`"改写成"先算 `dL/dπ` 再乘 softmax 雅可比"，
而在写 `dL/dπ` 时用了 **−t** —— 那是**交叉熵对 logit 的梯度**，不是对 π 的梯度。
后果：整条策略梯度被系统性缩小 `p_i` 倍（雅可比会把常数向量投影掉），方向对、幅度错，
**训练照跑、loss 照降**。`test_grad` 的 E 节（中心差分）当场抓到：

```
修复前: head.b[8099]  解析 +1.72e-02   差分 +1.37e-01   相对误差 8.75e-01   <- 差了 7.8 倍
修复后: head.b[8099]  解析 +1.37e-01   差分 +1.37e-01   相对误差 2.00e-06
```

正确的形式（两种目标统一，直接给 logit 梯度）：

```
CE    : dL/dz_i = p_i − t_i
裁剪  : dL/dz_i = p_i·Σ_a k_a − k_i ,  k_a = [未裁剪]·ρ_a·A_a
熵    : + entropyCoef · p_i · ( H̃ − log p_i − 1 ),  H̃ = Σ_a p_a(log p_a + 1)
```

（`Σ_a k_a` 那一项**不能**写成 `Σ_a k_a·p_a`。这一条我用一份独立的数值脚本
对着"裁剪目标 + softmax 参数化"做中心差分验证过：`Σk` 形式与数值梯度差 8.8e-11，
`Σk·p` 形式差 5.9e-04。）


### 11.3 改后的实测读数

**critic 不再发散、策略真的变尖**（`--mode=probe`，48 个采样局面）：

| 权重 | 策略熵（归一） | top1 | \|Q\| | Q 区间 |
|---|---|---|---|---|
| 随机初始化 | 0.999 | 0.026 | 0.059 | [−0.134, 0.080] |
| 改前 40 局 | 0.962 | 0.035 | **4.146** | [−4.410, −3.633] |
| 改前 150 局 | 0.961 | 0.036 | **13.381** | [−14.060, −11.941] |
| **改后 14 局** | **0.634** | **0.205** | **0.185** | [−0.329, −0.030] |

* 值域约束生效：\|Q\| 停在 0.185（改前同一训练量级已经在 4 以上，且单调涨到 13.4）。
* α 不再卡死：策略熵从 0.999 收到 **0.634** —— 这是本工程第一次看到 SAC 的策略**变尖**
  （改前无论训练多久都停在 0.96 = 几乎均匀）。

**稀疏头把每步成本压回来**：

| 条件 | 每步 |
|---|---|
| 128 槽动作空间（改前改前，历史记录） | 55 ms |
| 8100 动作 + 全量叶子估值 | **216 ms** |
| 8100 动作 + 稀疏头（改后） | **75 ms** |

**但棋力仍然没有提升**（这是必须说清楚的一条）：

| 对局（改后 14 局权重） | 局数 | 得分率 | 区间 | 判定 |
|---|---|---|---|---|
| SAC(改后) vs MCTS | 30 | 38.3% | [23.2%, 56.1%] | inconclusive |
| SAC(改后) vs 它自己的随机初始化 | 30 | 40.0% | [24.6%, 57.7%] | inconclusive |

而**随机权重**的 SAC 对同一个 MCTS 是 73.3%~75.0%（§3，三颗种子）。也就是说：

> **critic 发散是一个真缺陷（它此前把搜索的 PUCT 打坏），但它不是"训练后变弱"的全部原因。**
> 修好它只是把"训练后剧烈退化"变成"训练后仍然不涨"。

剩下的原因（§8.3 已列，仍未解决）：
1. **自对弈数据的参照物是它自己** —— 150 局自对弈的监督信号上限就是当前策略；
2. **评估基线太弱**（AB 深度 2 以 20:0 通杀 MCTS）—— 天花板效应 + 与实际棋力脱钩；
3. 训练预算：本轮的 14 局只能算冒烟；要判定"改后能不能学"需要 ≥150 局 + 锚点对局。

## 0. 结论摘要

1. **"SAC+AZ 能赢 MCTS"不是训练的结果** —— 它在**随机初始化**的权重上就已经决定性地赢：
   3 颗种子、共 140 局，得分率 73.3% / 75.0% / 75.0%，区间全部在 50% 以上（+176~+191 Elo）。
2. **训练反而把它弄坏了** —— 同一权重、同一协议，自对弈 150 局后对 MCTS 从 **73.3% 掉到
   32.5%**（两个 Wilson 区间不重叠，摆动 300 Elo）；对**它自己的随机初始化**
   （3 颗种子、140 局）是 **3 胜 28 负 109 和**（42.0%）。
3. **机制查清了：critic 发散，而且与策略塌缩无关** —— 策略熵在三个训练量下都是 **0.96**
   （几乎均匀，top1≈0.03），而 critic 的 |Q| 从 **0.07 → 4.15（40 局）→ 13.4（150 局）**
   单调发散，且**所有动作的 Q 一起变负**，而奖励量级只有 ±1。搜索的叶子估值就是这个数。
4. **PPO+MCTS 这边：策略在收敛，棋力没动** —— 它的策略熵确实从 0.999 收到 0.828
   （唯一"真的变尖"的 agent），但对 MCTS 始终是 48.3% / 56.7% / 50.0%，
   五个区间**全部跨过 50%**（`inconclusive`）。它是"打平弱基线"。
5. **原来那三条读数（5 胜 0 负 5 和 / 奖励曲线远超 / loss 曲线密集）都不能支撑
   "SAC 更高效"** —— 逐条理由见 §7，其中"奖励曲线"与 MCTS 在口径上就不可比。
6. **"SAC 高效"里唯一成立的部分是搜索结构，不是训练算法** —— 见 §6 的机制归因。

## 1. 工具与协议

为什么不能直接用 `bench_sacaz_vs_ab` / `bench_ppo_vs_ab`：那两个各自只测"一个 agent 对
AB"，而"哪个算法更强"是**三方**问题（两个学习 agent 互打 + 各自对同一个无学习基线），
分两次运行无法保证随机开局、种子、模拟预算一致。

| 协议项 | 取值 |
|---|---|
| 交换先后手 | 局数强制偶数；第 i 局 A 执红 ⟺ i 为偶数 |
| 随机开局 | 每局先用同一颗种子随机走 4 步合法棋（双方都不参与） |
| 每步模拟 | A/B 与 MCTS 全部 **160**（`--sims`） |
| 手数上限 | 120 手（到上限判和） |
| 合法性 | **逐手**校验；任一方返回无效/非法走法 → `BROKEN` + 退出码非 0 |
| 统计 | 得分率（胜 1 / 和 0.5）+ **Wilson 95% 区间**；区间跨 50% 标 `inconclusive` |

**为什么要区间**：11 局的比分差在 ±8.8% 噪声带内分辨不出来
（`docs/mcts_sims_scaling.md` §3）。"5 胜 0 负 5 和"与"5 胜 5 负 1 和"这两个读数看着
差别大，实际都在噪声里。

### 三个 agent 的结构

|---|---|---|---|---|---|

| MCTS（基线，`src/mcts.cpp`） | 走法集 | — | 0 | **随机走子 rollout** 的终局结果 | 145–183 ms |

## 2. 基线强度校准（**先证明它有分辨力**）

| 对局 | 局数 | 比分 | A 得分率 | 区间 | 判定 |
|---|---|---|---|---|---|
| MCTS(160) vs AB 深度 2 | 20 | 1 / 19 / 0 | **5.0%** | [0.9%, 23.6%] | decisive |
| MCTS(160) vs AB 深度 4 | 20 | 0 / 18 / 2 | **5.0%** | [0.9%, 23.6%] | decisive |
| AB 深度 2 vs MCTS(160) | 20 | 20 / 0 / 0 | **100%** | [83.9%, 100%] | decisive |

**MCTS（随机 rollout + UCB1）在本工程里是个弱基线**：AB 深度 2 就能 20:0 通杀，耗时只有
它的 1/94。后果有两个：

* 拿它当对手**天花板效应风险高**（谁都可能赢它），只适合看方向（变强/变弱）；
* 但它**不是地板**（PPO 随机权重只有 35%–48%），所以"某 agent 明显强于它"仍然是有信息的。

## 3. 随机权重对照矩阵（训练前的起点）

| # | A vs B | 局数 | seed | 比分 | A 得分率 | Wilson 95% | Elo | 判定 |
|---|---|---|---|---|---|---|---|---|
| R1 | SAC(随机) vs MCTS | 60 | 20240901 | 33 / 5 / 22 | **73.3%** | [61.0, 82.9] | +176 | decisive |
| R2 | SAC(随机) vs MCTS | 40 | 777 | 21 / 1 / 18 | **75.0%** | [59.8, 85.8] | +191 | decisive |

**这是整份报告最重要的一组对照**：两边都是**随机初始化**的网络、同一搜索骨架
（PUCT + 访问分布）、同一族 MLP 专家骨干、同一模拟预算。

* SAC+AZ **决定性地**赢弱基线（三颗种子一致，+176 ~ +191 Elo）；
* PPO+MCTS **打平或略亏**（48.3% / 35.0%）；

未训练的网络 + 自带的 PUCT 搜索上。`docs/agents_design.md` §21.5 记录过 DQN+MCTS
报"50 胜 0 负 50 和"（自对弈口径失效）；这里是**跨 agent 对局**口径下同样的形状：
**赢弱基线的比分不构成"算法高效"的证据**。

### 5.1 训练让 SAC 变弱（三颗种子、方向一致）

* **对 MCTS：73.3% → 32.5%**，两个区间**不重叠**（[61.0, 82.9] vs [22.0, 45.1]），
  Elo 从 +176 摆到 −127（**摆动 300 Elo**）。
* **对自己的随机初始化**（3 颗种子，共 140 局）：**3 胜 / 28 负 / 109 和**，
  合并得分率 **42.0%**。三颗独立种子的得分率分别是 37.5% / 45.0% / 42.5%，
  **没有一颗种子支持"训练变强"**。
* 剂量关系（各 20 局，小样本但方向一致）：随机 73% → 40 局 40% → 150 局 32.5%。
* 注意：单看某一颗种子的区间都跨 50%（`inconclusive`）—— **三种子合并 + 与随机权重那
  75% 的对比**才构成"训练有害"的证据。这正是"5 胜 0 负 5 和"这类单次读数的教训。

### 5.2 机制：critic 发散，而策略**没有**塌缩（探针实测）

`--mode=probe` 在同一批局面（标准开局 + 随机开局 4 步后的中局，48 个样本）上量
"策略分布 + Q 的尺度"：

| 权重 | 合法数 | 策略熵（归一） | top1 | **\|Q\| 均值** | Q 区间 |
|---|---|---|---|---|---|
| 随机初始化 | 44.0 | 3.643 (**0.963**) | 0.029 | **0.063** | [−0.138, 0.101] |
| 自对弈 40 局 | 44.0 | 3.641 (**0.962**) | 0.035 | **4.146** | [−4.410, −3.633] |
| 自对弈 150 局 | 44.0 | 3.636 (**0.961**) | 0.036 | **13.381** | [−14.060, −11.941] |

> 探针的 Q 列**只对 SAC 有效**（PPO 的 value 头是标量不是动作价值，探针不采样它，
> 打印出来的 0.000 是"未测"而不是"真的是 0"）。PPO 的读数见 §5.4。

三条读数：

1. **策略没塌缩**：归一化熵 0.963 → 0.961，top1 0.029 → 0.036 —— 训练后策略仍然几乎是
   均匀的。所以"训练后走法变差"**不是**"策略收敛到坏着法"。
2. **critic 单调发散**：|Q| 0.063 → 4.146 → 13.381，而且**所有动作的 Q 一起变负**
   （[−14.06, −11.94]），说明它不是在学一个更好的价值排序，而是在**整体漂移**。
3. 量级对比：即时奖励的材质上限是 0.1×3.5=**0.35**，终局奖励是 **±1**，而 Q 跑到 **−13**。
   搜索的叶子估值就是 `softValueFrom`（min Q − α log π 的期望），所以**搜索拿到的
   叶子信号整体平移了 −13 且几乎没有区分度**。

**为什么这会把搜索弄坏**：`getPUCT` 是

```
puct = (-child.getQ()) + c_puct · child.prior · sqrt(N_parent) / (1 + N_child)
```

Q 项的尺度一旦远大于探索项（c_puct=1.5、prior≈1/44），`argmax` 就由 Q 的尺度主导；
而 Q 的值是"整体平移 + 噪声"，于是**先验与访问计数带来的信息被淹没**，
搜索退化成"按一个几乎无信息的排序走"。这解释了 §5.1 的 300 Elo 摆动。

### 5.3 但"缩放 Q"**不能**把棋力修回来（一次负结果）

我加了 `--sac-value-scale`（只作用于**搜索**的叶子估值，不动学习目标），把训练后 Q 的
量级缩回初始量级（×0.01 ⇒ |Q|≈0.13）再打：

| 条件 | 局数 | 对 MCTS 得分率 | 平均手数 |
|---|---|---|---|
| SAC(150) 原样（\|Q\|=13.4） | 60 | 32.5% | 84.2 |
| SAC(150) + scale 0.01（\|Q\|≈0.13） | 20 | 40.0% | **99.3** |
| SAC(40) 原样（\|Q\|=4.1） | 20 | 40.0% | 77.5 |
| SAC(40) + scale 0.01 | 20 | 42.5% | **112.3** |

* **有一半效果**：平均手数从 84 / 77 拉回 **99 / 112**（"11–24 手就和棋"那种退化消失了），
  说明**叶子估值的尺度确实在破坏搜索的结构**。
* **但棋力没回来**：40–42.5%，离随机权重的 73% 差得远，且样本只有 20 局（区间跨 50%）。

**结论**：critic 尺度是**一个**真实缺陷，但不是全部。训练后的 actor 先验（熵虽均匀、
方向可能变坏）与 critic 的**排序质量**仍然是坏的 —— 这三件事叠在一起才是"训练后变弱"。
"把 Q 归一化"是个必要但不充分的修法。

### 5.4 PPO 这边：策略在收敛，但棋力没动

| 训练量 | 策略熵（归一） | top1 | 对 MCTS | 对自己的随机版本 |
|---|---|---|---|---|
| 随机 | 3.782 (**0.999**) | 0.026 | 48.3% / 35.0% | — |
| 150 局 | 3.430 (**0.906**) | 0.121 | 56.7% [44.1, 68.4] | 56.7% [44.1, 68.4] |
| 400 局 | 3.134 (**0.828**) | 0.208 | 50.0% [35.2, 64.8] | 56.2% [41.0, 70.4] |

* **actor 确实在学**：归一化熵 0.999 → 0.906 → 0.828，top1 0.026 → 0.121 → 0.208。
  它是三个矩阵里唯一"策略真的变尖"的 agent（SAC 停在 0.96）。
* **但棋力没有任何可测的变化**：对 MCTS 48.3% → 56.7% → 50.0%，
  对自己的随机版本 56.7% → 56.2%，**五个区间全部跨过 50%**（`inconclusive`）。
  训练量翻 2.7 倍（150 → 400 局）也没有带来方向性变化。
* 和棋率极高（PPO 400 对 MCTS 是 2 胜 2 负 **36 和**），说明它学到的策略是**求稳/求循环**的
  —— 与"学习目标是模仿自己的 MCTS 访问分布"这个闭环一致（§8.2）。

**能说的**：PPO 没有像 SAC 那样剧烈退化，它的策略确实在收敛。
**不能说的**：PPO 变强了 —— 按同一套判据（区间不跨 50%）它在 190 局里一次都没通过。

## 6. 为什么随机权重的 SAC 能赢 MCTS（机制归因）

这一条必须解释，否则"随机权重赢 73%"看起来像 bug。三个候选机制，逐条看证据：

| 候选 | 证据 | 判定 |
|---|---|---|
| 树复用/置换表 | SAC 的 `selectMove` 每次调用**新建**树（`nodes.clear()`），跨手不复用；MCTS 的 `findBestMove` 也每次 clear。两边都没有复用 | **排除** |
| 访问次数分布不同 | 两者都是"按访问次数出招"、同模拟预算 | **排除** |
| **叶子信号的信息量** | MCTS 的叶子是**随机走子 rollout 的终局结果**：中国象棋随机走子极少在步数内分出胜负且大量判和 ⇒ 叶子值几乎恒为 0/近似常数 ⇒ **UCB1 里 Q 项无区分度**。SAC 的叶子是随机双 Q 的软价值，量级只有 ±0.1，但它**随局面变化**（吃子/被吃、机动性在随机网络里也有非零响应）⇒ 搜索有微弱但有方向的偏好 | **保留（主因）** |

也就是说：**赢的不是"SAC 训练算法"，是"用带先验的 PUCT 搜索 + 一个随局面变化的叶子估值"
替换掉"UCB1 + 常数叶子"**。这是**搜索结构**的优势，不是"训练算法高效"的优势。

**一个现成的旁证（本报告 §3 已经量到）**：PPO+MCTS 用的也是 PUCT + 学习型叶子
（单值头 `V(s)`），但它对同一个 MCTS 只有 48.3% / 35.0%。也就是说
**"PUCT + 学习型叶子"本身并不保证赢**：随机 PPO 的 `V(s)` 在 [−1,1] 里几乎不区分局面
（与本仓库记录的"critic 只能学成常数""一步杀 0/20"同源），于是它的搜索**也没有判别信号**，
跟随机 rollout 打平。SAC 那一侧的叶子（双 Q 的软价值）虽然也是随机网络，却**带着随局面
变化的量**，所以有微弱偏好。

这条旁证把归因收窄成一句可证伪的话：**"叶子估值到底有没有随局面变化的信息"**才是
随机权重下胜负的来源，而不是"SAC / PPO 的算法"。要做成对照，把 MCTS 的
`simulateRandomPlay` 换成 `abagent.cpp` 那套手工评估即可（未跑，留作待办）。

## 7. 逐条回应原来的三个读数

| 原读数 | 实测怎么说 |
|---|---|
| **"5 胜 0 负 5 和"** | 10 局的比分落在噪声带（±8.8%）里。本报告 60 局的同口径对照给出**相反方向**：训练后 32.5%，决定性变弱。而这个"5 胜 0 负"最可能来自：**随机权重** SAC 对弱基线 MCTS 的短期比分（随机权重对 MCTS 就是 73%–75%，10 局很容易打成 5 胜 0 负 5 和）。**"5 胜 0 负 5 和"根本不是训练成果的读数。** |
| **"奖励曲线能远超 MCTS"** | 口径上不成立：MCTS 没有可学习参数，它的损失/奖励曲线永远是空的（`getLastTrainLoss()` 恒 NaN，界面也不画它的线）。被比的其实是"SAC 一方的**局内累计吃子奖励**"对"一条空线"。而即时奖励口径是 `REWARD_MATERIAL_COEF = 0.1`，一方吃光全部材质 = **0.35 > 终局 ±1**，所以累计吃子曲线的量级天然超过终局奖励。**它量的是"吃了多少子"，不是棋力**（本仓库同类教训：代理指标会与胜率脱钩，`docs/agents_design.md` §7.10）。 |
| **"loss 曲线密集"** | 密集是训练日程的算术结果：SAC 每 4 手更新一次（150 局 ≈ 4600 次），PPO 每局更新一次（150 次），差 30 倍。而 SAC 报的是批平均 MSE（`lossSum/(batchSize×epochs)`），PPO 报的是 `[−1,1]` 值域上的 critic MSE —— **量纲不同、不可比**，也都不与棋力挂钩（本报告的 T1 就是反例：SAC 的 loss 曲线最"密集"，同时它是最弱的）。 |

## 8. 优化方法评估

### 8.1 SAC 这一侧：哪些机制真的在起作用

| 机制 | 实测表现 | 判定 |
|---|---|---|
| **双 Q + 目标网 + negamax 软备份** `y = r − γ(1−done)·V(s')`，`V = E_π[min Q − α log π]` | 搜索的叶子估值与 critic 的学习目标是**同一函数族**（只差在线/目标网延迟），这是 SAC 一侧唯一自洽的设计 | **设计对，但实测发散**：\|Q\| 0.063→13.4（§5.2）。软备份把 r(≤0.35)+终局(±1) 与 bootstrapped V 反复回代，在 `lr=1e-3`、`clipGrad`（按向量归一）下没有把 V 拉回 [−1,1] 量级的机制 —— **缺少值域约束** |
| **off-policy 回放复用** | 4096 池 / 每 4 手抽 32 条 | 理论红利真实，实测被两件事抵消：① 池内去重率 **99.0%**（`docs/agents_design.md` §21.2[4]），装的几乎是同一批局面；② 训练墙钟从 595 s 涨到 1268 s，换来的却是变弱 |
| **α 自动调节**（目标熵 0.98·log 合法数） | `alpha` 在探针里**三个权重都是 0.200**（= 构造函数初值）：因为策略熵本来就几乎等于目标熵（H/H̄≈0.96/0.98），梯度 `alphaGrad = H − H̄ ≈ 0`，再乘 `learningRateAlpha=1e-3`、再过 `clamp(0.02, 5.0)` ⇒ **α 事实上不动**（代码路径：`sacazagent.cpp:980 → 1026-1028`） | **功能性失效**：目标熵 0.98 把策略钉在"几乎均匀"，α 在这个设定下既不能收紧探索、也解释不了训练前后的变化 |
| **AlphaZero 监督项**（交叉熵，`azWeight=1.0`） | 策略熵 0.96 ⇒ 大概率策略梯度被这一项主导；但 π 目标来自 **128 槽哈希**动作空间上的访问分布，同局面平均挤掉 5.16 个着法 ⇒ 目标本身带别名 | **有贡献也有噪声**：它让策略"像搜索"，但搜索的叶子又是发散的 Q ⇒ 学的是一个坏老师 |
| **每 4 手更新一次** | 4600 次 / 150 局 | 是 loss 曲线密集的**全部来源**；也让训练成本翻倍 |

**"SAC 高效"这句话在本工程里成立的部分**：
它在**未训练**状态下就决定性地赢弱基线（+176~191 Elo）。这来自搜索结构（PUCT + 先验 +
随局面变化的叶子），**不来自它的训练算法**。而一旦开始训练，这套组合在
"128 槽动作空间 + 目标熵 0.98 + 弱基线自对弈数据 + 无值域约束的软备份"下**反向**了。

### 8.2 PPO 这一侧：名字与实现不符（这条最关键）

`src/rl/ppo.h:114` 自己写着：

```
全连接头 / 损失函数的学习部分与原来一致 (无 clip、无 KL 惩罚、无 actorQ):
  Policy loss: cross-entropy(actor(state) || MCTS 目标分布)
  Value loss:  MSE(critic(state), 回报)
```

所以这个 "PPO+MCTS" 实际是：

* **策略**：纯交叉熵行为克隆（模仿 MCTS 访问分布），无信任域、无 ratio、无熵项；
* **价值**：对**蒙特卡洛回报**做 MSE（一局一条轨迹算一次），无 GAE、无 bootstrapping
  （截断局靠一个 `truncationBootstrap` 开关兜着）；
* **数据**：近似 on-policy，进池抽 64×2 epoch 后基本丢弃（150 局只更新 150 次）。

因此本报告里"PPO 没变强"**不能**推断成"PPO 这个算法不行"，只能说**这条学习路径不行**。
它是"带搜索目标的行为克隆"，价值头在 150 局数据下不足以支撑搜索的叶子估值。

### 8.3 两边共同的结构性缺陷（都不是调参能解决的）

1. **自对弈数据来自一个弱得多的"自我"**，而评估标准是"像不像它自己" —— 循环论证。
2. **评估基线太弱**（AB 深度 2 通杀 MCTS 20:0）⇒ 天花板效应 + 与实际棋力脱钩。
   要谈棋力应当用 `bench_anchor` 那种锚点对局。
3. **代理指标与目标脱钩**：本仓库已量过"一致率 3%→32% 而胜率一次都没动"
   （`docs/agents_design.md` §7.10）。本报告与那条负面结果一致：loss / 奖励 / 一致率
   都不能替代锚点对局的分辨力。

### 8.4 如果要继续改，按性价比排序

| 优先级 | 动作 | 依据 |
|---|---|---|
| 1 | **给 critic 加值域/尺度约束**：把 V 的目标 clamp 到 [−1.5, 1.5] 或对 TD 目标做归一化 | §5.2 的单调发散（0.063→13.4）；§5.3 显示尺度确实破坏搜索 |
| 2 | **换评估协议**：锚点对局（AB 深度 N 阶梯）+ 至少 100 局，报区间 | §2 基线太弱、§1 小样本无分辨力 |
| 3 | **动作空间换双射**（128 槽 → 8100）：SAC 的 π 目标与 Q 都带别名（同局面平均挤掉 5.16 个着法） | `docs/agents_design.md` §20.4/§21.2[1] |
| 4 | **PPO 补齐信任域**：ratio + clip + 熵项 + GAE/自举价值目标 | §8.2：现在它是行为克隆，不是 PPO |
| 5 | **目标熵 τ 调低**（0.98 → 0.5 量级）并检查 α 是否真的在动 | §8.1：α 恒为 0.200，实际没工作 |

## 10. 工具本身踩过的四个坑（都已修，都值得记住）

1. **每个 agent 各持一个私有棋盘 + 对局再用第三个** ⇒ 第二个走子的那一方永远被判成
   "走了非法走法"（它读的是自己那个还停在初始局面的棋盘）。
   现在所有 agent 绑定**同一个**棋盘。
2. **`train` 分支无条件访问 `A.sac`** ⇒ `--a=ppo` 时是空指针访问违例 0xC0000005，而且崩在
   "训练第一行之前"，看起来像"PPO 训练崩了"（我一度按这个方向查了很久，还去给 PPO
   源码加了追踪）。现在按 `Kind` 分派。
3. **未知 `--mode` 被静默当成 match** ⇒ 用旧二进制跑 `--mode=probe` 时它跑成了一场对局，
   而报告里差点把那一场的"比分"当成探针读数。现在未知模式直接拒绝执行。
4. **存盘文件名按位置拼** ⇒ 训练时 A/B 两个 agent 的文件名可能撞在一起（甚至出现
   "SAC 的权重文件里装的是 PPO 的权重"）。现在按 **`kindName()`** 命名，名字与内容一致。

教训与本仓库既有条目一致：**包装层必须按 kind 分派；凡是要给人当决策依据的读数，
自己必须先被钉住。**
