# 行为克隆 (BC) 训练：PPO agent 与 SAC agent (2026-10)

> 一句话：把 **"用 Alpha-Beta 的选点当监督信号、只训策略头"** 这件事从
> `bench_ppo_distill --actor=1` 里的一次性实验，做成**两条 agent 线上的生产路径** ——
> PPO 走与在线训练同一个 **R2 合法列口径**，SAC 三支（此前**完全没有** BC 路径）
> 走它自己的掩码 softmax 口径，并且**只动策略头**（critic 一个字节都不动，有测试钉住）。

> 读这份文档的三条入口：**§2.5 = 原理**（为什么这些式子写出来就是行为克隆、三个读数怎么来的）；

> 这类问题的公式化答案）。

## 1. 为什么需要它（全部是实测背景，不是推测）

这条线不是凭空加的，前面的每一轮都为它铺了一步：

1. **§7.7 价值头蒸馏：成功了，但选点没动。** 用 AB 深度 3 的根分值蒸馏 PPO 的 critic，
   留出 MSE 降 **4.2 倍**（0.0294 → 0.0069），而"与 AB 深度 4 的完整着法一致率"从
   3.0% → **2.0%**（噪声内）。诊断结论：瓶颈不是价值，是**先验（actor）还是随机的** ——
   中局 ~40 个合法着法、80~200 次模拟，树主要靠随机先验铺开，好价值头无从发挥。
   旁证：那时把模拟从 80 提到 200，探针数字**一动不动**。
2. **§7.8 行为克隆 actor：当前最有效的杠杆。** 1500 局面、AB 深度 3 的选点做交叉熵，
   prior top-1 0.0% → 4.8%（留出 7.0%），端到端一致率 **3.0% → 16.0%**（5.3×）。
3. **§7.9 加数据：scaling 被证实，"加步数"被排除。** 20000 局面：top-1 **33.6%**、
   P(AB) 0.192、留出 CE 3.49、探针一致率 **28.0%**；而 40 epoch 的对照更差
   （train/留出 CE 差 1.43 nats = 过拟合的量化证据）。
4. **§7.10 代理指标 vs 目标（最重要的负面结果）。** 一致率涨 9 倍（3% → 28%），
   对 AB 深度 4 的得分率 **5.0% → 2.5%（没动）**。所以 BC 是**课程起点**，不是棋力结论。
5. **R2（训练侧只算合法列）之后，这条 BC 路径变成"旧口径"。** 在线训练早已换成
   "softmax 分母 = 该局面的完整合法集（Z ≡ 1）"，而 `bench_ppo_distill --actor=1`
   仍是**全量 8100 维 softmax**（合法集上的概率质量 Z 实测只有 0.51~0.59）。
   `docs/issues_review.md` 的"已知缺口"里写着迁移它需要三件事：给样本存 legalIdx、
   改用稀疏口径并把 critic 那一路剥出去、把 CE/P(AB) 读数换成合法集口径。
   **本轮把这三件事全做了**（见 §4、§6），并且顺手补上了 SAC 那一侧 ——
   三个 SAC agent 类此前**一行 BC 代码都没有**。

<a name="s2"></a>
## 2. 它训练什么（口径）

监督信号 = **ABAgent 深度 D 的根选点**，one-hot；监督对象 = **策略头（actor）**。

* **状态**：用 agent **自己**的编码器（PPO：19 平面 × 90 = 1710；SAC+AZ 默认表示：
  1263 维），并且**规范视角**（轮到黑方时 x → 9-x）。
* **动作**：用 agent **自己**的 `stepToActionIdx`，**同一个 color**。
  ⚠ 这两处必须同一个 color —— 状态按黑方、动作按红方算，老师的着法会落到另一个坐标帧，
  典型后果是"目标不在合法集里"，而**那不是零梯度**：`L ≡ 0` 但 `dL/dz = π ≠ 0`
  （一条"对这条样本无效、却实实在在改别的局面权重"的伪梯度）。所以有两道闸门：
  造样本时 `sampleFrom` 返回 `SampleFail::TeacherIllegal`，内核里 `bcGradSparse`
  再查一次并**丢弃 + 计数**（`bcTargetMisses` / `UpdateStat::targetMiss`）。
* **损失**：合法集上的交叉熵，梯度直接写成 `dL/dz = π − t`：
  `L = −Σ_a t_a·log π_a`，`π = mask ⊙ softmax(z)` ⇒ `dL/dz_a = π_a − t_a`（合法列），
  非法列**恰好 0**。
  * SAC 那条等价的雅可比形式是 `g = (π − t)/π` 再经 `maskedSoftmaxBackward`；
    两者数学恒等，但本实现不用那个除法（`π → 0` 时会爆）。
    `test_bc [1]` 用**两条独立路径**对照 + 中心差分把这条钉死。
* **只动策略头**：
  * PPO：`bcGradSparse` + `bcApplyGradients` 整段**不含 critic 前向/反向**，也不写
    `lastLoss`（那是 critic 的 MSE）—— 这是结构性的，不是约定。
  * SAC 独立口径（`TrunkMode::Separate`）：只更新 `actor`，`q1`/`q2` 逐字节不变。
  * SAC 共享口径（`TrunkMode::Shared`）：**骨干会变**（策略梯度会改到共享表示，
    这是共享的固有代价），但 **Q 头自己的权重不变**。两种口径分开断言，
    因为把前者读成缺陷是最容易犯的错。
* **不做的**（明确列出）：value 目标蒸馏（本轮只克隆策略头，见 §1 第 1 条的实测理由）、
  镜像数据增广（PPO 在线路径有，BC 这一版没有：SAC 默认 128 槽哈希动作空间下
  "镜像动作"不是合法槽位，两支要分开做，先留着）、MCTS 访问分布当软目标
  （会变成"强化自己的先验"的自我循环）。

<a name="s2.5"></a>
## 2.5 原理：这套训练在数学上到底做了什么

> 这一节回答的是"**为什么这些式子写出来就是行为克隆**"，而不是"怎么调参"。三条读数的含义、
> 以及"一致率比 P(老师) 高说明什么"这类问题，全部由这里的公式推出来（见 §2.5.6）。
> 全部结论都能在代码里逐行对上：口径层 `src/rl/bc.cpp`、PPO 内核 `src/rl/ppo.cpp`
> 的 `bcGradSparse`/`bcApplyGradients`、SAC 胶水 `src/bcagent.hpp` 的 `update`。

<a name="s2.5.1"></a>
### 2.5.1 它属于哪一类学习：把"模仿"写成最大似然

老师是**确定性的**：在局面 s 上它选一手 `a*`，相当于目标分布

```
μ(a | s) = δ_{a*}(a)        (one-hot: 老师那一手概率 1, 其余 0)
```

行为克隆就是在这个目标上做**最大似然**（等价于最小化交叉熵）：

```
min_θ  E_{s~D}[ −log π_θ(a* | s) ]
```

把它写成 KL 就看清了它在优化什么：

```
E_s[ −log π_θ(a*|s) ]  =  E_s[ KL( δ_{a*} ‖ π_θ(·|s) ) ]        (因为 H(δ_{a*}) = 0)
```

（一般式是 `CE(p, π) = H(p) + KL(p ‖ π)`；这里 `p` 是 one-hot 所以 `H(p) = 0`，两项并成一项。
以后若接**软目标**（例如 MCTS 访问分布），那个 `H(p)` 就是一个与 θ 无关的**下界** ——
这时候"CE 降到多少算好"要按 `H(p)` 重新标定，不能再用 0 当目标。）

⇒ **最小化 CE ≡ 在每个状态上最小化"策略分布到老师那一手的 KL"**。这就是 BC 的全部原理，
剩下的都是"怎么把它算得准、算得稳"。

两点必须记住的性质：

* 这是**前向 KL**（`KL(老师 ‖ 学生)`），它的固有倾向是 **mode-covering**：当老师在某些局面上
  "几手都差不多"（近分好手多）时，前向 KL 更愿意把概率质量**摊到这些着法上**，而不是只压住
  一个。所以"软侧"（P(老师)）与"硬侧"（A 一致率）**不必同步**：实测的两个端点就是这样 ——
  **训练前 P ≳ A**（都贴着 1/合法着法数、摊平），**训练后 A > P**（分布变尖），见 §2.5.6。
  （这只说明两端点的方向；中间的轨迹本工程**没有逐点记录**，别把"谁先动"当成实测结论。）
* 它**不是强化学习**：数据里**没有回报**，只有 `(s, a*)`。任何"顺手把 critic/Q 也训一下"的
  写法都是拿错误的目标去拟合价值函数 —— 见 §2.5.4。

<a name="s2.5.2"></a>
### 2.5.2 一条样本、一次前向、一步梯度

样本（`RL::BCSample`）= 状态用**学生自己的**编码器 + **同一个 color** 的动作映射：

| 字段 | 含义 |
|---|---|
| `state` | agent 自己编码的观察（PPO 1710 维 / SAC 默认 1263 维；**规范视角**：轮到黑方时 x → 9-x） |
| `legalIdx` | 该局面**完整合法集**的动作下标（有序） |
| `targetIdx` / `targetProb` | 老师那一手（one-hot；结构上允许软目标，但本轮只产生 one-hot） |
| `posHash` | 去重用（CLI 报"去重 3993/4000"就是它） |

**前向**只算合法列的 logits，再过**掩码 softmax**（`Z ≡ 1`：分母只含合法列，于是合法集上
概率和恰为 1）。**损失与梯度**（`src/rl/bc.cpp`）：

```
L      = −Σ_a t_a · log π_a                     (one-hot 时 = −log π(a*))
∂L/∂z_a = π_a − t_a        (a 在合法集里)
∂L/∂z_a ≡ 0                (a 不在合法集里 —— 精确的 0, 不是"很小")
```

* 这条解析梯度与"softmax + 交叉熵"的雅可比推导、以及**中心差分**三条路在 `test_bc [1]` 里
  互相对过（最大差 `0.000e+00`）。SAC 那条等价的写法是 `g = (π − t)/π` 再走
  `maskedSoftmaxBackward`，数学恒等，但生产实现**不用**它（`π → 0` 时会爆）。
* **非法列必须恰好 0**：非零梯度会在若干步之后把非法着法的 logit 抬起来，而掩码一挡就看不见 ——
  直到某次掩码换了位置才暴露。这是本工程反复记过的一类静默错。
* ⚠ **"目标落空"不是零梯度**：若 `t` 不在合法集里，`Σt = 0` ⇒ `L ≡ 0`（看起来"这条样本没影响"），
  但 `∂L/∂z = π ≠ 0` —— 它会实实在在改**别的局面**的权重。所以有两道闸门：造样本时
  `BC::sampleFrom` 报 `TeacherIllegal`，内核里 `bcGradSparse` 再查一次并**丢弃 + 计数**
  （`bcTargetMisses` / `UpdateStat::targetMiss`，报告里的 `targetMissed=` 就是它）。

<a name="s2.5.3"></a>
### 2.5.3 一次更新做什么：批、优化器、节奏

| 项 | 值 | 为什么是这个 |
|---|---|---|
| 批 | 缓冲区里**最近 ≤32 条**（不足就用全部） | 一局只有几十手学生着法，攒够 64 条再更新 = 这一局白克隆 |
| 缓冲 | FIFO，上限 512 条 | "越近的局面权重越大"这件事是**显式**的 |
| 优化器 | **逐张量 RMSProp**：PPO `RMSProp(lr, 0.9, 1e-3)`；SAC `RMSProp(lr, 0.9, 0)` | 逐张量归一化 ⇒ 步长对张量尺度不敏感，"每手一次更新"的位移**有界**（不会一局跑飞） |
| 学习率 | **0.002**（与命令行 `train_bc` 默认一致） | 两条入口同一套口径 |
| 节奏 | 学生**每走一手**一次更新 | 见上（批那一行）；也是 `samples ≈ updates` 的原因 |

<a name="s2.5.4"></a>
### 2.5.4 为什么"只训策略头"是原理要求，而不是省事

BC 的数据里**没有回报信号**，所以：

* 用 `(s, a*)` 去训 critic / Q（它们的目标是**回报**）等于拿一个错误的目标去拟合价值函数 ——
  不是"少学了一点"，而是**往价值函数里灌噪声**。
* 具体风险形态：PPO 的 `lastLoss` 是 **critic 的 MSE**。若 BC 顺手写了它，界面上"损失在降"会被
  读成"BC 有效"（而那条曲线与老师半点关系都没有）。
* 所以这三条是**结构性**的、由测试钉住：PPO 的 BC 路径整段不含 critic 前向/反向、不写
  `lastLoss`；SAC 独立口径 `q1`/`q2` 权重文件**字节摘要不变**；SAC 共享口径骨干会变
  （共享表示的固有代价）而 **Q 头自己的权重不变**（`test_bc [4]`）。

<a name="s2.5.5"></a>
### 2.5.5 它能学到什么、学不到什么（以及两种训练分布）

* **学得到**：老师选点的**条件分布** —— "在这个局面上老师会走哪一手"。这是一个**静态映射**，
  里面**不含搜索**。
* **学不到**：① 老师强在"**搜索**"上的那部分 —— 一个静态函数装不下"搜了 D 层才知道"的信息
  （这条有受控对照：§7.11 换更强的老师**并不提升**克隆精度，d3 32.0% vs d4 28.4%）；
  ② 棋力（§7.10：一致率涨 9 倍而得分率不动）；③ 回报结构（数据里没有回报）。
* **上限就是所选那一档老师**（`--depth` / 界面下拉框），而"老师"本身也只是"AB 深度 D 的策略"，
  不是最优策略。

**两种训练分布，读数不可直接比**（这条经常被忽略，却决定了数字能不能引用）：

| 入口 | 局面从哪来 | 分布性质 |
|---|---|---|
| CLI `train_bc` | `makePosition`：从开局**均匀随机**走 `openingPlies` 手（只由 `seed + index` 决定） | **与权重无关、可复现**；偏"乱局" |
| 界面（对局中 / 人机） | **学生自己在真实对局里走到的局面** | 与对手、模式、当时的权重都有关；**不可复现**，但它正是学生自己的状态分布 |

在原理上，后者更接近模仿学习想要的状态分布（缓解 distribution shift）。但要注意：
**它不是 DAgger** —— DAgger 会在学生的状态分布上**反复**采样并问老师纠正（有交互循环，
能修正"学生走错之后越走越偏"的轨迹）；这一版只是把**采样侧**落在了学生的局面上，**没有**
"用学生自己行动的后果再问老师"的迭代纠正环节。

<a name="s2.5.6"></a>
### 2.5.6 三个读数与原理的对应（把"怎么读曲线"落成公式）

| 读数 | 定义 | 在原理里的身份 |
|---|---|---|
| **A 一致率** | `argmax_a π_θ(a) == a*` 在窗口里的频率 | 最大似然目标的**硬侧**；也就是 BC 的**训练目标本身** |
| **P(老师)** | `E[ π_θ(a*) ]` 在窗口里的均值 | 目标的**软侧**：前向 KL 里直接出现的那个量 `π_θ(a*)` 的期望 |
| **CE** | `−log π_θ(a*)` 在窗口里的均值 | **目标函数值本身**（最连续、最适合看趋势） |

两个数为什么可以"一个在另一个上方"（这是被问过的问题，答案就是下面这个恒等式）。记
`q = A`，`m₁` = 同意样本上老师那一手的平均概率，`m₀` = 不同意样本上的：

```
A − P  =  q·(1 − m₁)  −  (1 − q)·m₀
          同意时"没用满的概率"    不同意时仍留给老师的概率
```

⇒ **A > P ⟺ 分布尖（果断）**：同意时给老师很大的概率，不同意时给老师很小。
**P > A ⟺ 分布摊平（骑墙）**：不同意时老师那一手还留着不低的概率。

这条恒等式与实测完全一致（CLI 800 条留出样本）：

| 状态 | A | P | A − P | A/P |
|---|---|---|---|---|
| PPO 训练**前** | 2.26% | 2.7% | **−0.4pp**（P > A，摊平） | 0.84 |
| PPO 训练**后** | **35.71%** | 22.9% | **+12.8pp**（A > P，果断） | 1.56 |
| SAC 训练**前** | 1.38% | 3.1% | **−1.7pp**（P > A） | 0.45 |
| SAC 训练**后** | **41.73%** | 27.9% | **+13.8pp** | 1.50 |
| 全量 8100 口径（对照臂，训练后） | 21.68% | 6.6% | +15.1pp | 3.29 |

读法（与 §6.6 的曲线配套）：

* **两者同向上升、CE 明显低于 `ln(平均合法着法数)`** ⇒ 健康收敛（又像又果断）；
* **A > P 但 CE ≈ ln L** ⇒ 果断但学的是**它自己**（塌成固定偏好），先查窗口局面是否单一、
  `onlineSteps=` 是否在线训练在拉扯；
* **P > A 或两者贴在一起** ⇒ 摊平：常见于训练早期、老师更深（近分好手多）、合法集很大；
* ⚠ **噪声门槛**：窗口 n=64 时 A 的 1σ ≈ 6pp，n=8（最小值）时 ≈ 18pp ⇒ `A − P` 只有几个
  百分点时不要读（`均值/最小/最大/k 点` 一起看）。跨窗口、跨场、**跨老师档位**都不可直接比。

<a name="s2.5.7"></a>
### 2.5.7 失效模式：原理 → 现象 → 该看哪个数

| 失效 | 原理上的原因 | 读数（都在界面上） |
|---|---|---|
| 完全没在学 | 老师 = 关 / 模式不是训练对局 / 场上没有学生 | `samples=0 updates=0`，面板写明原因 |
| 伪梯度 | 目标不在合法集（视角/索引错位） | `targetMissed>0`（且 `L ≡ 0` 却改了别的局面） |
| 塌成常数策略 | 前向 KL + 单一局面分布 | A 升而 CE 不降；CLI 里能看到熵掉向 0 |
| 过拟合 | 数据量受限 | **train−留出 CE 差**（CLI；4000 局面实测 0.53~0.57） |
| 两个目标互相拉扯 | 在线训练（探索+预训练）同时改**同一张策略头** | `onlineSteps>0`（见 §6.5.1） |
| 读数自欺 | 混了两个口径的 CE | 读数行的"最近 CE"= **64 条窗口**；报告的"批平均 CE"= **每次更新的批** |

<a name="s2.5.8"></a>
### 2.5.8 与在线 RL 的关系：同一张头、两个不同的优化问题

```
在线 RL:  max_θ  E[ 回报 ]              (PPO 的 clip 目标 / SAC 的 soft-Q)
BC:       min_θ  E_{s~D}[ −log π_θ(a*) ] (老师的选点, 掩码交叉熵)
```

两者写的是**同一张策略头**（所以可以同时开、互不阻塞，各自持锁），但它们是**两个优化问题**：
同一个参数上交替走下坡（各自下自己的坡）。因此读数必须分开看：BC 的 CE/一致率在面板与
`行为克隆 (BC)` tab，在线训练的 loss 在损失曲线；**BC 刻意不写 `lastLoss`，所以 BC 的更新在
损失曲线上一个点都没有**（那正是"两个口径别混着比大小"的落地方式）。

## 3. 怎么跑

```bat
:: ---- 界面这条路 (推荐先试) ----
:: 启动 chess.exe -> A/B 面板上把"行为克隆训练"下拉框选成某一档 Alpha-Beta
::                 (老师; 与对手是谁无关 —— 对手可以是别的 agent, 也可以是人)

::              -> 读数进下面的"模型自检"面板, 曲线进"行为克隆 (BC)"那个 tab

:: train/留出 CE 差会告诉你"是不是该加数据了"。

cmake --build <build> --target train_bc

:: PPO+MCTS (MLP 专家骨干 —— 便宜 ~25x, 冒烟与小实验用它)
<build>\train_bc.exe --agent=ppo-mlp --positions=4000 --depth=3 --epochs=8 ^
                     --opening=8 --seed=20240901 --save=weights/bc_ppo_mlp_d3

:: SAC+AZ (纯 MLP)
<build>\train_bc.exe --agent=sac --positions=4000 --depth=3 --epochs=8 ^
                     --opening=8 --seed=20240901 --save=weights/bc_sac_d3

:: 界面现役骨干 (TB 专家; 建网/内存都贵: actor+critic 约 2.4 GB, 存盘约 1 GB)
<build>\train_bc.exe --agent=ppo --load=weights/ppomcts_agent --save=weights/ppomcts_bc

:: 对照臂: 全量 8100 维 softmax (旧口径, 与 bench_ppo_distill 同源)
<build>\train_bc.exe --agent=ppo-mlp --masked=0 --positions=4000 --depth=3 --epochs=8

:: 其余开关: --agent=sac-moe-mlp | sac-moe (TB) / --shared=1 (共享骨干) /
::           --hidden= --expert= --lr= --batch= --holdout= --report-every= /
::           --seed= --load= --save= --max-positions= (冒烟截断)
```

`--save` 写的是**与界面同一份格式**的权重（PPO：`_actor`/`_critic`；SAC：`_actor`/`_q1`/`_q2`，
共享口径 4 个文件），结构指纹与 CRC 照旧 —— 所以可以直接在界面上选中那个 agent 载入。

## 4. 一个刻意的重构：稀疏策略内核被两条路共用

`RL::PPO::accumulateGradSparse`（在线 R2）与 BC 的差别**只有中间那一步**
（dlogit 是 ratio 裁剪 / 是 `p − t`）—— 前向（`forwardTrunk` + 只算合法列的 logits +
合法集 softmax）与反向（头的合法行权重梯度 + `backwardFrom` 走骨干）是同一件事。
本轮把这两段抽成 `sparsePolicyForward` / `sparsePolicyBackward`，两条路共用。

理由就是本工程反复记过的那条账：**同一个口径写两份必然漂移**（"合法列 Z≡1"这条
曾经修过一次缺陷，再复制一份迟早只剩一份是对的）。

**证据（回归不是靠"我读了一遍"）**：
* `test_grad`：解析梯度 vs 中心差分（**有限差分是独立于实现的判据**），
  `合法集上 Σ(p − t) = 0.000e+00`，15 项断言全过；
* `test_ppomcts`：**测试13（R2 训练侧只算合法列）** 全过，读数 ——
  稀疏 `P(target0)=0.5812` / 全量 0.6424、**非法行 #0 的梯度 稀疏 = 0.000e+00**（全量 2.466e-04）、
  信任域位移 `140.83 / 149.35 / 163.36`（eps=0.05 / eps=1.0 / 无 p_old），
  以及 MoE 负载均衡接线那一节 —— 全部通过；
* `test_weights`(49 项) / `test_diag`(68 项) / `test_pretrain`(38 项) 全过；
* `ctest -E "test_match|test_mcts"`：**14/14 通过**（含 `test_ppomcts` / `test_sacaz` 385 项 /
  `test_sparse_moe` / `test_dqnab` / `probe_hvai_flow`）。

> **没有做的一件事（如实写）**：本轮**没有**做"参照二进制逐位对照"（repo 里 `build/ref/`
> 那种手法）—— 那份参照是 2026-09 的，写成这条时它早于 2026-10 的 TB E=8/top-2 改动，
> 已经不构成可比基线。所以这里的结论是"**同一个口径的两条路共用一份实现 + 独立判据（有限
> 差分、非法行梯度恰为 0）通过**"，而不是"与旧二进制逐位相同"。要补这一条，需要先从
> `git stash` 出来的旧源码构一份参照二进制再跑同一批种子。
>
> ⚠ **[2026-10 追加] 那个"不可比"的理由已经消失了一半**：`TB` 的 E/top-k 已按用户口径
> **降回 4/1**（`rl/ppo.h`，见 `docs/moe_gate_experiment_2026_10.md` §14），而 2026-09 那份
> 参照二进制**正是 4/1 时代的** ⇒ 结构参数这一层重新对得上。但这**不等于**现在就能直接
> 逐位对照：2026-09 至今还有别的改动（R2 的稀疏训练头、无辅助损失偏置那个非参数缓冲、
> 各种搜索/训练路径调整），要补这条仍然得**现场核一次 `paramCount` 与结构指纹**再决定
> 拿哪一份参照，不能凭"E/k 一样了"就假定可比。

## 5. 实测读数（本机 MSVC Release + AVX2，4000 局面 / AB 深度 3 / 8 epoch / lr 0.002）

标注成本对三行是同一个数：**16 ms/局面**（4000 局面 ≈ 64 s；`老师无有效着法 7`、
`局面无合法着法 0`、**`老师着法不在合法集 0`** —— 视角一致这条由它证明，
去重 **3993/4000** 个互不相同的局面）。

| 配置 | prior top-1（训练 / 留出） | P(老师)（留出） | CE（训练 / 留出） | train−留出 CE | 训练耗时 |
|---|---|---|---|---|---|
| **PPO+MCTS (MLP 专家)，合法列口径** | 2.28% → **40.25%** / 2.26% → **35.71%** | 0.027 → 0.229 | 3.663 → **2.006**(1.83×) / 3.660 → **2.577**(1.42×) | **0.571** | 43.5 s / 400 次更新 |
| **SAC+AZ，合法列口径** | 1.00% → **52.02%** / 1.38% → **41.73%** | 0.031 → 0.279 | 3.536 → **1.699**(2.08×) / 3.530 → **2.228**(1.58×) | **0.529** | 6.1 s / 400 次更新 |
| PPO+MCTS (MLP 专家)，**全量 8100 口径**（对照臂） | 0.00% → 19.56% / 0.00% → 21.68% | 0.00012 → 0.066 | 9.018 → 4.190(2.15×) / 9.019 → 4.723(1.91×) | 0.532 | 87.6 s / 400 次更新 |

三条读数：

1. **两条 agent 线都真的学得动**：留出集上的 CE 分别降 1.42× / 1.58×、top-1 从
   1~2%（随机水平：PPO 是 1/40 的合法集 ≈ 2.5%，SAC 是 1/128 槽 ≈ 0.8%）
   涨到 **35.7% / 41.7%**。**训练目标本身在留出集上成立**，不是背下了训练集。
2. **train−留出 CE 差 0.53~0.57 nats**，落在 §7.9 划出的"数据受限"区间
   （1500 局面时是 1.43 = 明显过拟合，20000 局面时 0.37）。也就是说 4000 局面这一档
   还远没到"该加步数"的地步，**下一个杠杆仍是数据量**（标注 16 ms/局面，10⁵ 局面 ≈ 27 分钟）。
3. **两个口径的代价是量出来的**（同一份数据、同一个老师、同一个种子）：
   全量 8100 口径的留出 top-1 只有 **21.68%**（合法列口径 35.71%）、CE 高 2.1 nats、
   训练时间 **翻倍**（87.6 s vs 43.5 s）。这不是"实现差异"，是**学习问题不同**：
   全量口径把概率质量分给非法槽位（Z ≈ 0.5），合法集上的信号被稀释。
   ⇒ **R2 之后要存 BC 权重，就应该用合法列口径**（`--masked=1`，默认）。

> ⚠ 这三行**不是棋力读数**。§7.10 已经给出过反例：一致率涨 9 倍而胜率一动没动。
> 要谈棋力只有 `bench_anchor`（固定开局集 + 换先手成对 + 95% 区间）能回答。

<a name="s6"></a>
## 6. 三个"静默失败"与它们各自的读数

BC 这一层的失败模式几乎全部是**静默**的（跑得挺快、损失挺漂亮），所以每一类都有一个
**被数出来的**读数，而不是靠"应该没问题"：

| 静默失败 | 后果 | 读数 / 闸门 |
|---|---|---|
| **目标不在合法集里**（视角/索引算错） | `L ≡ 0`（读数完美）而 `dL/dz = π ≠ 0`（**不是零梯度**：把该局面所有合法 logit 一起抬高） | `sampleFrom` 返回 `SampleFail::TeacherIllegal`；内核 `bcTargetMisses` / `UpdateStat::targetMiss`；内核**丢弃**该样本（不是"学一条没信息的"） |
| **口径静默退回全量**（头不支持稀疏 / `maskedTrainHead=false`） | 损失照降，但学的是另一个归一化问题（Z < 1），权重与在线训练的尺度不兼容 | PPO 自检打印 `bcSamples / bcSparseSteps`：两者不相等时就出声明"没有一个样本走合法列口径" |
| **critic 被顺手训了**（"BC 只动策略头"破了） | 价值头被一个与它无关的目标推着走，而且看不出来 | PPO 结构上不含 critic 那一段；`test_bc [4]` 用**权重文件字节的 FNV 摘要**断言 critic / q1 / q2 逐字节不变；`lastLoss` 也断言未被写过 |

另外一条同样属于"读数自带前提"的：`Metrics` 里的 `entropy`（合法集上的策略熵）——
BC 会把策略推尖是预期的（PPO 3.65 → 2.01），但**熵掉到 0 附近就是塌了**，
这个数不报出来就没法区分"学好了"与"塌成一招"。

## 6.5 界面入口（2026-10 追加：把它接进 chess 程序）

**用户口径（第三轮，按原话改的）**：*"行为克隆勾选框改成下拉框选择要克隆的 abagent，
与将要对弈的对方 agent 或者人类棋手无关，训练的时候参考下拉框选择的 abagent 的决策
进行行为克隆训练"*。于是界面上是**一个下拉框**（在"局数/预训"那一组上面）：

```
[A ▾ PPO+MCTS (AlphaZero, 稀疏MoE+MLP专家)]  [B ▾ MCTS (800次模拟)]   ← 对手**不是** AB 也行
行为克隆训练: [克隆 Alpha-Beta L2(深2) (depth=2) ▾] [ ] 软目标 (多深度一致)
                     ↑ 关 / L1 / L2 / L3 / (深度=4)      ↑ §9 的目标形态开关 (默认不勾)
--------------------------------------------------------------
模型自检 (自动更新)
  …（权重文件状态 / 结构口径 / MoE 负载 …）
  [BC] 曲线已建线 (chart-armed): 老师=Alpha-Beta L2(深2) [teacher-depth=2] [mode=human]
  [BC] 克隆 AB 的着法: samples=1 updates=1 批=1 CE=2.3068 (目标落空 0) [teacher-depth=2 soft=1]
  ---------- 最近一次行为克隆 (BC) ----------
  === 对局中行为克隆 (BC): 学生=PPO+MCTS-MLP, 老师=Alpha-Beta L2(深2) (下拉框选) [teacher-depth=2] ===
  本场汇总 (match-summary): samples=8 updates=8 targetMissed=0 onlineSteps=0 soft=1
  软目标 (soft targets, 多深度一致): 软样本=8/8 targetH=0.1733
  批平均 CE: 第一条 2.3068 -> 最后一条 2.2663 (降 1.02x)
  口径: 只更新**策略头** (PPO 的 BC 路径整段不含 critic; …), 目标是**软分布** …
  [注] 只改了**内存里的权重**: 与既有约定一致, 唯一的落盘点是退出程序时 …
```

上面的读数是**本机实测**（`-SkipHuman` 之外的默认路径，老师 depth=2 + 软目标勾上；
`soft=` 与 `targetH=` 见 §9，`[teacher-depth=2 soft=1]` 里那个 `soft` 就是那个复选框）。
⚠ **老师选 L1 时软目标会退化成 one-hot**（深度 1 只有一票 ⇒ `H(t)=0`），报告里会明说 ——
所以验证脚本的默认老师是 **depth=2**（见 §6.5 的验证一段）。

**这一轮改的是口径本身，不只是控件形态**（三件事，必须一起看）：

| 上一版 | 这一版 | 为什么必须改 |
|---|---|---|
| 老师 = **对面的那个 AB** | 老师 = **下拉框里那一档 AB**（`m_bcTeacherDepth`，0 = 关） | 用户口径：与对手无关。对手换成 MCTS 或**人**，BC 照旧 |
| 采样时机 = **对手(AB)走的那一手** | 采样时机 = **学生自己要走的那一手**所在的局面 | 老师不再由场上的人充当，就没有"对手那一手"可抄；而"学生自己的局面"本来就是它真要做决策的分布（BC 的标准口径） |
| 可用条件 = "恰好一边 AB + 一边可训练" | 可用条件 = "**场上至少有能做的学生**"（`bcHasStudent` = A/B 任一侧 `bcSupported`；人机那条路的"学生"是"对战AI") | 老师不再是配对的一半，配对条件里只剩"有没有学生" |

**老师那一手是现场搜出来的，且只用局面副本**（`bcOnStudentMove`）：在 `Chess` 副本上
`ABAgent(depth).getBestMove(color)` —— 深度取自下拉框（1/2/3/4 = L1/L2/L3/(深度=4)）。
用副本不是洁癖：AB 搜索会真的 `moveForward/moveBack` 并改 `history`，直接拿样本局面去搜，
搜索过程就会被写进这条样本的**状态编码**里（编码要看规则历史），样本当场被污染而且看不出来。
代价：每手多一次 AB 搜索（深度 1 约 3 ms、深度 4 约 90 ms，见 `test_ab` 的实测），相对一步
决策（MCTS/PPO 0.3~3 s）可以忽略；而且它**不属于**任何临界区（不碰 agent、不碰共享 `env`）。

**人机那条路也接了**（用户口径里的"人类棋手"）：`humanTurnAiMoveForTest`
（`aiThink` 与测试钩子共用的那一份）在决策之后、落子之前调 `bcSampleForHumanTurn`，
它自己从棋盘锁里拷一份局面，然后与对局循环**共用同一段** `bcOnStudentMove`。三个闸门
逐条对齐（老师 ≠ 关 / 模式 = 训练对局 / 这一支能做学生），否则"人机能偷偷改权重"就会重演
P0-b 那个洞。人机没有"场"的概念 ⇒ 读数**按一局**归零（第一次采样时归零一次，
终局/重开时清标志）；报告正文也因此**每做一次更新就刷新一次**（面板在别的时机整段
`setPlainText`，只在场末写的话人机里读不到任何读数）。

**人机那条路的"曲线"是 2026-10 补上的**（用户口径："补上人机对弈 BC 训练的 BC 曲线显示"）。
缺口的形态值得记下来，因为它是**静默**的：曲线那两条线是在 `matchStarted` 里建的，而
`matchStarted` **只有 Agent 对 Agent 才有**；`CurveChart::addPoint` 在序列不存在时是
**静默 `return`** ⇒ 人机里 BC 明明在训练（面板 `samples=`/`updates=` 一直在涨），**曲线却永远空白**，
而"空白"在界面上没有任何读数能区分"没建线"与"建了线但样本还不够"。

修法三件事（都是"把静默那一半堵掉"）：

1. 新增 `ChessBoard::humanGameStarted` 信号：在 `setHumanGameInProgress` 的 **false→true 跳变**
   （= 玩家落下本局第一子）发一次 —— 人机没有"场"，所以**每局一次**，与"人机读数按局归零"同一口径。
   按"玩家第一子"而不是"按了开局"算，与"对弈期间权重不落盘"那条的起算口径逐字一致。
2. 建线判据抽成**唯一一处** `MainWindow::armBcChartSeries(studentAvailable, teacherDepth, humanMode)`：
   Agent 对局（`resetMetricsForMatch` ← `matchStarted`）与人机（← `humanGameStarted`）共用它，
   顺带**清线**（横轴是"这一场/这一局的第几次 actor 更新"，不清线会把两局的 4,8,12… 接成一条假时间轴）。
3. 面板里留一行**机器可读的"曲线准备好了没有"**（`[BC] 曲线已建线 (chart-armed) … [mode=human]`）——
   因为"图上是空白"有两种原因（没建线 / 样本不够 8 条），而下一步动作完全不同。

另外给 `CurveChart` 的 **accessibleName 加了点数后缀**（`<标题> · n=<点数>`）：Qt 的 UIA 桥
**不暴露 Description**（读出来是空串），所以"曲线真的在长"只能靠 Name 观察 ——
这也是验证脚本能断言"人机那条路真的画出了点"的唯一通道（见下面的断言清单）。

**对比第一版（已删除）**：曾经有"行为克隆 [局面数][老师深度][epoch][开始行为克隆]"那一行 ——
那是"单独跑一次 BC"，与口径不符，所以连它依赖的 `ChessBoard::startBehaviorCloning` /
`m_bcThread` / `bcFinished` 信号一起**整个删掉**了（不是留着不用）。单独跑一次 BC 仍然可以，
但走命令行 `train_bc` —— 它不占界面，参数也全开。

<a name="s6.5-mechanism"></a>
### 机制：对局循环 / 人机路径里的钩子

| 时刻 | 位置 | 做什么 |
|---|---|---|
| 学生那一手**落子之前**（对局） | `playMatchGame` 的棋盘锁内 | 判 3 个条件并**拷一份局面**（`Chess bcPos = chess`）：下拉框 ≠ 关 / 模式是训练对局 / **走这一手的这一方**是能做 BC 的学生 |
| AI 决策之后、落子之前（人机） | `humanTurnAiMoveForTest` | 同一个判据；局面由 `bcSampleForHumanTurn` 在棋盘锁里拷一份 |
| 该手之后、下一手之前 | 棋盘锁外 | 在副本上搜出老师的着法 → `BC::sampleFrom` 造一条样本（学生自己的编码口径 + 同一个 color）→ 进 FIFO 缓冲（上限 512 条）→ **立刻**做一次 actor 更新（批 = 缓冲里最近 32 条，不足就用全部） |

四个刻意的选择：

| 决定 | 为什么 |
|---|---|
| 样本在 **moveForward 之前**取 | 那一刻棋盘还是"学生将要走的那一步"的原局面 —— 与同一处的吃子读数、学习口径即时奖励是**同一个时序要求**（三处必须在同一刻取）。做法是在锁内拷一份局面、出了锁再干活，于是锁的顺序只有一种：棋盘 → agent |
| **学生每走一手更新一次**（不攒 64 条） | 一局只有几十手，攒批等于这一局白克隆。批不足时用全部样本，所以第一条样本就产生一次真实更新（脚本能在一秒内断言到它） |
| **只在"训练对局"模式生效** | 评估/只对弈声称"权重不变"，而 BC 是学习 —— 让它在那两种模式下偷偷改权重，正是 P0-b 修掉的那类静默失效。选了老师但没生效时，面板里会**说明原因**（模式不对 / 场上没有学生） |
| **不做"暂停后台训练"这一层** | BC 只持 agent 锁**几毫秒**（一次 actor 更新），不整段占用 agent；后台训练每轮把 clone 权重同步回来时，学到的是"BC 之后的权重"，不是把它覆盖掉（与"单独跑一次 BC"那种分钟级占用是两回事） |

**"能不能选"只有一处实现**：库侧 `ChessBoard::bcHasStudent(a, b)`（A/B 里有没有学生）
+ `bcSupported(对战AI)`（人机那条路的学生）；界面在 A/B、对战AI、对弈开始/结束、
启动完成时各重算一次（`MainWindow::updateBcMatchControlsEnabled`），并把**原因**写进 tooltip。

<a name="s6.5.1"></a>
### 6.5.1 能和"探索+预训练"（rollout 预训练）同时开吗？—— 能，而且两条路各自有读数（2026-10 用户提问）

用户问：*"勾选行为克隆训练后能否勾选 rollout 预训练"*。**代码层面**：两者**互不相干** ——
BC 那条路一行都没碰 `preTrainCheck`（`grep preTrainCheck src/mainwindow.cpp` 只有三处：
构造接线、启动禁用、开赛时 `setPreTrainEnabled`），BC 下拉框的启用判据也从不看它；
反过来预训练的开关也不影响 BC 的下拉框。所以**两个可以同时开**。

但"能开"不等于"都真的在跑"，所以报告里多了一个计数器（`onlineSteps=`，见下），并且脚本
多了一条 `-KeepPreTrain` 路径来量它。**两条路各自改的是同一张策略头**，所以读数必须分得开：

| 路径 | 每手做什么 | 它的读数 |
|---|---|---|
| 行为克隆（本功能） | 学生局面 → 下拉框那一档 AB 的着法 → **掩码交叉熵**更新策略头（PPO 路径整段不含 critic） | 面板里 `samples= / updates= / CE=`，曲线在 `行为克隆 (BC)` tab，`[teacher-depth=N]` 标明老师 |
| 探索+预训练（rollout 预训练） | 从当前局面用自己的策略 rollout ≤`preTrainSteps` 步 → `learnBatch` 在线更新 | 损失曲线（`trainLossSample`）；报告里的 `onlineSteps=` = **这场里在线训练上报过多少次损失** |

**实测（同一份 Release 二进制、真界面 UIA，`verify_bc_ui.ps1`）**：

```
:: 默认路径（脚本把预训练关掉, 只为了让检查快）
info  onlineSteps (在线训练/探索+预训练 上报损失的次数): 0   (KeepPreTrain=False)
      本场汇总 (match-summary): samples=8 updates=8 targetMissed=0 onlineSteps=0

:: -KeepPreTrain（预训练**开着**, 与 BC 同开）
PASS  pretraining checkbox still ENABLED while a BC teacher is selected
PASS  pretraining checkbox is ON together with the BC teacher (both can be on)
      本场汇总 (match-summary): samples=8 updates=8 targetMissed=0 onlineSteps=8
PASS  pretraining stayed ON and really trained alongside BC (onlineSteps>0)
RESULT: PASS
```

即：**两个都开着时，BC 的 8 次策略头更新与在线训练的 8 次损失上报同时发生**；关掉预训练
之后 `onlineSteps` 是 **0**（这条对照很重要 —— 它证明这个计数器不是恒为正的装饰）。

> ⚠ 顺带记一条方法学：这个断言的第一版是去读损失曲线的 **HelpText**（`count=`），
> 实测 Qt 的 UIA 桥**根本不暴露 HelpText**（读出来是空串 —— `verify_match_ui.ps1` 里
> "loss chart = " 那一行其实一直是空的，只是被 `if ($desc -ne "")` 静默跳过了）。
> 所以"某条路有没有真的跑"必须有产品自己打印的**机器可读计数器**，不能指望无障碍属性。

**同时开的两个代价（都要知道，不然读不懂读数）**：

* **读数会混**：损失曲线是**在线训练**的口径，BC 的 CE 在面板/BC tab 里 —— 两条曲线量的是
  两个目标，别放在一起比大小（BC 刻意不写 `lastLoss`，所以 BC 的更新在损失曲线上
  **一个点都没有**，这不是 bug）。
* **每手更慢 ⇒ 同样时间里 BC 更新更少**：预训练每手多跑 ≤`preTrainSteps` 步 rollout + 一次
  `learnBatch`（实测 PPO+MCTS-MLP 从毫秒级涨到秒级），而 BC 是**每手一次**更新，
  所以"一分钟练了多少次"会掉下来。脚本默认正是为了这个才关掉预训练。

  **真实点击**让人走一步 → 等 AI 应手 → 断言 `bcReportText()` 里
  `samples=1 updates=1 targetMissed=0 [teacher-depth=1]` → 再把下拉框拨回"关"重下一局，
  断言样本数**不再增长**（开关真的关掉了）。本机实测 `失败项: 0`。

  ```
  [E] 人机对战里的行为克隆 (老师来自下拉框, 与人无关)
    [ OK ] [BC] AI (学生) 在人机里应手了一次
    [ OK ] [BC] 报告里的老师 = 下拉框选的那一档 (teacher-depth=1)
    [ OK ] [BC] 下拉框 = 关 时不再产生新样本 (开关真的关掉了, 不是一直开着)
  ```

* `verify_bc_ui.ps1` 的 **human game** 段（曲线本身）= 选"对战AI" = PPO+MCTS-MLP、
  老师 `depth=2`、按"开局"，然后**真的点棋盘**下这一局（盲走红兵）。
  ⚠ 这一段现在**可以整段关掉**（`-SkipHuman`，2026-10 用户口径"不进行人机对弈测试"）；
  需要它时把开关去掉即可:

  ```
  PASS  human game: the AI side is a BC-capable student  (PPO+MCTS (AlphaZero, 稀疏MoE+MLP专家))
  info  arm marker: [BC] 曲线已建线 (chart-armed): 老师=Alpha-Beta L2(深2) [teacher-depth=2] [mode=human]
  PASS  human game: the arm marker arrived ([chart-armed] … [mode=human])
  PASS  human game: the BC curve got armed (series created) [chart-armed]
  PASS  human game: armed with the dropdown teacher (depth=2)
  PASS  human game: BC produced a live line in this game (samples=)
  PASS  human game: >= 8 updates, so the BC curve drew points (chart n=1)
  RESULT: PASS
  ```

  > ⚠ 这一段的**两幕要预期**：脚本不会看局面，红兵盲走 ⇒ **AI 会把红方将军/将死**
  > （用户在自己的屏幕上就看到了"被将军了 / 黑方已经胜利"）。所以断言分两层，见下；
  > 默认只跑 75 s，不值得让人盯着屏幕看自己输。

**"曲线出点"是条件断言**（这一条很重要，别把它读成"脚本不稳定"）：保真度第一个点要
**≥8 次 actor 更新**（`kBcFidEvery=4` × 窗口下界 `kBcFidMin=8`），而人机那条路的曲线**每局清零**
⇒ 一局没走到 8 手（被将死 / 预算用尽 / 候选着法用尽）时，曲线**本来就不该有点**。
所以脚本断言的是：**只要面板出现这一局的 `samples=8`，曲线就必须已经有点**（实测触发过：
`chart n=1`）；没到 8 就打印一行"跳过 + 原因"。两条**确定性**断言（建线 + 这一局有
`samples=` 行）不依赖走了多少手。

六条这一轮踩出来的教训（都留在脚本/探针的注释里）：

1. **必须在等待"启动完成"之后再断言**：预加载期间界面把所有交互控件都禁用了，
   `agentComboBox` 重新可用的那一刻才是判据（第一版在加载中就去断言，报了一个假的 FAIL）。
2. **"机器要读的记号用 ASCII"**：汇总行写成 `本场汇总 (match-summary): samples=…`，
   老师档位写成 `[teacher-depth=2]`（实时行里是 `[teacher-depth=2 soft=1]`）。
   ⚠ **[2026-10 追加一条]** 正则**别把"方括号紧跟数字之后"当作结束**：实时行在 `teacher-depth=`
   后面多了 ` soft=`，于是原来那条 `\[teacher-depth=([0-9]+)\]` 在**产品完全正确**的情况下
   失配（本机实测的第二次假失败）。现在的模式是 `\[teacher-depth=([0-9]+)\b`，
   并且期望的档位是从 `-TeacherItemMatch` 里解析出来的 `$TeacherDepth` ——
   "脚本选 depth=2 而断言里写 depth=1"这种漂移一次也不该再发生。
3. ⚠ 正则别指望记号**紧跟着冒号**：产品写的是 `(match-summary): …`，所以 `match-summary:` 什么也
   匹配不到 —— 而当时面板里明明有那行字。诊断脚本把两件事分开打印
   （`panelTextHasSummary=True` + `editTextContainingFound=True` + 匹配结果为空）才定位到它。
4. ⚠ **读到"对局中的读数"不能只等报告正文**：正文只在面板刷新时机整段重写，而对局进行中
   面板主要在**追加**实时行（这个脚本还把每手预训练关了）。所以老师档位放进实时行里断言——
   第一版去等正文里的 `teacher-depth=`，结果 FAIL 时那行字其实就在面板里（只是要等对局结束）。
5. ⚠ **Qt 的下拉框项是懒建的**：不展开时 `FindAll(Descendants)` 在组合框上返回 **0** 个元素
   （第一版的正则/断言因此输出空列表）。要展开之后再取，而且取**展开前后桌面 ListItem 的差集**——
   直接枚举"当前可见的 ListItem"会把对局明细列表、面板文本一起算进来（第一版的输出里出现了
   "(还没有对局)" 与一串构建目录文件名）。
6. **脚本必须自己证明"程序关掉了"**：它**杀掉**进程而不是关窗（关窗会触发 app 的退出保存，
   把用户的权重换成刚克隆的那份），而且最后再 `Get-Process chess` 复查一次 —— 一条
   "关掉了没有"的断言比一条"我以为我杀了它"可靠。**脚本被中途打断时窗口会留在屏幕上**
   （任何外部中断都会这样），再跑一次就收干净。

> ⚠ 脚本是 **ASCII-only** 的：无 BOM 的 UTF-8 `.ps1` 会被 Windows PowerShell 按 ANSI 解码，
> **代码里**的中文会拆成非法字节、直接把脚本解析坏（注释里的没事）。所以所有断言都匹配
> 产品自己打印的 ASCII 记号（`match-summary` / `samples=` / `updates=` / `CE=` / `teacher-depth=`）。
> 这是本工程第四次踩这条（见 `verify_moe_load_view.ps1` 的说明）；**改完必须核前三个字节是
> `EF BB BF`** —— 编辑工具会把 BOM 顺手吃掉。
>
> 另外：这一条脚本**不做**"weights/ 没变"的断言 —— Agent 对弈结束时 app **本来就会**把双方
> 权重写回标准路径（那是既有行为，`verify_chess_saves_weights.ps1` 专门测它）。BC 自己不落盘这
> 一条是**结构性的**（对局中那条路只调 actor 更新，代码里没有任何 save），报告里也写着。

## 6.6 可视化：一条"保真度"曲线（2026-10 追加，用户口径"在 loss 曲线窗口增加一个 tab"）

原来 BC 的效果**只以文本存在**（面板里的进度行 + 每场汇总 + 命令行报告），**一条曲线都没有**：
损失曲线画的是 critic 的 MSE（BC 刻意不写它），奖励曲线画的是"下成什么样"。所以这一轮把
"克隆得像不像老师"这件事画出来：

```
右侧面板:  [ 训练损失 (loss) ][ 行为克隆 (BC) ]      ← 两个 tab，不额外占列高
           ┌───────────────────────────────────────────┐
           │ 行为克隆保真度 (每 4 次 actor 更新一个点,   │
           │ 最近 64 条样本窗口)                        │
           │   ── 一致率 (策略头 top-1 == 老师那一手)    │  0~100 %
           │   ── P(老师着法)                           │  0~100 %
           └───────────────────────────────────────────┘
           克隆保真度 一致率: 最新 75, 均值 75 … | P(老师着法): 最新 53.5 … | 最近 CE 1.0685 (窗口 8 条)
```

五个刻意的决定：

| 决定 | 为什么 |
|---|---|
| **画"一致率"与"P(老师着法)"两条线** | 这两条是**同一个量纲**（都是百分比），所以一根纵轴不会出现"两个口径比大小"。`CurveChart` 只有一根轴，混量纲的线画在一起就是本工程反复记过的那个坑 |
| **CE 不进曲线**，改放图下读数行 | CE 是 nats（0~10 量级），与 0~100 的百分比画在一起会被压成一条贴底直线，读起来像"CE 恒定" |
| **横轴 = actor 更新次数**（不是手数/时间） | BC 学习只在"AB 走完一手"时发生；用手数当横轴会把"对手没走"的空档画成停滞 |
| **窗口 = 最近 64 条样本**，每 4 次更新一个点 | 想看的趋势是"**当前**水平"，不是全程平均（全程平均会把早期很烂的部分永久混在里面）。窗口少于 8 条不算点：1 条样本上的"一致率"只有 0% 或 100%，那是噪声 |
| **代理指标的警告写进图标题** | 一致率是 BC 的**训练目标本身**：它上升只说明"克隆成功了"。`docs/training_optimization.md` §7.10 的负面结果（一致率涨 9 倍而胜率没动）就写在那行标题里，免得曲线被单独引用成棋力 |

数据源与命令行**同一份实现**（`BC::evaluate`）：对局线程每 4 次更新取缓冲里最近 64 条样本算
一次，`emit bcFidelitySample(...)` → 队列投递到 GUI 线程加点。代价 = 每 4 次更新一次
≤64 条前向（MLP 骨干约 10~30 ms），相对一步决策（0.3~8 s）可以忽略。

另外两处顺手接上的：**双击放大**（与损失/奖励同一个 `openLargeChart`，各自一个窗口）、
**CSV 导出**（"导出 CSV"里多一段"行为克隆保真度"，行号口径 = actor 更新次数，注释行写明）。
每场开始时曲线**换线**（与奖励曲线同一手法：`removeAllSeries` 而不是 `clearData`，否则每场多挂两条空线）；
不入 BC 的那一对选手图上**不建线**（两条空平线会被读成"保真度 0"）。

**两种模式的"一场"不一样，曲线也跟着不一样（2026-10 补齐）**：

| 模式 | 建线时机 | 清线/换线的含义 | 横轴单位 |
|---|---|---|---|
| Agent 对 Agent | `matchStarted` → `resetMetricsForMatch` | 每**场**（可以是多局） | 本场第几次 actor 更新 |
| **人机对弈** | `humanGameStarted`（玩家落下本局第一子） | 每**局** | 本局第几次 actor 更新 |

人机那条路原本**没有**建线（人机没有 `matchStarted`），而 `CurveChart::addPoint` 在序列不存在时
是**静默 `return`** ⇒ "BC 在训练、曲线一直空"（用户 2026-10 报的缺口）。修法（新的
`humanGameStarted` 信号 + 两种模式共用 `armBcChartSeries` + 面板里的 `chart-armed` 标记）
与三条断言见 §6.5 里那段。

⚠ 由此带来的**读数门槛**：保真度第一个点要 **≥8 次 actor 更新**（`kBcFidEvery=4` ×
`kBcFidMin=8`），而人机模式**每局清零** ⇒ **一局里 AI 没走满 8 手（被人速杀 / 你自己速杀）时，
这一局的曲线就是空的** —— 这是口径，不是缺陷。想看曲线就多下几手；想少等就选一档更弱的老师
（老师深度只影响标签难度，不影响门槛）。

### 6.6.1 双击放大（2026-10 用户报："双击行为曲线窗口后弹出窗口放大显示"）

用户报的时候界面上**双击是没反应的**，而且这是**静默**失败：编译过、启动无警告。原因是一句
条件的**执行顺序**：

```cpp
// setupMetricsPanel() —— 第 393 行调用
if (m_bcChart != nullptr) {                 // ← 此刻还是 nullptr
    connect(m_bcChart, &CurveChart::doubleClicked, ...);
}
// ...
setupChartTabs();                           // ← 第 400 行才 new 出 m_bcChart
```

`m_bcChart` 是在 `setupChartTabs()` 里才创建的，而接线写在**先跑**的 `setupMetricsPanel()` 里
⇒ `connect` 被那个空指针判断悄悄跳过。修法不是"把顺序调过来"，而是**接线搬到创建它的同一个
函数里**（`setupChartTabs()` 末尾）—— 这条比"记住两个函数的调用先后"可靠。同一处注释里写明
了这个坑，免得下次再有人在上游那一节顺手加一句 `connect`。

顺带修掉两个会让"放大窗口和源控件读起来不是一回事"的地方：

| 症状 | 原因 | 修法 |
|---|---|---|
| 放大窗口里的数字**没有 `%`** | `suffix` 是 `CurveChart` 自己的状态，数据同步（`follow`）不会带上它；原来那行 `setValueSuffix(source == ui->lossChart ? QString() : QString())` 两个分支**一模一样**，等于没设 | 放大窗口在每次同步时从源控件抄一份（新增 `CurveChart::valueSuffix()`） |
| 放大窗口里**没有 CE** | 放大窗口的读数行是**从曲线数据重新格式化**出来的，而 CE 不在曲线上（§6.6 的第二个决定） | `CurveChartDialog::follow(source, extraReadout)` 多接一个**回调**：每次同步都问一遍"还有没有不在曲线上的数"，于是窗口开着时 CE 跟着对局更新。CE 那段的格式抽成 `MainWindow::bcFidelityCeTail()`，图下标签与放大窗口**共用一份**（两处各写一遍迟早分叉，而"放大窗口少一个数"几乎看不出来） |

`tools/verify_bc_ui.ps1` 新增的断言（**用 `mouse_event` 真双击**——UIA 只有 Invoke、
没有双击模式；窗口按标题在桌面根节点的 Descendants 里找，因为 Qt 的 `QDialog(parent)`
在 Windows 上是"被拥有的顶层窗口"，不在 Children 里）：

```
PASS  double-click on the BC curve opens the enlarged window (行为克隆保真度 (放大))
info  enlarged readout = 读数 一致率 (策略头 top-1 == 老师那一手): 最新 62.5, 均值 62.5, 最小 62.5,
                        最大 62.5, 1 点  |  P(老师着法): 最新 44.878, …  | 最近 CE 1.0565 (窗口 8 条)
info  mirror vs source label = True  (strip the prefix, compare the rest)
PASS  the enlarged window mirrors the source readout (incl. the CE tail)
PASS  the enlarged window carries the CE (it is not a chart series)
PASS  the enlarged window closes again
```

> 这条断言刻意**不只**检查"窗口开了"：只判"存在"的话，"窗口开了但少一个数"照样通过。
> 它把放大窗口的读数与源标签**去掉各自的前缀后逐字比较**（`读数` vs `克隆保真度`），
> 于是"镜像"是一个可以证伪的判据。
> 回归：`verify_match_ui.ps1 -Full` 仍 PASS（损失曲线的放大窗口没被这次改动带坏 ——
> 它的 `suffix` 本来就是空，抄一份等于没变；读数镜像那条断言也照旧成立）。

`tools/verify_bc_ui.ps1` 里对应的断言（实测 PASS）：

```
PASS  the loss chart area is now a tab widget (chartTabs)
info  tabs found: 2 / tab: 训练损失 (loss) / tab: 行为克隆 (BC)
PASS  switched to the BC tab (tab page visibility gates UIA exposure)
PASS  the BC fidelity chart exists (bcChart)
PASS  the BC readout label exists (bcValueLabel)
PASS  the readout line carries the CE (not on the chart: different unit)
      (… 一致率: 最新 75, 均值 75 … | P(老师着法): 最新 53.468 … | 最近 CE 1.0685 (窗口 8 条))
```

> ⚠ **隐藏 tab 页里的控件在 UIA 树里不存在**：第一版断言直接去找 `bcChart`，报的是
> "NOT FOUND"，而功能是好的 —— 必须先切到那个 tab 再找。为了让脚本能选对 tab，两个
> tab 的文字里带了 ASCII 记号（`(loss)` / `(BC)`）。

**这一轮"BC 效果"能被量化到什么程度（诚实的边界）**：曲线与报告量的是**保真度**（像不像老师），
它能回答"克隆有没有在发生、有没有变好"；它**不能**回答"棋力涨没涨"——那只有
`bench_anchor`（固定开局集 + 换先手成对计分 + Elo 95% 区间）能回答，而且历史实测是
"代理指标涨 9 倍而胜率不动"（§7.10）。所以这一节补的是**过程指标**，不是终局指标。

**"这条曲线该读出什么"的规则（含被问到的两个问题）都在 §2.5.6**，这里只重复结论：

| 现象 | 含义 | 下一步 |
|---|---|---|
| CE 明显低于 `ln(平均合法着法数)` + A/P 同向上升 | 在克隆，且已经"果断" | 继续 / 加数据 |
| **A 在 P 上方**（一致率 > P(老师)） | 分布**尖**：同意时给老师很大概率、不同意时给很小 —— 训练后的**常态**（CLI 留出实测 A/P ≈ 1.5；训练前反过来是 P ≳ A） | 看 CE 是否一起降；是 ⇒ 健康 |
| A > P 但 CE ≈ `ln L` | 果断，但学的是**它自己**（塌成固定偏好） | 查窗口局面是否单一 / `onlineSteps=` 是否在拉扯 |
| P > A 或两者贴在一起 | 摊平（骑墙）：概率面像老师、峰值没对 | 常见于训练早期 / 老师更深 / 合法集更大 |
| `A − P` 只有几个百分点 | **噪声**（n=64 时 A 的 1σ ≈ 6pp，n=8 时 ≈ 18pp） | 看 `均值/最小/最大/k 点`，别读单点 |

## 7. 边界与已知缺口（明确列出）

* **上限就是老师**（AB 深度 D）。它是**课程起点**，不是终点：§7.10 的实测是
  "三成时候像强手 ≠ 像强手那样下棋"，而 §7.11 的受控对照进一步表明**换更强的老师
  不会提升克隆精度**（8000 局面下 d3 32.0% vs d4 28.4%，但迁移到深度 5 参照更好）。
* **prior top-1 / CE / P(老师) 都不是棋力**。这一条写在工具报告的最后一段里，
  免得读数被单独引用。
* **`bench_ppo_distill` 保持原样**（仍是全量口径的 bc 蒸馏 bench）—— 它的历史读数
  被 §7.7~§7.11 引用，改了会让那些数字不可复现。生产路径是 `train_bc`；
  对照臂（`--masked=0`）保留在同一条工具里。
* **只支持 AB 选点做老师**（命令行 `--depth`；界面 = 那个下拉框的 1/2/3/4 四档）。
  MCTS 访问分布（软目标）、人机棋谱库（`chess_games.db`）都还没接。
* **界面那条路的旋钮比命令行少**：界面上能选的只有**老师是哪一档**（下拉框）；其余口径
  都是源码里的常量（批最多 32 / lr 0.002 / 缓冲 512 / 每手一次更新 / 保真度每 4 次更新、
  最近 64 条窗口）—— 要调它们就去命令行（`train_bc` 参数全开），它不占界面。
* **界面不再有"单独跑一次 BC"的入口**（用户口径）：面上只有"选老师"那一个下拉框，
  所以"局面数 / epoch"这些规模旋钮在界面上**不存在**了 —— 要那一套就去命令行
  `train_bc`（参数全开，含 `--save` 与 `--masked=0` 对照臂）。界面这一条随之不再有
  "分钟级独占 agent + 模态沙漏 + 关窗取消"这些问题：它只持几毫秒的 agent 锁。
* **界面那条路的老师是"现场搜出来的"**，与对手无关（2026-10 口径）：每个学生的局面多跑
  一次 AB 搜索（深度 1 约 3 ms / 深度 4 约 90 ms）。设成深度 4 时这个开销会**叠加**在
  每手决策上（对 MCTS/PPO 的秒级决策仍可忽略，但对 AB-L3 这种毫秒级对局会明显变慢）。
* **人机那条路的读数是"一局一次"口径**：人机没有"场"的概念，所以 samples/updates 在
  **每局**第一次采样时归零（对局那条路是每场归零）。两个口径都写进报告，但不要拿人机的
  数字与"一场多局"的数字直接比。
* **TB 专家骨干的两支（`--agent=ppo` / `sac-moe`）只做了冒烟，没有正式读数**：
  它们走的是同一套胶水（同一个 `runBc` 模板被实例化），冒烟确认了两条路都**能跑通**
  （`--positions=16 --depth=1 --epochs=1 --max-positions=8`：PPO 的 8 条样本**全部**走合法列
  口径、1 次 actor 更新、`目标落空 0`、`critic 未被碰`；SAC-MoE-TB 同样跑通并把 CE 从
  3.61 降到 3.00），但**建网/内存的代价高一个量级**（PPO 的 actor+critic ≈ 2.4 GB，
  `--save` 一次约 1 GB），所以本轮的读数表全部来自 MLP 骨干。
  **§5 的读数是这两个骨干的"机制证据"，不是它们的性能结论。**
* **BC 不注入 MoE 辅助损失之外的均衡机制**：PPO 那一侧只对 **actor** 注入 batch 级的
  辅助损失（`moeAuxCoef`），**不碰** `moeLossFreeBias` 的控制回路；SAC 三支的 BC
  完全不碰它们自己的 MoE 均衡那一路（那一路归在线训练）。⇒ **BC 期间 MoE 路由
  可能偏斜**，本轮没量（`bench_gate_moe` / `bench_ppo_moe_balance` 是量它的工具）。
* **SAC 还原版两支（`SACAZLegacyAgent`）没有接 BC** —— 它们是"59e5233 行为还原版"，
  按本工程的惯例不许被新机制渗入。同理 `RL::SAC`（库里那个离散 SAC，无生产调用方）
  也没接。
* **SAC 共享口径下骨干会被 BC 改到**（Q 头不变）—— 这是共享表示的语义，不是缺陷；
  但因此"BC 预训练"与"加载已有 SAC 权重继续训"混用时，共享口径的 Q 值尺度会跟着变。
* **没有镜像数据增广**（PPO 在线路径有；SAC 默认 128 槽哈希下不可用）。

<a name="s9"></a>
## 9. 软目标（多深度一致性）：one-hot 之外的那条路（2026-10 用户问题 + A/B 实验）

> 用户原话：**"不直接使用 onehot 通过 abagent 计算概率分布再进行行为克隆是否会更好？"**
> 本轮的回答分三部分：**原理上怎么算（§9.1）**、**为什么是"多深度一致"而不是别种分布（§9.2）**、
> **实验上到底有没有更好（§9.3 的 A/B 表）**。结论先说：**两个指标方向相反，两个都必须报** ——
> 可比口径 **留出 KL（`CE − H(t)`）4/4 个种子都更低**（2.379 → 1.866），而硬口径
> **留出 top-1 略低**（38.59% → 36.78%，3/4 个种子、单种子符号不一致 ⇒ 只能说"没变好"）；
> **train−留出 差 4/4 都更小**（0.427 → 0.280），代价 +12~14%。
> 所以它作为**可选开关**落地（界面 + `train_bc --soft=1`），**默认关**。

<a name="s9.1"></a>
### 9.1 目标从"一只手"变成一个分布：公式上差在哪

one-hot 与软目标的差别只有**目标 `t` 的形状**，别的（状态编码、合法集掩码、只更新策略头、
批/缓冲/优化器）逐行相同：

| | 老师给什么 | `t` | `H(t)` | 损失 |
|---|---|---|---|---|
| one-hot（默认） | AB 最深那一层的根选点**一手** | `δ_{a*}` | 0 | `−log π(a*)`（掩码 NLL） |
| 软目标（`soft=1`） | 深度 1..D **各投一票**，票数/D | 一个分布 | `−Σ t log t > 0` | `−Σ_a t_a log π_a` |

关键在于**下界**。把掩码交叉熵拆开：

```
CE(t, π) = −Σ_a t_a log π_a = H(t) + KL(t ‖ π)          （H(t) = −Σ t log t）
```

于是同一份数据上：

* one-hot 时 `H(t) = 0` ⇒ `CE = KL(δ‖π) = −log π(a*)`，**CE → 0 是可达的**；
* 软目标时 `CE ≥ H(t) > 0`，**CE 不可能降到 0**（π = t 时恰好取到 H(t)）。

这直接决定了两条**读数纪律**（也是本轮在界面/报告里加 `targetH=` 的全部理由）：

1. **"CE 2.41（软）比 2.58（one-hot）小"这句话本身没有意义** —— 两者的下界不同
   （一次 A/B 里软目标的 H(t) ≈ 0.47）。要比就得比 `CE − H(t)`（= KL，即"像不像老师"），
   或者比 top-1（两者口径相同）。
2. **报告里必须印 H(t)**，否则读者无法区分"学生学得差"和"老师本身就模糊"。而且**两个 split
   都要印**（`train_bc` 现在印"训练 / 留出"两个，界面报告里印本场的 `targetH=`）——
   只在留出上印的话，"train−留出 差"这个读数就跨不了口径（§9.3 第 3 条差一点栽在这里）。

<a name="s9.2"></a>
### 9.2 为什么软目标是"多深度一致"，而不是根分值 softmax

最自然的想法是"把 AB 根层每个孩子的分值做 softmax 当分布"。**本工程不能用**，理由是
`ABAgent` 的根循环是**窗口写法**：

```
abagent.cpp getBestMove():  beta = r; alpha = r;   // r = 当前最优
```

第一个孩子之后，每个孩子的搜索都以"当前最优"为中心 ⇒ **非最优孩子返回的是界（bound），
不是精确分值**（失败低 / 失败高）。拿这些数做 softmax，等于在一个由**裁剪**产生的伪分布上
克隆 —— 看起来很有道理，实际是 artifact，而且**从读数上看不出来**（它会稳定、会收敛）。

要做根分值分布，必须**根层全窗口重搜每个孩子**（代价与噪声都另说）。本轮不走这条路，
改成只用"**各深度的最优着法**"这一个稳定量：

```
softTargetFromAB(board, color, D, depths=D):
    for d = 1..D:  mv_d = ABAgent(board, D).getBestMove(color, d)   # 深度覆写
    votes[mv] += 1/D;  同一着法被多层选中 -> 合并
```

语义清楚且可解释：**"每一层深度投一票"**，`票数/D` 就是权重。它天然表达"这一手稳不稳" ——
三层都选它（p=1）vs 只有最深那层选它（p=1/3、其余分给别的）。

三条必须写清的边界：

* **候选全是合法着法**：每次搜索返回的都是走法生成器的产物，所以 `t` 天然落在合法集里；
* **同一着法合并**（多深度一致里是常态）：不合并的话会得到 `targetIdx` 里的重复下标，
  而 `argmaxTarget()` / 评估口径都会读错；
* **深度 1 退化成 one-hot**（只有一票）⇒ `H(t) = 0`，与旧口径**逐位一致**。

<a name="s9.3"></a>
### 9.3 A/B 实验：它到底有没有更好

结论（**先说，因为两个指标方向相反**）：**可比口径（KL）软目标一致更好，而硬口径（top-1）略差**；
`train−留出` 差稳定压小；代价 +12~14%。所以它是**可选开关**，不是新默认。

**主指标先声明**（纪律：主指标必须在实验之前定，否则"哪个数好看说哪个"）。
一次**只加目标形状**的 A/B，可比的主指标有两个，都必须报：

* **留出 KL = 留出 CE − H(t)**：这是唯一"同尺"的目标函数读数（`CE = H(t) + KL`，见 §9.1）。
  ⚠ **不得**用留出 CE 的**绝对值**对比两臂 —— 它含有只属于软目标的 H(t) 项。
* **留出 top-1**：两臂同尺（"策略头的 argmax 是否 == 老师那一手"），且**它就是 BC 的硬目标本身**。

配置（两臂**逐字相同**，只有目标形状不同；同一台机器、逐个种子**相邻**跑，避免机器状态漂移）：

```
train_bc --agent=ppo-mlp --positions=4000 --depth=3 --epochs=8 --opening=8 --seed=S
         [--soft=1 --soft-depths=3]        # 只有这一处不同
```

| 种子 | 目标 | 留出 top-1 | 留出 CE | 留出 **H(t)** | 留出 **KL** | 训练 H(t) | 训练 KL | **train−留出 CE 差** | **KL 差** | 留出熵 | 标注 ms/局面 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 20240901 | one-hot | **35.71%** | 2.5768 | 0 | **2.5768** | 0 | 2.0058 | **0.571** | **0.571** | 2.0277 | 15.8 |

| 20240902 | one-hot | 38.62% | 2.2993 | 0 | **2.2993** | 0 | 1.8995 | **0.400** | **0.400** | 2.0134 | 15.7 |
| 20240902 | 软目标 | **39.62%** | 2.3286 | 0.4720 | **1.8566** | 0.4486 | 1.6184 | **0.262** | **0.238** | 2.0078 | 17.6 |
| 20240903 | one-hot | **39.62%** | 2.4840 | 0 | **2.4840** | 0 | 1.9902 | **0.494** | **0.494** | 1.8951 | 15.7 |
| 20240903 | 软目标 | 38.50% | 2.3358 | 0.4415 | **1.8943** | 0.4561 | 1.5414 | **0.338** | **0.353** | 1.9040 | 17.9 |

> ⚠ 两个 split 的 H(t) 必须**分开报**：`KL 差` 那一列是**直接量出来的**
> （`(留出 CE − 留出 H(t)) − (训练 CE − 训练 H(t))`，即 `train_bc` 报告里那行
> `KL 口径 … (train/留出 KL 差 = …)`），不是拿 CE 差改个名字。两侧 H(t) 只差
> 0.007~0.034（训练 0.4498 vs 留出 0.4621）⇒ CE 差与 KL 差同向，但**只有 KL 差能跨口径比**。
> 标注两列的机器都是空闲状态（第一批 1、2 号种子那两次是 `+14% / +12%`，
> 补跑三臂时是 `+12~14%` 且**稳定**：15.7~16.4 → 17.6~18.3 ms/局面）。

**逐条读法（每条都是"哪一半是真的"）：**

1. **留出 KL：4/4 个种子都更低**（2.5768→1.9364、2.2993→1.8566、2.4840→1.8943、2.1555→1.7780），
   均值 **2.379 → 1.866（−21%）** ⇒ **在"匹配老师的整个分布"这件事上，软目标稳定更好。**
   这一条是本轮**唯一方向一致**的正面结果，也是 §9.1 那条拆解的直接预言。
2. **留出 top-1：3/4 个种子略低**（均值 38.59% → 36.78%，**−1.8 pp**）。
   口径上这不奇怪：软目标的学生被要求把质量摊在老师的支撑集上（`P(老师着法)` 也从
   0.252 → 0.232），于是"只赌一手"的命中率略降、而分布更像老师。
   **但 −1.8 pp 是"接近噪声"的量级**（4 个种子的 per-seed 差是 −3.33 / +1.00 / −1.12 / −3.78，
   符号不一致）⇒ **不能说 top-1"变差"，只能说"没有变好"**。想看棋力只有 `bench_anchor` 能回答。
3. **train − 留出 差：4/4 个种子都更小**，CE 口径 0.427 → 0.280（−34%），
   **KL 口径 0.427 → 0.268（−37%）**。
   ⚠ 这条差一点成为**口径造成的假象**（直接比 CE 差会被只属于软目标的 H(t) 项污染），
   所以两个 split 的 H(t) 分开量了一遍：它们只差 0.007~0.034 ⇒ **两个口径同向、结论成立**。
4. **策略熵：不塌**（均值 1.964 → 2.077，4/4 都不低于对手）⇒ 软目标**没有**把策略变尖。
   对后续 RL 微调来说这通常是想要的方向（探索没被提前掐掉）。
5. **代价**：打标签 **+12~14%**（多搜 D−1 次；D=3 时那两次浅搜比深度 3 便宜得多，
   所以不是 3 倍）。训练/评估耗时不变（网络与口径都没动）。

**结论怎么落到产品上**：主指标（KL）一致更好、次指标（top-1）不变差到可判定、代价十几个百分点
⇒ 值得做成开关，但**不足以改默认**（BC 的公开目标一直是 top-1/CE 那一套，
把默认换掉等于悄悄换掉所有人读数的口径 —— 那正是本工程反复记过的那类"静默换尺"）。
所以：**默认关，界面上一勾就能开，开的时候报告里必须能看到 `targetH=`**。

| 位置 | 开关 | 读数 |
|---|---|---|
| 命令行 | `train_bc --soft=1 [--soft-depths=N] [--soft-linear=0\|1]` | 报告里"标签:"那行现在印**两个 split 的 H(t)**（`平均 H(t): 训练 … / 留出 …`），并新增一行 **`KL 口径 (CE − H(t) …): 训练 … -> …, 留出 … -> … (train/留出 KL 差 = …)`** —— 上面那张 A/B 表用的就是这一行（跨口径唯一可比的那一列） |
| 界面 | 老师下拉框**右边**的复选框 `bcSoftCheck`（"软目标 (多深度一致)"，**默认不勾**） | 面板实时行 `[BC] ... [teacher-depth=D soft=1]`；报告正文 `本场汇总 (match-summary): ... soft=1` 与 `软目标 (soft targets, 多深度一致): 软样本=k/n targetH=H` |
| 内核 | `RL::BCSample.targetIdx/targetProb` 本来就是**多项**（`Σt ≈ 1`），`maskedCeLogitGrad` 的 `dz = π − t` 与 `maskedCrossEntropy` 的 `−Σ t log π` 天然支持分布 ⇒ **内核零改动** | `BC::targetEntropyOf(s)`、`Metrics.targetEntropy`、`Metrics.softSamples` |

界面这一侧的**四个**决定：

1. **开关放在老师下拉框旁边，而不是另起一行**：它改的是"老师给什么"，不是另一个功能；
   把它单列会让用户以为要先选"which mode"。
2. **与下拉框同进同出**（同一个启用判据、同一句 tooltip 口径）：场上一旦没有学生、或对弈
   已开始，改它同样没有定义。⚠ 只在"启用"时同步状态，**不用 `setChecked` 回写当前值** ——
   那会把用户已经勾上的框清掉。
3. **勾了但老师仍是"关"时不去动下拉框**：用户的顺序可能是先勾再选老师，替他改选择会把
   "我只是勾了一下"变成"顺便开了克隆训练"。
4. **老师停在 L1 时，报告要自己解释"为什么 `targetH=0`"**（见 §9.5 末尾与
   `issues_review` 零之二点三十九）：那是**正确的退化**（只有一票），但用户看到的只是一个 0，
   分不清"开关没生效"与"退化了"。所以报告里明说原因与下一步
   （"想真的用软目标请把老师选成 L2 或更深"）。这也是"零值/空白必须自解释"这条纪律的又一次应用。

<a name="s9.5"></a>
### 9.5 钉住它的测试（`test_bc` 的 `[9]` 段，**105 条断言**）

| 断言 | 为什么必须是这条 |
|---|---|
| `softTargetFromAB` 的每项 > 0、`Σp == 1`（实测最大偏差 3e-08） | 它必须**真的是一个分布**；`Σt = 1` 是 `dz = π − t` 无偏的前提 |
| 每一项都是该局面的**合法**着法（用独立 `sample()` 出来的合法集逐项核对） | 不然就是"克隆一个走不了的着法"，梯度里多一份偏置 |
| 同一着法**被合并**成一项（下标两两不同） | 不合并会让 `argmaxTarget`/评估读错 |
| 深度 1 ⇒ 只有一项且 p=1（`H(t)=0`） | 深度 1 必须**退化成 one-hot**，即旧口径没被偷偷换掉 |
| 深度 3 在多数局面上给多于一项 | 否则"软目标"根本没生效（会静默退化成 one-hot） |
| 未归一权重被强制归一（票数 1/3/1 ⇒ 权重 0.4/0.6） | 调用方给的是票数，归一必须在库里做，只做一次 |
| **一个候选不合法 ⇒ 整条作废**（`TeacherIllegal`，不是丢掉那一项） | 丢掉之后 `Σt < 1`，`dz = π − t` 不再是"匹配一个分布"；这是 `rl/bc.h` 第 2 条 |
| 单老师重载 == 单候选多老师重载（`targetIdx/targetProb/legalIdx/posHash` 全等） | 单老师路径被**委托**给了多老师，这条钉住"旧路径逐位不变" |
| `targetEntropyOf(0.5,0.5) == ln 2`、one-hot == 0 | H(t) 的定义本身 |
| `CE == H(t) + KL(t‖π)`（手算对照，1e-6） | 文档 §9.1 那条拆解的**数值依据**；它不成立的话 `targetH=` 就是装饰 |
| `π == t` 时 `CE` 恰好等于 `H(t)` | "软目标的 CE 不可能降到 0"的证据 |
| 软目标 CE 严格大于"只看 argmax 那一项"的写法 | 盯住"评估口径换了一半"（退回 one-hot 写法会系统性压低软目标那一臂） |

界面那一侧由 `tools/verify_bc_ui.ps1` 钉住（新增断言）：开关**默认关**、与下拉框**同时**可用、
勾上后实时行出现 `soft=1`、报告正文出现 `targetH=` 且 **> 0**（= 目标真的是分布）。

⚠ 两个**实测才会知道**的细节（都写进脚本注释与 `issues_review` 零之二点三十九）：

* **老师必须选 depth ≥ 2**：`softTargetFromAB` 是"深度 1..D 各投一票"而 D = 老师档位，
  **D=1 只有一票 ⇒ 退化成 one-hot ⇒ `H(t)=0`**（这是 `test_bc [9]` 钉住的性质，不是缺陷）。
  所以脚本的默认老师是 `depth=2`，且期望档位从 `-TeacherItemMatch` **解析**出来（`$TeacherDepth`），
  不再手写常量。产品侧也补了一句自解释：报告里在"`targetH=0` 且档位 ≤ 1"时明说原因与下一步
  （"想真的用软目标请把老师选成 L2 或更深"）。
* **`H(t)` 在 depth=2 上只有 0.17 量级**（深搜与浅搜选同一手的比例很高，实测 `targetH=0.1733`）。
  它是**老师侧**的量：`H(t)` 越大 = 这个局面上老师自己越不确定，此时 CE 高**不代表**学生差 ——
  判学生只看 `CE − H(t)`（KL）。
