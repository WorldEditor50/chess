# DQN+MCTS (稀疏 MoE + TB 专家): 把 SAC 那条线上的优化搬过来

> **本轮交付** (分支 `dev-dqnmcts-moetb`, 基于 `main`): 新增**独立类**
> `DQNMCTSMOETbAgent`(`src/dqnmctsmoetbagent.{h,cpp}`, 界面类型 `AGENT_DQNMCTS_MOE`),
> 以及它的断言测试(`test/test_dqnmcts_moe_main.cpp`)、实测工具
> (`test/bench_dqnmcts_moe_main.cpp`)与界面接线。
> **旧类 `DQNMCTSAgent`(`AGENT_DQNMCTS`)与它的权重文件一位没动** —— 两支可以在界面上
> 直接对弈比较。
>
> 本文只写**做了什么、为什么、实测到什么**。所有"棋力"结论都带样本量; 没测的一律
> 写"没测"。

---

## 0. 一句话

旧类 `AGENT_DQNMCTS` 的骨干是 `RL::DQN` 里写死的**稠密** `MOE<16,16>` + `TransformerBlock`
(16 个专家**全算**), 状态是 90 维裸棋盘, 搜索用 UCB1 且 exploitation 项**符号是反的**。
本分支把 SAC 那条线上**已经被实测过**的十几项优化搬到一个新类里, 并给出每一项在这条
路径上的实测数字。

## 1. 搬过来的优化 (逐条 + 实测出处)

| # | 优化 | 旧类 (改前) | 新类 | 本机实测 |
|---|---|---|---|---|
| 1 | **稀疏路由 MoE** | 稠密 `MOE<16,16>` (16 个专家全算) | `SparseMoE<TB专家, E=4, top-1>` | **3.99x** (等参数: 1445 ms vs 364 ms / 120 模拟, `bench_dqnmcts_moe --mode=agree --dense=1`) |
| 2 | **TB 专家头数口径** | 老规则"头数整除 d_model" | `TransformerBlock<15,315,HonorHeads=true>` | 请求 15 / **实用 15**, d_k=84, 注意力元素 105,840。老规则在 1263=3×421 上会静默降成 **3 个头** (SAC 实测慢 3.07x) |
| 3 | **表示: 规范视角 + 规则上下文** | 90 维裸棋盘 (无走子方/无上下文; 且子力值按 `Stone::Type` **序数**取 —— 车 1/7 < 兵 4/7) | 14 子力平面 + 3 上下文标量 = **1263** | test[2]: 32 个非零格; 红黑视角编码逐元素相同; 镜像+换色后黑方视角 == 原红方视角 (差 0) |
| 4 | **共享骨干 (骨干一次 + 头)** | 一张网缝在一起, 叶子估值要算满 128 列 | `trunk` / `qHead` / `qNet` 三个视图共享同一批层 | 一次叶子估值 = 骨干 1 次 (3.05 ms) |
| 5 | **稀疏列叶子估值 (R1)** | 无 | `Net::forwardTrunk` + `iLayer::sparseLogits` | test[3]: 与全量同列 **5.96e-08**; 128 列的头太小, 只省 **2%** (动作空间到 8100 列时这条才值钱 —— 如实写在这里) |
| 6 | **PUCT + 先验, 符号按 negamax** | UCB1, `+child.totalReward/visitCount` (**符号反的**) | `-child.getQ() + c_puct·P·√N/(1+n)`, 先验 = 合法槽位上 Q 的 softmax | test[4]: PUCT(对手好) = −0.848 < PUCT(对手差) = +1.152 < 未访问 = DBL_MAX |
| 7 | **叶子终局单出口** | `chess.isGameOver()` (只认"将/帅还在不在", 将杀/判和都不算终局) | `terminalReward()`, 与训练目标**同一个函数** | test[8]/[10] 走同一条 |
| 8 | **Double DQN** | vanilla (argmax 与取值都来自目标网) | 在线网选 a\*, 目标网估 Q(s',a\*) | test[5] |
| 9 | **目标钳位 + Huber** | `RL::DQN` 既不夹目标也不用 Huber | `clampTarget=2 / huberDelta=1` | test[5]: `|y| ≤ clampTarget` |
| 10 | **梯度累积 + 每批只调一次优化器** (P3) | `RL::DQN` 每条样本一次 `RMSProp` | 批内累积, 优化器在批末调一次 | test[5]: 多 epoch 仍只 +1 步 |
| 11 | **多 epoch 回放** (P4) | 无 | `replayEpochs` (每遍**重抽**) | test[5]: epochs=3 ⇒ 24 条样本, 仍只 1 次更新 |
| 12 | **目标网同步率可调** (F1) | `tau=0.01` 每 256 次 learn (≈ 每 1024 手, 目标网基本是死的) | `targetTau=1.0` (硬拷贝) 每 `replaceTargetIter=64` | 见 §4 的"刻意没改的默认值"那条 |
| 13 | **MoE 辅助损失的批边界** | 无 (旧类连 MoE 接口都没有) | `resetMoeBatchStats()` 在批首, `addAuxGradient(0.1)` 在优化器前**各一次** | test[7] 的 MoE 路由直方图 |
| 14 | **稀疏回放表示** | 90 维稠密 + 无上下文 | 只存被占据的格子 + 上下文标量 + 合法位图 | — |
| 15 | **外部终局通道** | 无 | `notifyGameResult` 回填**最新那条真实决策样本** (幂等) | test[8]: 池尾往回第 3 条 (池尾是推演样本), 计数 +1, 重复通知不重复计 |
| 16 | **从自己的搜索学一次** | 无 (关掉"探索+预训练"就完全不学) | `learnFromSearch` (默认开) | test[9]: 关掉之后 `selectMove` 不产生任何更新 |
| 17 | **只读诊断 (自检面板)** | 只有别名与终局通道 | + 骨干指纹 / 注意力头 / `|y|` / 夹住比例 / Q spread / `|Q_target|` / MoE 路由 / 层激活实测名 | test[7]: 只读、可重复、含"不是棋力" |

**没有搬过来的** (连同理由, 免得下次再想):

* **8100 双射动作空间**: SAC 在同一数据量下实测净亏约 200 Elo (200 局 71.8% vs 54.8%,
  区间不重叠), 机制是 Q 头从 128 列涨到 8100 列 = **63 倍参数量**而瓶颈宽度不变。
  本类沿用 128 槽哈希, 别名问题由自检面板如实报告。
* **最大熵 / 温度 α / 熵项进目标 / 熵中心化**: 那是 SAC 的 actor 那一半, DQN 没有策略头。
* **tanh 输出 / tanh 奖励 / α Gumbel 噪声**: SAC 那边三条都实测更差, 直接不搬。
* **奖励塑形 (rewardShape 2/3)**: SAC 在新实现上不显著 (p=0.45~0.56), 且 mate 那一半在
  自对弈里是死旋钮 (decisive done 样本 0~0.14%)。
* **双 critic 的 `min(Q1,Q2)`**: **实现了但默认关闭** (`twinCritic`)。理由见 §4。

## 2. 关键实测 (本机, Release/MSVC, `build-sacmoetb`)

### 2.1 单点耗时 (`test_dqnmcts_moe` 的 [11] 节)

```
骨干 28,772,468 + 头 8,320 = 28,780,788 参数 | 建网 758~788 ms
全量前向            2.87~3.05 ms
稀疏叶子(合法列)     2.83~3.00 ms   (省 1~2% —— 128 列的头太小)
一次决策(40 模拟)   124.9~134.8 ms
一个训练样本         36.1~43.4 ms   (3 次骨干前向 + 1 次骨干反向)
```

(区间来自多次运行: 同机上有别的负载时数值会一起抬高 —— 所以只按数量级用, 不当基准。)

**由这两个数定下来的默认值**:

* 界面模拟次数 `DQNMCTS_MOE_SIMS = 120` (**不是**旧类的 200, 也不是 SACAZ_MOE 的 40)。
  实测 120 次 = **364 ms/步**; 而 **40 次时搜索退化了**: 开局 ~40 个合法着法 ⇒ 每个
  孩子恰好被访问 1 次、严格打平, 根选择退化成"按先验顺序取第一个孩子" = 1 层 Q 贪心。
  证据: `--sims=40 --sims2=120 --positions=16` 的着法一致率 **0/16 = 0%** —— 预算
  是这条路径上**真的会改行为**的旋钮 (而 twin/sparse/dbl/clamp 这一组翻转之后一致率
  100%, 见 §4)。
* `learnEveryMoves = 8` (**不是**旧类的 4): 32 条的一个批 = 1.39 s, 摊到 8 手上 =
  每手 174 ms ≈ 一次搜索。旧类的 4 是在 d_model=90 的稠密 MoE 上定的, 照搬会让每手
  多背 350 ms。

### 2.2 稀疏路由值多少 (`bench_dqnmcts_moe --mode=agree --dense=0/1`, 120 模拟)

```
稀疏 (E=4, top-1):  364.4 ms/步
稠密 (E=4, top-4):  1445.3 ms/步      ⇒ 3.99x
```

两者**参数量完全相同**, 差别只在"算 1 个专家还是 4 个"。这条复现了 SAC 那条线上的
`bench_moe` 结论 (3.8x)。

### 2.3 旋钮敏感性 (着法一致率, 24 个固定局面, 120 模拟)

| 臂 A | 臂 B | 一致率 | 判读 |
|---|---|---|---|
| `sims=40` | `sims=120` | **0/16 = 0%** | 搜索预算真的改行为 |
| `sparse=1` | `sparse=0` | 16/16 = 100% | 稀疏列与全量**等价** (与 test[3] 的 5.96e-08 互证) |
| `twin=0 + sparse=1 + dbl=1 + clamp=2` | 四项全部翻转 | 16/16 = 100% | 这一组旋钮在**随机权重**下不改变选点 |

⚠ 最后一行**不等于**"这些旋钮没用": 它只说明"在随机权重 + 120 模拟下, 选点对它们
不敏感"。`clamp/dbl` 本来就只作用于**训练**侧 (评估期不训练, 所以一致是应该的);
`twin` 会改叶子值, 但两个随机初始化的 Q 头排序高度相关, 所以 argmax 没变。
**能证明它们值的只有"训练之后的对局"**, 本文不做这个声明。

⚠ 一个测量方法上的坑 (踩到了): 这个 bench 第一版**没有在建 agent 之前钉种子**, 而
`RL::Random` 的默认种子是**按线程身份派生**的 ⇒ 两次运行的初始权重不同, 同一条命令
给出过 0% 与 100% 两个相反结果。修法: `RL::Random::setSeed()` 放在**构造 agent 之前**。

### 2.4 对局比分 (随机权重, 对手 MCTS 400, `--train=0` 纯评估)

| 臂 | 局数 | 手上限 | 胜/负/和 | 得分率(和棋半分) | 每步 |
|---|---|---|---|---|---|
| 40 模拟 | 8 | 60 | 0 / 1 / 7 | 43.8% | 118 ms |
| 120 模拟 | 8 | 120 | 1 / 0 / 7 | 62.5% | 339 ms |
| 120 模拟 | 6 | 100 | 2 / 0 / 4 | 66.7% (胜率 95% Wilson [9.7%, 70.0%]) | 330 ms |

**这三行不是棋力结论**, 理由写在这里免得被误读:

1. **n=6~8, 单样本**: 本工程实测过的 20 局噪声是 ±10~25 个点 —— 上面的区间大面积重叠;
2. **三种设置的手数上限不同** (60/120/100), 所以它们之间也不严格可比;
3. **随机权重**: 这是"没训练过的网络 + 搜索"的读数, 不是"学过之后"的读数;
4. **和棋占绝大多数**: 上限一到就判和, 所以"得分率"主要在量"会不会被将死", 不是棋力。

要回答"120 比 40 强不强"至少需要: 同一套开局、200 局 × 多种子、配对比较
(本工程口径: 配对的 SE 从 7.8% 降到 4.0%)。**本分支没有做**, 所以文档里没有任何
"更强"的声明 —— 只有"预算会改变行为"(§2.3 的 0% 一致率) 这一条确定性事实。

## 3. 断言测试: 80 条, 0 失败

```
build-sacmoetb/test_dqnmcts_moe.exe   ->  断言 80 条, 失败 0 条
```

覆盖: 骨干指纹(含头数口径) / 表示(规范视角、上下文、镜像+换色) / 稀疏==全量 /
PUCT 负号 / 学习口径(P3、P4、夹目标、未走到的列梯度为 0) / 权重往返(三文件) /
自检只读可重复 / 外部终局通道(幂等、不挂推演样本) / learnFromSearch 关闭无更新 /
搜索输出合法 / 耗时读数。

其中两条是**回归指示器**, 专门钉住本工程出过事的地方:

* `tbHeadsUsed() == 15` —— 老规则会静默降成 3 个头, 而参数指纹/paramCount/权重格式
  一个都不变 (SAC 那条线上实测 3.07x 慢);
* `hiddenActivationName()` 报的是**真实层类型** —— 那一层曾被换成 `TanhNorm<Sigmoid>`
  而掉 26 个点, 当时面板上一个字都看不出来。

## 4. 默认值: 哪些是"实测定的", 哪些是"刻意保留的"

| 成员 | 默认 | 依据 |
|---|---|---|
| `denseMoe` | false (构造参数) | 3.99x; 且**必须是构造参数** —— 建网在构造函数里, 构造后再赋值是静默空操作 |
| `simulations` | 120 (界面常数) | 40 时搜索退化 (一致率 0% 那条证据) |
| `learnEveryMoves` | 8 | 43.4 ms/样本 ⇒ 32 条 = 1.39 s, 摊 8 手 = 174 ms/手 |
| `doubleDQN` | true | 不增加任何参数就处理 max 偏置 |
| `clampTarget` / `huberDelta` | 2.0 / 1.0 | 与 SAC 同值; 挡住 SAC 实测过的发散 (|Q| 0.063 → 4.15 → 13.4) |
| `targetTau` / `replaceTargetIter` | **1.0 (硬拷贝) / 64** | SAC 的 F1: 机制确定 (目标网必须动起来), 但**棋力不显著**; SAC 因此**没改默认**, 本类是**新类**(没有历史读数要保护) 所以默认取修好的那一档, 并留成成员供 A/B |
| `twinCritic` | **false** | 见下 |
| `learnFromSearch` | true | 外部终局通道与"关掉探索也仍在学"都靠它; 对弈模式由界面的 `finishDecisionSearch` 逐手关掉 |
| `auxLossCoef` | 0.1 | SAC 实测选出来的 (0 会让专家坍缩: 8 个里 3 个从不被选中; ≥0.5 开始盖过真正的梯度) |
| `replayEpochs` | 1 | 与旧类每批的更新量一致; 自对弈路径想开就设 2 |
| `priorTemp` | 1.0 | Q 值域 ±2 ⇒ 先验偏平 (SAC 的记录: Q spread ~0.2 相对 PUCT 探索项 0.3~1.0 是弱的) |

**`twinCritic` 默认关闭的理由** (写清楚, 免得被读成"忘了做"): 它在 SAC 那边是与最大熵
策略**耦合着**测的, 本工程从未单独量过它的棋力; 而它要解决的 max 偏置已经由 Double DQN
直接处理 (且不增加参数)。实测 (§2.3) 也显示: 随机权重下翻转它对选点**没有影响**。
所以它是一条**A/B 臂**(`bench_dqnmcts_moe --twin=1`), 不是默认口径。

## 5. 接线 (界面)

`AGENT_DQNMCTS_MOE`, 显示名 **`DQN+MCTS (稀疏MoE+TB专家)`**。改动点与 `AGENT_DQNAB`
同形 (它也是"独立类 + 多文件权重 + 自己的预算常数"): `chessboard.h`(枚举末位追加 +
常驻指针)、`chessboard.cpp`(24 处: 显示名/可探索/奖励口径/临时权重前缀/启动预载/
构造/存载/自检/两条决策路径/后台训练五处/退出保存)、`mainwindow.cpp`(下拉框 + 可训练 +
全部自检)、`CMakeLists.txt`(CHESS_CORE + test + bench 目标)。

四条**必须**记住的约定:

1. **枚举只能追加在末尾** —— 这些值经 GUI 下拉框的 `userData` 传出去, 插在中间会静默
   改变既有 agent 的编号;
2. **权重前缀独立**: `weights/dqnmcts_moe_agent{_trunk,_q,_q2}`, 临时前缀
   `weights/_temp_train_dqnmcts_moe`。三个文件**无条件**写 (文件个数不许依赖
   `twinCritic` 这种运行时开关, 否则载入方要猜"这一次有没有 `_q2`");
3. **两条决策路径都要改** (`aiThinkRaw` 与 `decideOnEnvRawLocked`), 而且都走
   `finishDecisionSearch` —— 那条模板负责"对弈模式把 learnFromSearch 关掉"与
   "这一手真的学了就上报损失";
4. `notifyHumanGameEnd` 的名单里加上了本类型 —— 它保留**真实决策样本**, 人机对弈里
   "人把 AI 将死"那一手必须能回填 −1 (否则 AI 输掉的那一局拿不到终局值)。

## 6. 本轮实测记录 (含负结果)

* **稀疏 vs 稠密**: 3.99x (见 §2.2) —— **确定性、可复现**。
* **40 vs 120 模拟**: 着法一致率 0% (见 §2.3) —— 确定性、可复现。
* **twin / sparse / dbl / clamp 四项翻转**: 一致率 100% (随机权重, 评估期) —— 见 §4 的
  判读, **不构成"这些旋钮没用"的结论**。
* **对局比分** (见 §2.4): 三行单样本读数, **不构成任何棋力结论**。给出它们是为了留下
  复现命令与量级 —— 40 模拟那一臂 8 局里输 1 和 7, 120 模拟两臂 14 局 3 胜 0 负 11 和。
  这**不足以**说"多搜索更好": 手数上限、样本量、随机权重三个因素都在里面搅着。

## 8. 还没做 / 已知的开放项

1. **棋力**: 本分支**没有**任何"更强"的声明。要下结论需要 200 局 × 多种子 + 配对,
   并且要有训练过的权重 —— 那是一次独立的工作量。
2. **训练的稳定性**: 目标钳位/Huber/双 critic 这些只在 SAC 上量过。本类需要一次
   "训练 200 局之后 |Q|/Q spread/夹住比例"的过程读数 (自检面板已经把这些量都印出来了)。
3. **`priorTemp` 与 `c_puct` 从未扫过**: 先验目前只是"合法槽位上 Q 的 softmax",
   在 ±2 的值域上很平 (SAC 的记录: Q spread ~0.2 vs 探索项 0.3~1.0)。
4. **树复用**: 每个 `selectMove` 都重建整棵树 (与旧类同)。传递子树是最自然的下一步,
   但会让"预算"的口径从"每次模拟数"变成"全局限额", 需要先定清楚。
5. **动作空间**: 128 槽哈希的别名是结构性上限 (开局 44 → 39 槽)。SAC 那条线上 8100
   双射在**当前数据量**下净亏; 数据量上来之后应当重新评估 —— 那时本类的稀疏列路径
   (实测只省 2% 是因为头太窄) 会开始真的值钱。
