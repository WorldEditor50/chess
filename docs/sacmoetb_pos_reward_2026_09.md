# 按局面动态分配"吃子 / 杀将"两个奖励权重（`rewardShape = 3`）

用户口径（2026-09，两轮原话）：

> ① 前期应该加强吃棋子的奖励权重，后期应该重杀将奖励，或者说这者都不应忽视奖励。
>
> ② 分阶段太过思维定势，因为局势是反复变化的，是否可以参考棋子的数量和价值来评估局面
> 动态调整杀棋杀将的奖励比例。

② 是对 ① 的修正，而且**修得对** —— 这一份就是照 ② 做的：
把 ① 里的"阶段钟"换成**局面评估** e，由**棋子的数量、价值、双方优势**三个因子算出，
再用它动态决定"吃子奖励"与"杀将奖励"的比例。

设计与全部理由写在 `src/sacazagent.h` 的 `rewardShape = 3` 一节，实现写在
`src/sacazagent.cpp`，回归钉在 `test_sacaz` 的 **[15b]** 节（39 条断言）。

---

## 1. 起点：现在的奖励长什么样

| 项 | 值 | 出处 |
|---|---|---|
| 吃一个马/炮 | `0.1 x 0.3 = 0.029`（另加每步代价 −0.001） | `stone.h` 的 `stepReward` |
| 一方全部非将子力 | `3.5 x 0.1 = 0.35` | `REWARD_MATERIAL_COEF` |
| 终局 | `±1`（和棋 0） | `REWARD_TERMINAL` |
| 熵偏置 `α·H` | `≈ 1.9`（实测） | [`dev_sacmoetb_strength_2026_09.md`](dev_sacmoetb_strength_2026_09.md) §3.1 |

两句话概括：**吃一整个子只有终局的 3%**；而实测里未训练的 TB agent 对 AB L1
**32/32 局净输子**（平均 −2.48），同时又 **70~95% 是和棋** —— 也就是
"**送子**"与"**赢了子也转换不成杀**"同时存在。用户这条提议正好打在这两个症状上：
该吃的时候要有吃子的激励，该杀的时候要有杀将的激励。

## 2. 为什么第一版（阶段钟）被否掉

第一版把 ① 做成了**一个单向的阶段坐标**：

```
φ = 1 − 双方剩余子力 / 7.0        开局 0 -> 光将 1 (单调不减)
e = 1 + matBoost x (1 − φ)        吃子权重
终局权重 = 1 + termBoost x φ
```

它对**棋盘状态**是对的（子越少越像残局），但它是**单调**的：一局棋从满盘走到光将，
φ 只往一个方向走。而"局势"不是单调的 —— 落后一方吃掉一个车，局势当场翻面；
双方互兑之后子力骤减，局面立刻进入残局。**一个单调坐标表示不了会反复的局势**，
而且它只看"还剩多少"，完全不看"谁占优"。

## 3. 现在的设计：局面评估 e → 两个权重

### 3.1 三个因子（都归一到 [0,1]，都随"越接近残局/越定局"增大）

```
f_值 = 1 − 双方剩余非将子力价值 / 7.0                   (稀疏度: 价值)
f_数 = 1 − 双方剩余非将棋子个数   / 30                  (稀疏度: 数量)
f_势 = |红方剩余子力 − 黑方剩余子力| / (红方 + 黑方)      (定局度: 相对子力差)
```

* **将不参与**材质与计数：它的价值就是"被吃"= 终局本身（与 `stepReward` 同口径）。
* **数量是独立的一维**：同样 1.0 的价值，"两个车"与"十个兵"对**杀棋**的难度天差地别 ——
  子少则棋盘开阔、将好露头，杀棋近。只看价值会把这两者算成同一个局面。
* **优势用相对差**（`|红−黑|/(红+黑)`）：绝对差在残局里会被"总量本来就小"放大
  （只剩两个兵 vs 一个兵也得出一个"看起来很大"的差）；相对差尺度无关 ——
  0 = 完全均势，1 = 一边被吃光。**局势反复就体现在这一维**。

```
e = clip( (f_值 + f_数 + f_势) / 3, 0, 1 )         <- 默认 (mateScoreMode = 0)
```

> **e 的上限不是 1，而是 ≈ 0.984。** 因为 `f_势 = 1` 要求对手一个子都没有，
> 而那会把 `f_值 / f_数` 推到"接近 1 但到不了 1"（自己手里总还剩一点子）。
> 极值出现在"一方只剩一个兵、另一方光将"：`(0.9857 + 0.9667 + 1)/3 = 0.9841`，
> 于是默认 boost=0.5 下终局倍率的实际上限是 **1.492**（不是 1.5）。
> 这是设计里的一处**便宜的保守**：越接近"必胜"越接近上限，但永远不会恰好顶到。

`mateScoreMode` 1/2/3/4 分别只用价值 / 只用数量 / 数量+价值 / 只看优势，
既是消融臂，也是"哪一维在起作用"的探针。

### 3.2 两个权重与"比例"

```
材质倍数 m_mat(e)  = 1 + matRewardBoost  x (1 − e)     ∈ [1, 1+matBoost]
终局倍数 m_mate(e) = 1 + mateRewardBoost x e            ∈ [1, 1+mateBoost]
```

默认 `matBoost = mateBoost = 0.5` 时 **`m_mat + m_mate ≡ 2.5`** ——
这才配得上用户说的"比例"：**一个固定的奖励预算，按局面在"吃子"与"杀将"之间动态分配**。

| 局面 | e | 吃子倍数 | 杀将倍数 |
|---|---|---|---|
| 满盘均势开局 | 0.000 | **1.50** | 1.00 |
| 5 兵 vs 5 兵（价值 1.0，10 子） | 0.508 | 1.25 | 1.25 |
| 1 车 vs 1 车（价值 1.0，2 子） | 0.597 | 1.20 | 1.30 |
| 均势残局：马+2兵 vs 马+2兵 | 0.552 | 1.22 | 1.28 |
| 一边倒：马+3兵 vs 马+1兵 | 0.619 | 1.19 | 1.31 |
| ← 落后方吃回一个兵 | 0.605 | 1.20 | 1.30 |
| 红车马 vs 黑车（胜势） | 0.648 | 1.18 | 1.32 |
| 红车马 vs 光将（必胜残局） | 0.940 | 1.03 | 1.47 |
| 双方光将 | 0.667 | 1.17 | 1.33 |

**两条永不归零**：材质倍数最小是 1（基准 0.1 仍在），终局倍数最小是 1（±1 真值仍在）——
这就是"两者都不应忽视"的代码含义（对照：`rewardShape = 1` 是**去掉**材质，
把终局当唯一信号，正好是被否掉的那一头）。

### 3.3 走哪几条出口

| 量 | 出口 | 说明 |
|---|---|---|
| 即时（吃子）奖励 | `SACAZAgent::computeReward` | 只放大**材质项**；每步代价 −0.001 不参与放大 |
| 终局值 | `SACAZAgent::terminalReward` | **唯一出口**：搜索叶子 / 自对弈 / rollout 三处全走它 |
| 吃将 | 仍**不给**即时奖励 | 它必然是终局，由 `terminalReward` 给（与 `rewardShape = 0` 同口径） |

**按"走子前"的局面算 e**：本步正要吃的那个子算回"还在"，于是 `moveForward` 之前
与之后调 `computeReward` 得到同一个 e（工程里两个调用点都真实存在：
`agentrollout.hpp` 在走子前，自对弈路径在走子后）。

## 4. 事先算好的三条约束（都可断言）

1. **量纲不变量仍在**：材质被抬到 `(1+matBoost)` 倍后，"吃光对方全部子力"仍必须
   **小于**赢一盘棋 ⇒ `0.35 x (1+matBoost) < 1.0` ⇒ **matBoost < 1.857**。
   默认 0.5 → `0.525 < 1.000`，在线内。
2. **只放大，不改符号与排序**：两个倍数恒 ≥ 1，终局倍率对**双方同一个数**
   ⇒ 零和对称保持（`+m / −m`）；和棋恒 0 ⇒ "赢 > 和 > 输"一位不变。
3. **一个 e 贯穿即时与终局** ⇒ "搜索估的"与"训练学的"仍是同一个游戏。

## 5. 已知的代价（写在明处）

* **终局加权与 `γ = 0.99` 的折现方向相反**。把 `mateRewardBoost` 开到 b 之后，
  "晚 Δ 手再杀"的折现价值 `0.99^Δ x (1+b)` 在 `Δ < 100·ln(1+b)` 手之内**超过立刻杀**：
  b=0.5 是 **40 手**，b=1.0 是 **69 手**。也就是说这个旋钮在**奖励"磨到残局再动手"**，
  而 e 里"越磨越大"的那两维会把它喂大。默认取 0.5 而不是更大值就是为了压住这条通道；
  实测把 b = 0.5 / 1.0 两档都测，见 §7。
  > **但这在当前的训练协议里是潜伏风险而不是现实风险**：自对弈训练根本走不到终局，
  > `mateBoost` 一个样本都影响不到（实测见 §10）。只有先把对局打到真终局（§10.3 的 ①），
  > 这条算术才会变成真约束。
* **奖励结构随局面变化** = 价值函数要拟合的靶子本身在动。这是 §6 那条实测结论
  （"奖励尺度不是 critic 的约束，`α·H` 才是"）的加强版，不是新问题。
* **与前一支 `rewardShape = 2` 方向相反**：2 奖励"对方满子就被将死"（快杀 > 磨死），
  3 奖励"进入残局/定局之后的将死"。两者**故意不叠加**：一个旋钮只回答一个问题。

### 事先的预期（用于事后对账）

按 §6.1 已量出来的机制，`y = r − γ·V(s')` 的主项是 `−γ·V(s')` 而不是 `r`，
所以**只把材质放大**大概率仍然没有效果（§6 已测过 5x / 20x 无效）。
两处真正可能改变行为的地方：① 后半句把 `r` 里唯一与胜负同量级的项按局面放大；
② 这个权重是**动态**的，它给 critic 提供了"同一个子在不同局面下价值不同"的结构 ——
后者既可能是信号，也可能是噪声，这一轮实测要回答的就是这件事。

## 9. 实测：四条臂（各 60 局自对弈 + 16 局/锚点）

共同口径：`--train-games=60 --train-sims=16 --openings=8 --opening=4 --eval-plies=80
--eval-sims=40 --opponent=both --target-tau=1 --target-iter=256 --seed=20240901
--mcts-srand=12345`，日志与 CSV 在 `.r1build/posrwd/`（每条臂 58 分钟，四条并行）。

| 臂 | 配置 | vs AB L1 得分率 | vs AB 材料差 | vs MCTS 得分率 | vs MCTS 材料差 | Q 间距 | 被夹 |
|---|---|---|---|---|---|---|---|
| **R0** | `reward-shape=0`（参照） | 37.5% [26.5, 48.5] | **−2.51**（占优 0 / 落后 16） | 50.0% [50.0, 50.0] | **+0.19**（12 / 4） | 0.1125 | 52.4% |
| **P1** | shape=3, mat 0.5 / mate 0.5 | 34.4% [22.6, 46.1] | **−2.26**（0 / 16） | 53.1% [47.0, 59.2] | **+0.51**（10 / 6） | 0.1076 | 50.8% |

**读法（按 §5.1 的优先级）：**

1. **得分率：没有结论。** AB 上 37.5% → 34.4%（多输一局），MCTS 上 50.0% → 53.1%
   （多赢一局），两个方向的移动都在 16 局这把尺子的噪声里。
2. **材料差：两个锚点都往好的方向动了，但很小。** AB：−2.51 → −2.26（16 局全部落后，
   没变）；MCTS：+0.19 → +0.51。这是"净输子 → 少输子"的量级，不是上一册那种
   "净输子 → 净赢子"的翻转。
3. **训练侧：critic 没被动态权重弄坏也没被治好**（Q 间距 0.1125 → 0.1076，−4%；
   被夹 52.4% → 50.8%）。
4. **`mateBoost` 三档（0 / 0.5 / 1.0）的结果完全一样** —— 连"材料差 +0.51"和每一局的手数
   都一样。这不是"没测出差别"，这是**这个旋钮根本没起作用**。原因见 §10。

## 10. 【本轮最有用的发现】训练里"终局通道"极稀疏（曾实测为 0 —— **注意 §10.4 的更正**）

第 9 节的第 4 条必须查到底：为什么把终局倍率从 0 开到 1（甚至 10）会一位不变？

### 10.1 两条硬证据

**(a) 权重逐字节对比**（同一命令、只改一个旋钮，训练完存盘比 SHA256）：

```
mateBoost 0  vs  mateBoost 10      ->  trunk / actorhead 哈希**逐字节相同**
matBoost  0  vs  matBoost  0.5     ->  trunk / actorhead 哈希**不同**   （阳性对照）
```

也就是说：**吃子那一半进了学习，杀将那一半没进** —— 而且不是"影响小"，是**零**。
（阳性对照保证了这个对比有分辨力。）

**(b) 直接数样本**（给 `TrainDiag` 加了 `doneSamples` / `decisiveSamples`
两个计数器，工具在"训练诊断"下面打一行"终局通道"）：

```
--train-games=12 --train-plies=120   样本=11296
  终局通道: done 样本=0 (0.0000%) 其中分胜负=0 (0.0000%)
--train-games=4  --train-plies=120   样本=3616     同上: 0 / 0
```

**自对弈训练里一条终局样本都没有。** 原因是 `trainSelfPlay` 的退出条件是
`moves < maxMoves`（120 手）—— 一局棋**走到手数上限就被截断**，而截断的那一步
`done` 仍是 false，所以 `terminalReward()` 从来没有被学习目标调用过。

### 10.2 这条发现解释了三件事

1. **为什么 `mateBoost` / `rewardShape=2` 都是死代码。** 它们只作用在 `terminalReward()`
   上，而那个函数在训练里**一次都没被调用**。"和棋恒 0"又让"没分胜负的终局"也不带信号 ⇒
   只有 done 且分胜负的样本才携带杀将奖励，而这类样本是 **0 条**。
2. **为什么 §5 那条"延迟激励"的风险是**潜伏**的而不是现实的**：奖励函数确实奖励
   "磨到残局再杀"，但训练里根本走不到杀那一步，所以它现在害不到人 —— 而**一旦按下面的
   ① 把对局打到真终局，这条风险就会立刻生效**，那时 §5 的算术（b=0.5 → 40 手窗口）
   就必须当成真约束来对待。
3. **补上一册 §7.3 那条结论的机制。** 那一册说"`α·H` 是唯一让 critic 不塌成 0 的脚手架"、
   "60 局自对弈来不及把 ±1 的终局值沿 100 手回传" —— 现在知道得更准确：
   **不是"来不及"，是"一次都没有"**（`done` 样本恒为 0），所以 critic 的自举项里
   从来就没有过棋局真值。

### 10.3 于是"后期重杀将"要落地，只剩三条路

| # | 做法 | 代价 / 风险 |
|---|---|---|
| ① | **让自对弈真的打到终局**：残局课程（从"车马 vs 光将"这类可赢局面开局）、或换一个会杀棋的对手当陪练 | 会**同时**唤醒 §5 的"延迟激励"，那时 `mateBoost` 必须按 `Δ < 100·ln(1+b)` 重新取值 |
| ② | **把杀将信号搬到即时通道**：每步给"将军 / 威胁对方将 / 将死距离"的塑形项（本工程的 `evaluate()` 里已经有"将安全"项可借） | 即时项**一定**进得了学习（第 9 节证明了 `matBoost` 有效），代价是又多一个手写塑形 |
| ③ | **给价值函数任务外的直接监督**（把子力/引擎评分蒸馏进 critic） | 上一册 §7.3 已经点名；是本工程里唯一"不依赖终局样本"的通道 |

**短结论**：用户那句"后期应该重杀将奖励"在**当前训练协议下无法实现** ——
不是加权加得不够，而是那条通道没有样本。要让它有意义，先得让训练见到终局（①），
或者换一条每步都能到的通道（②/③）。

### 10.4 【2026-09 更正】"终局通道是空的"是**协议特定**的，不是结构性结论

上面 §10 写的是"自对弈训练里一条终局样本都没有"。**那句话在当时那个协议下是对的，
但不能推广**——后续（独立类拆分那一轮）在另一个协议上量到了非 0：

| 协议 | 样本 | done（且分胜负） | `mateBoost` 0 vs 10 |
|---|---|---|---|
| TB 类, `--train-sims=4`, 120 手上限, 12 局 | 11296 | **0 (0.0000%)** | 权重**逐字节相同** |
| TB 类, `--train-sims=16`, 80 手上限, 12 局 | 7040 | 2 (0.0284%) | — |
| MoE-MLP, 16 模拟/步, 80 手上限, 60 局热身 | 37504 | **53 (0.1413%)** | 权重**不同**（`221FB956…` vs `D419EF76…`） |

⇒ 准确的表述：**终局样本极其稀疏（0 ~ 0.14%，取决于每步模拟数 / 手数上限 / 骨干），
可以恰好为 0；一旦非 0，`mateBoost` 就真的会改权重**。
所以"后期重杀将"仍然不是一条有效的路（信号在万分之一的样本上），
但"它在训练里完全不存在"这句话要撤回。
详见 `docs/sacmoetb_independent_classes_2026_09.md` §9.4（那张更正表与复现命令）。


### 10.5 这一轮**没有**得出的结论

1. **16 局/锚点分辨不了棋力。** 上一册已经实测过 32 局/锚点的区间宽到 ±8%，
   十二条臂全部重叠；这里更少，所以**任何"涨了/跌了"的得分率都不能单独当结论**。
2. **"因子权重"没有扫。** 三因子等权是**定死的**（只有 `mateScoreMode` 选因子组合），
   "数量该占几成 / 优势该占几成"这一维完全没测。
3. **`mateScoreMode` 的五个口径没测。** 它们只是"哪一维在起作用"的探针。
4. **材料差那一点改善（−2.51 → −2.26 / +0.19 → +0.51）没有统计效力检验。**
   它是 16 个配对的均值差，本轮没算配对 t 检验（上一册的 +9.4 个百分点是 80 局配对
   才显著的）。**要把它变成结论，得按配对口径把局数堆到 80 以上。**
5. **`matBoost` 的最优点没扫**（只测了 0.5 与 0 两档，上界是 1.857）。
