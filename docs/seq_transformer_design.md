# `SeqTransformerExpert` 设计文档：一个**真正的** Transformer 专家（2026-10）

> 代码：`src/rl/seq_transformer.hpp`（约 700 行，含注释）· 接线：`rl/ppo.h` 的
> `Backbone::SeqExperts` · 测试：`test/test_transformer_main.cpp` · 背景审计：
> [`docs/tb_expert_training_2026_10.md`](tb_expert_training_2026_10.md) §9/§10
>
> 一句话：**把"状态向量"按格子切成 90 个 token，跑标准 Pre-LN Transformer 编码器，
> 再逐格投影回原维数** —— 旧 `TransformerBlock` 的两处结构错误（没有 token 轴、
> 全局 softmax）在这里都不存在。

---

## 0. 为什么要有它（以及为什么不是"修一修旧的"）

`MultiHeadAttention` / `TransformerBlock` 收的是**一个 `(d_model × 1)` 向量**，于是：

| 旧实现 | 后果（实测，见 §9 审计） |
|---|---|
| 没有 token 轴 ⇒ `z = q·kᵀ` 是 `d_k×d_k` **外积** | 混合的是"特征维"，不是"哪个位置该注意哪个位置"。这不是 attention |
| `softmax(z)` 是**全局**归一（对整张 `d_k²` 张量求和） | 每行只分到 `1/d_k` 的质量 ⇒ 单头输出被**恰好 `d_k` 倍**衰减（d_k=114 时实测 114.01×） |
| 初始化时该支路只占块输出方差 **5.6e-07** | 90.4% 的参数、90.8% 的乘加服务于一条几乎不影响函数的支路 |
| 没有位置信息（`PositionalEncoder` 从未被实例化） | 棋盘是"无序的格子袋" |

两处都不是调参能修的：**前者是接口形态错了**（没有序列就没有 attention），
**后者是归一化轴错了**。而"在原来的类里把 softmax 改成按行"会有一个静默的代价：
参数量不变 ⇒ 存量权重会被**静默误用**（本工程记过很多次这类事故）。
所以这里选**新加一条支路**：`SeqTransformerExpert`，旧的 TB 专家原样保留（带 `HonorHeads` 修正）。

## 1. 全景数据流

```
 状态 (dIn × 1) = 平面优先: state[plane * 90 + cell]        ← PPOMCTSAgent::STATE_DIM = 1710 = 19 × 90
        │
        │  gather()  —— 按格切 token:  X[t][f] = state[f * SeqLen + t]
        ▼
 序列 X (90 × 19)                                           T = 90 个 token, featDim = 19
        │
        │  fcFwd(embed)      Linear(19 → 64)
        ▼
 (90 × 64) ── + posEmb (90 × 64, 可学) ──►  X₀
        │
        ├───────────────► Block 0 ───────────────►  X₁
        │                                          │
        └───────────────► Block 1 ───────────────►  X₂          (Blocks 可调, 默认 2)
                                                   │
                                  fcFwd(outProj)   │  Linear(64 → 19)
                                                   ▼
                                        (90 × 19) ── scatter() ──► 输出 (1710 × 1)
```

`gather` / `scatter` 是**互逆**的同一套下标：输入按"平面 → 格"，输出按"格 → 平面"。
选择"**每格一个 token**"（而不是每个平面一个 token）的理由：
19 个 token 太少；90 个格子有明确的棋盘语义（谁和谁相邻由位置嵌入与注意力自己学）；
而且输出侧天然可以**逐格投影回 19 维**（见 §6 的决策 D3）。

### 1.1 形状表（PPO 的生产口径）

| 量 | 值 | 来源 |
|---|---:|---|
| `SeqLen` = T | **90** | `PPO_SEQ_LEN`（= `ChessState::CELLS`），编译期模板参数 |
| `featDim` | **19** | `dIn / SeqLen` = 1710/90，构造时校验**整除** |
| `tokDim` | **64** | 运行时：`expertHidden`（`train_bc --expert=` / `PPOMCTSAgent::expertHidden`） |
| `Heads` | **4** | `PPO_SEQ_HEADS`（编译期） |
| `dk` | **16** | `tokDim / Heads`，构造时校验**整除** |
| `Blocks` | **2** | `PPO_SEQ_BLOCKS`（编译期） |
| `dff` | **192** | `3 × tokDim`（运行时） |
| 注意力矩阵 | **90 × 90** / 头 | `Heads × T² = 32,400` 个元素 |

## 2. 单层内部

```
        X  (90 × 64)                                    ← 残差流
        │
        ├───────────────────────────────┐   ← 残差 1（恒等路径）
        ▼                               │
   ln1 = SeqLayerNorm(X)                │               逐 token: 对 64 维求均值/方差
        │                               │
        ├──► Wq ──► Q (90×64)           │
        ├──► Wk ──► K (90×64)           │
        └──► Wv ──► V (90×64)           │
                    │                   │
        每个头 h (dk=16):                │
           S_h = Q_h · K_hᵀ / √dk   (90 × 90)
           P_h = rowSoftmax(S_h)          ← ★ 归一化在 **key 轴**上（每行是一个概率分布）
           O_h = P_h · V_h          (90 × 16)
                    │                   │
        A = concat(O_0..O_3) (90×64)     │
        M = Wo · A                       │
                    │                   │
                    ▼                   ▼
        X1 = X + M        (90 × 64)                      残差 1 相加
                    │
        ├───────────────────────────────┐   ← 残差 2
        ▼                               │
   ln2 = SeqLayerNorm(X1)               │
        F = Wdown · Gelu(Wup · ln2)     │              (64 → 192 → 64)
                    │                   │
                    ▼                   ▼
        X2 = X1 + F       (90 × 64)                      残差 2 相加
```

公式（`T = SeqLen`, `D = tokDim`, `H = Heads`, `dk = D/H`，全部逐 token 独立）：

```
行归一 softmax 的按行性:   Σ_j P[i][j] = 1   （i 是 query，j 是 key）
输出量级:                  |O_h| ~ |V_h|   —— 与 T、与 dk **都无关**
旧实现:                    |o| ~ |v| / d_k  —— 归一化集合是 d_k²，所以量级被头数耦合
```

`dk` 与 `1/√dk` 的温度：LN 输出每坐标方差 ≈ 1，投影权重按 `1/√fan_in` 初始化 ⇒
`q,k,v` 每坐标 std ≈ `1/√3`，`√dk` 缩放之后 **logit 的 std ≈ 1/3**（与 `dk` 无关）——
这是一个"有选择性但不饱和"的起点：`p_max / (1/T) ≈ e^{0.33·2.5} ≈ 2.3`，
梯度（`p(1−p)` 量级）健康。**注意**：旧实现的 logit std 也是 1/3（同一个 `1/√dk`），
它坏在**归一化的集合大小**（`d_k² = 12,996` 而不是 `T = 90`），不是 logit 太小。

## 3. 反向（BPTT）与代码的对应

```
给定 dL/dY (90 × 19)  ← 由 e (1710 × 1) 按 scatter 的逆映射分散得到
  fcBwd(outProj)                       → dCUR = dL/dX₂
  对 b = Blocks-1 .. 0:
     fcBwd(ffnDown, X=c.fh)            → dFh        （dY = dCUR）
     fcBwd(ffnUp,   X=c.h2)            → dH2        （dY = dFh；Gelu 的导数用缓存 o）
     ln2[b].backward(X=c.x1)           → dCUR += …  （残差 2 与 LN2 两条路都进 x1）
     fcBwd(wo,  X=c.att)               → dAtt
     attnBwd(Q,K,V,P,dAtt)             → dQ,dK,dV
     fcBwd(wq,  X=c.h1, dY=dQ)         → dH1
     fcBwd(wk,  X=c.h1, dY=dK)         → dTMP2 ; dH1 += dTMP2
     fcBwd(wv,  X=c.h1, dY=dV)         → dTMP2 ; dH1 += dTMP2
     ln1[b].backward(X=curIn[b])       → dCUR += …  （残差 1 与 LN1 两条路都进本层输入）
  pos.g += dCUR                        ← 位置嵌入是加法路由: 两条支路同梯度
  fcBwd(embed, X=Xs)                   → dXs
  ei += 按 gather 的逆映射分散(dXs)     ← **累加**（iLayer 的约定）
```

`attnBwd` 的四步（逐头，`dO_i` = `dAtt` 在第 i 行、第 h 段的切片）：

```
dP[i][j] = Σ_c dO[i][c] · V[j][c]                       (90 × 90)
dS[i][j] = P[i][j] · ( dP[i][j] − Σ_l P[i][l]·dP[i][l] )  ← 按行 softmax 的雅可比（逐行独立）
dV[j][c] += Σ_i P[i][j] · dO[i][c]
dQ[i][c] += (Σ_j dS[i][j] · K[j][c]) / √dk
dK[j][c] += (Σ_i dS[i][j] · Q[i][c]) / √dk
```

> **按行 softmax 的雅可比是逐行独立的**（`dS_i = P_i ⊙ (dP_i − ⟨P_i, dP_i⟩)`），
> 而旧实现用的是"整张张量一起归一"的那个雅可比 —— 这是两条实现最本质的分叉点，
> 也是 §8 里"常量 token ⇒ 输出逐位相同"那条不变量能把它区分出来的原因。

## 4. 参数与初始化

### 4.1 参数清单（每个专家 = 91,731，实测）

| 张量 | 形状 | 数量 | 说明 |
|---|---|---:|---|
| `embed.w` / `.b` | 64×19 / 64 | 1,280 | `Layer<Linear>`（自带 g/v/m 与 write/read） |
| `pos.val` | 90×64 | 5,760 | **可学**位置嵌入（手动管 g/v/m；不进 `Layer`） |
| `wq,wk,wv,wo`（×2 层） | 各 64×64 / 64 | 16,640/层 | `Layer<Linear>`，带 bias |
| `ffnUp`（×2） | 192×64 / 192 | 12,480/层 | `Layer<Gelu>` |
| `ffnDown`（×2） | 64×192 / 64 | 12,352/层 | `Layer<Linear>` |
| `ln1.γ, ln1.β, ln2.γ, ln2.β`（×2 层） | 各 64 | 256/层 | **`SeqLayerNorm`**（自己管 g/v/m）；**初值 γ=1, β=0** |
| `outProj.w` / `.b` | 19×64 / 19 | 1,235 | `Layer<Linear>` |
| **合计** | | **91,731** | 与 `test_transformer [3]` 的读数逐位一致 |

构成（`paramBreakdown`，实测）：**注意力 33,280 / FFN+嵌入 57,939 / LN 512**。
对照：旧 TB 专家是 12,936,510（注意力占 90.4%）。

actor（E=4/top-1）≈ `4×91,731 + 门控 6,844 + Tanh 头 109,504 + Softmax 头 526,500 = 1,009,772`
—— 是 TB 骨干（52,388,888）的 **1/51.9**。

### 4.2 初始化（`scaleInit()`，由 `scaleExpertInit` 重载调用）

| 张量 | 初值 |
|---|---|
| `embed/outProj/wq,wk,wv,wo/ffnUp/ffnDown` | `U(-1,1)` 再乘 `1/√fan_in`（`scaleFcInit`） |
| `pos.val` | `U(-0.02, 0.02)` 再乘 `1/√tokDim` |
| LN `γ` / `β` | **1 / 0**（标准；不是随机值） |

为什么全部按 `1/√fan_in`：本工程 `iFcLayer` 的默认 `U(-1,1)` 在 d=1710 上会把
pre-activation 顶到饱和（见 `expert.hpp` 顶部那张账）。这里 d 只有 64，量级本来就温和，
但**保持同一套口径**能让"换骨干"这件事只剩结构一个变量。

## 5. 复杂度与内存

### 5.1 乘加（每专家前向，T=90 / D=64 / H=4 / dk=16 / dff=192）

| 项 | 公式 | MAC | 占比 |
|---|---|---:|---:|
| embed | `T·featDim·D` | 109,440 | 1.1% |
| QKV 投影（×2 层） | `2 · 3·T·D²` | 2,211,840 | 22.9% |
| `S = Q Kᵀ`（×2） | `2 · H·T²·dk` | 1,036,800 | 10.7% |
| `P V`（×2） | `2 · H·T²·dk` | 1,036,800 | 10.7% |
| `Wo`（×2） | `2 · T·D²` | 737,280 | 7.6% |
| FFN（×2） | `2 · 2·T·D·dff` | 4,423,680 | 45.8% |
| outProj | `T·D·featDim` | 109,440 | 1.1% |
| **合计** | | **≈ 9.67 M** | 100% |

对照（同 dIn=1710）：旧 TB 专家 **13.3 M**、`Layer<Gelu>` 专家 **2.92 M**、MLP 专家 **0.22 M**。
注意 FFN 在这里是**大头**（45.8%），而旧 TB 专家的**注意力**占 90.8% —— 这正是
"把 FFN 拉回来、把伪注意力去掉"的算术体现（旧实现 `d_ff=360` 只有 `0.21·d_model`，
而注意力是 `4d²`）。

### 5.2 缓存（每个专家实例）

| 组 | 内容 | float |
|---|---|---:|
| 每层（×2） | `h1,q,k,v,att,m,x1,h2,f`（9×90×64）+ `fh`(90×192) + `p`(4×90×90) | 101,520/层 |
| 全局 | `Xs,YS,dXs,dYS`(90×19) + `CUR,FIN,dCUR`(90×64) + `dTMP,dTMP2`(90×192) + `dQv,dKv,dVv`(90×64) + `curIn[2]` | ≈ 76,000 |
| **合计** | | **≈ 279,000 float ≈ 1.1 MB/专家** |

⇒ 一个 MoE 层（E=4）≈ 4.4 MB，actor+critic ≈ 8.8 MB（旧 TB 骨干的"每层四份缓冲"是
**608 MB/网络**，见 `rl/ppo.h` 的表）。`withGrad=false` 时**只**省下参数的 g/v/m（缓存仍要分配）。

### 5.3 实测代价（四臂同协议 BC，1000 局面 / 104 次更新，训练段含 8 轮评测）

| 骨干 | 训练段 | 相对 MLP | 留出 CE | 留出 top-1 |
|---|---:|---:|---:|---:|
| MLP（E8/t2） | 10.8 s | 1× | 2.6917 | 30.0% |
| **序列 Transformer（E4/t1）** | **145.1 s** | 14.8× | 2.6510 | 31.5% |
| 廉价专家（E4/t1） | 47.0 s | 4.3× | 2.5460 | 32.5% |
| TB（E4/t1，现役） | 347.0 s | 32× | 2.6600 | 31.5% |

⇒ 与现役 TB **同档保真度**，但训练**快 2.39×**、actor **小 51.9×**。
它比 MLP 贵 15×，代价的**实测构成**见 §9.2（不是"逐 token 循环"那么简单：反向占 ~88%，
其中 84% 是 `fcBwd`，而 `fcBwd` 的 ~85% 是 `MM::ikjk` 的标量分支）。

> ⚠ **seq 那一行是 2026-10-09 抽类当天重测的**（`145.1 s / 2.6510`，两次运行逐位相同），
> 不是最初那次四臂 sweep 的读数（`140.9 s / 2.6545`）。原因见 §8.3：**那次 sweep 的 seq 臂
> 跑的是"位置嵌入梯度还没修"的陈旧二进制** —— 把那个错法重新注入后，BC 读数把 sweep 的
> 数字**逐位复现**了（`2.5443 / 2.0979 / 2.6545 / 梯度范数 35.8826`）。另外三行不受影响：
> MLP 臂用当前二进制**逐位复现**了 sweep 的 `2.6917`，说明共享路径（BC agent / PPO / Tensor）
> 没变，而 TB/廉价臂根本不含 `seq_transformer.hpp`。
>
> ⚠⚠ **本表的"训练段"一列是 2026-10 修 `MM::ikjk` 之前量的**。修完之后（§9.2.1）两个骨干的
> 训练段实测快 2.19×（seq）/ 2.57×（MLP），所以这一列（以及"快 2.39×""贵 ~15×"这两个由它
> 推出的比值）**引用前要按 2.2~2.6× 重估、最好重测**；四行的留出 CE / top-1 不受影响。

## 6. 设计决策与**被否决的备选**

| # | 决策 | 为什么 | 否决了什么 |
|---|---|---|---|
| **D1** | 新写一个类，不改 `MultiHeadAttention` | 单向量接口里**不存在**序列注意力；而且在原类里改归一化轴会保持参数量不变 ⇒ 存量权重被**静默误用** | "把 `softmax(z)` 改成按行"（留作 §9.3 的选项，代价是权重作废 + 自描述标记） |
| **D2** | token = **格子**（T=90, featDim=19） | 与编码的平面优先布局天然对齐（`state[plane*90+cell]`）；90 个 token 有棋盘语义 | 按平面切（19 个 token 太少）；按任意窗口切（与编码语义脱节） |
| **D3** | 输出 = **逐格投影** `D → featDim` 再散回 | 保留"每格输出是该格特征的函数"这个结构；参数量是 `D·featDim` 而不是 `D·1710`（少 90 倍） | flatten 后 `Linear(90·64 → 1710)`（参数 90 倍、且丢掉逐格结构） |
| **D4** | **按行** softmax（key 轴） | 这是 attention 的定义；输出量级与 T、dk 无关 | 无归一化（输出量级随 T）、全局归一（旧实现，`1/d_k` 衰减） |
| **D5** | 位置嵌入**可学**、无正弦 | T 固定 = 90，可学最直接；正弦在长度可变时才有优势 | 正弦/相对位置/RoPE（§9.3 未做） |
| **D6** | Pre-LN + 残差 | 与仓库既有的块同构、训练更稳；残差保证梯度原样通过 | Post-LN（要 warmup）、无残差 |
| **D7** | `dff = 3 × tokDim` | 标准是 4×；3× 省一点，量级不变（FFN 仍是参数大头） | `dff = tokDim`（容量过小）、`4×`（多 1/3 成本） |
| **D8** | 逐 token 复用 `Layer<Linear>/Layer<Gelu>`，反向时**重跑该 token 的前向** | `Layer<Fn>::backward` 用**它自己缓存的 `o`** 算激活导数，而一个对象被 90 个 token 共用 ⇒ 必须先刷新。代价 1 个额外前向/层；换来"不写第二份 FC/激活反向" | 手写 FC 前后向（第二份实现，迟早漂移）；为每个 token 建一个 Layer 对象（内存 ×90） |
| **D9** | LN 反向**重算**均值/方差 | 同样的 float 运算顺序 ⇒ 逐位相同；省掉"每 token 一个 mu/sigma"的状态 | 缓存每 token 的统计量（多一份状态、多一处可能不同步） |
| **D10** | 主体用 `std::vector<float>` + 显式下标；张量只在参数上 | `(T×D)` 行主序写显式循环最不容易错（本文件的两处坑都是"布局"错）；参数走 `Tensor` 才能复用 write/read/优化器/`paramCount` | 全程 `Tensor` + `MM::` 内核（`ikkj` 是**累加**语义，历史上咬过多次） |
| **D11** | `dIn % SeqLen != 0` 或 `tokDim % Heads != 0` ⇒ **abort** | 这是编译期常量的错，必须**响亮失败**；旧实现"请求 16 头 / 实用 15 头"的静默降级就是反例 | 静默 clamp/取整（读数会变差而不报错） |
| **D12** | `usePos` 做成可关的开关 | 用于**不变量测试**（关掉 ⇒ 对 token 置换等变）；生产路径默认开 | 不可关（就少了一条能证伪的检查） |

## 7. 与旧 `TransformerBlock` 的逐项对照

| | 旧 TB（`<15,360,true>`，d=1710） | 新（`<90,4,2>`，tokDim=64） |
|---|---|---|
| 输入 | `(d_model × 1)` 单向量 | **90 个 token**（每格一个） |
| "注意力"矩阵 | `q·kᵀ` 外积 114×114 | `Q·Kᵀ` 90×90 |
| 归一化 | **全局** softmax（12,996 项） | **按行** softmax（90 个 key） |
| 单头输出量级 | `≈ \|v\|/d_k`（实测被压 114.01×） | `≈ \|v\|`（与 T、dk 无关） |
| 位置信息 | 无 | 可学位置嵌入 |
| 深度 | 1 层 | 2 层 |
| 每专家参数 | 12,936,510 | **91,731** |
| 每专家 MAC | 13.3 M | 9.67 M |
| 头数口径 | 请求 16 / 实用 15（已修成 15/15） | 请求 = 实用（构造时校验） |
| 注意力支路对输出的方差贡献 | **5.6e-07**（初始化时等于死的） | 正常量级；[2b] 证明逐 token 独立可加 |

**为什么 [1] 的输入梯度要"挑大坐标"**：随便取 8 个输入坐标时，多数坐标的解析梯度接近 0，
那里的"相对误差"量的是 float 差分的**噪声地板**（`|L|·1.2e-7/(2eps)`）而不是实现。
第一版随机取坐标，阈值 `1e-2` 长期悬在 6.3e-3；抽 LN 类之后编译器内联/FMA 收缩一变就翻红
（1.7e-2），**而同一批解析梯度只有末位数字变化** —— 那是测试自己在测噪声。改成"取 `|ei|`
最大的 8 个坐标"后读到 4.4e-5，离阈值 200×，读数才有意义。

**为什么 [4] 要用 double 参考**：生产初始化下旧 MHA 的真梯度只有 `1e-7` 量级，
`|L|~1e2` 时 float32 中心差分的噪声地板 ≈ `|L|·1.2e-7/eps`，信噪比 < 1 ——
用库的 float 前向**测不出来**（探针里全是"数值差分被噪声主导"）。
办法是：把前向用 double 逐字重写，先验证"参考 == 库"（相对差 9e-5），
再用 double 差分对库的解析梯度。

### 8.1 [5]：`SeqLayerNorm` 抽类之后为什么必须单独可测（2026-10）

LN 原来是专家里的两个 `static lnFwd/lnBwd` + 四个 `Param`（每个块 2 个 LN × 2 个参数），
抽成一个类之后，**同一份逻辑要有 10 处"新增参数就得顺手改"的接线**（构造 / 前向 / 反向 /
三个优化器 / clamp / `gradNorm2` / `scaleGrad` / `paramCount` / `write` / `read` /
`copyTo` / `softUpdateTo`）—— 每一处都只剩一行循环。代价是"这个类自己有没有写对"必须能查：

| 断言 | 钉住的行为 |
|---|---|
| [5a] γ=1, β=0 ⇒ 每 token 输出均值 0 / 方差 1 | 归一发生在**特征维**（对第 0 个 token 灌了 7.0 的偏置，输出均值偏差 1.8e-8） |
| [5b] γ/β/dX 的解析梯度 == 中心差分（9 项） | 反向里 `−mean(dY) − x̂·mean(dY·x̂)` 两项最容易写错；最差 1.6e-5 |
| [5c1] 同一输入连跑两遍单遍 `backward` ⇒ 逐位相同 | 反向是纯函数，没有残留状态 |
| [5c2] 清零后连跑两遍 ⇒ `dX`/`gG` ≈ 2×（单遍） | **`dX` 必须是 `+=`**：pre-LN 的残差与 LN 两条路写同一个缓冲，写成 `=` 只会"少加"而不报错 |
| [5d] 权重文本**第一行 γ、第二行 β** + 往返逐位相同 | 写序变了 ⇒ 存量权重会**错位读入而参数量对得上**，往返测试自己看不出来 |
| [5e] `gradNorm2` == 手算 Σ(gG²+gB²)、`scaleGrad` 按 s² 缩放、两个优化器跑完自动 `zeroGrad` | 全局裁剪与优化器的接线 |

⚠ [5c2] 的容差**不能**写成 `==`：一个 token 累加 5 次、两遍就是 10 次浮点加法，
浮点加法不满足结合律，所以 2×（单遍）与"累加两遍"只在 2~3 ulp 内相等（实测 gG 相对偏差
1.1e-7，dX 恰好为 0）。第一版这里写了 `==` **而且只调用了一遍 `backward`** —— 于是
"dX 没翻倍"这个假警报把自己骗了一次（真值其实是 `dX₂ == dX₁`）。测试写错和实现写错
长得一模一样，所以本节把两条读数都印出来。

### 8.2 纯重构的证据：抽类前后读数**逐字符相同**（2026-10）

抽 `SeqLayerNorm` 是**纯重构**，只有两件事能证明它对：专家的**权重指纹**不变，以及
**每个数值读数**不变。实测（`.r1build/test_transformer_preclass.txt` vs `..._postclass.txt`）：

| 读数 | 抽类前 | 抽类后 |
|---|---|---|
| FNV-1a 权重指纹（91,731 参数 / 490,037 字节文本） | `9a5483d39a42a333` | `9a5483d39a42a333`（**逐字符相同**） |
| [1] 21 项参数组 FD 的 `ana`/`num`/`相对误差` | 最差 2.277e-3 | 最差 2.277e-3（**18 行逐字符相同**，其余 4 行的**名字**从 `b0.ln1g[0]` 变成 `b0.ln1.gamma[0]`） |
| [2a] 置换等变 \|dx\| / max | 2.864e-06 / 2.384e-07 | 完全相同 |
| [2c] 位置嵌入正对照 | 6.537e-02 | 完全相同 |
| [3] 参数构成 | 注意力 33280 / FFN 57939 / LN 512 | 完全相同 |
| [4] 旧 MHA 反向（参考 vs 库 + 4 项 FD） | 9.077e-05 / 2.521e-07 | 完全相同 |

**这份"逐字符相同"不是白来的 —— 第一版抽类时它红过一次，并且抓到了一个真差别**：
新写的 `forward` 把 `Y = γ·(x−μ)/σ + β` 写成了 **float 除法**，而原来那个 `lnFwd` 是
`g[j] * (float)((xp[j] - m) / s) + b[j]` —— `m` 是 double，所以**除法在 double 里做**
再舍入回 float。差别是 1 ulp 级，但它是**数值改动而不是重构**：抽类后 [1] 的 `ana` 末位
就开始跳（`3.04996e-01` → `3.04997e-01`），21 项 FD 的读数整片位移。修法是把旧写法
**原样保留**（`(float)((xp[j] - m) / s)`），并把 `eps` 从 `float(1e-5f)` 改成 `double(1e-5)`
—— `1e-5f` 转成 double 是 `1.0000000116860974e-05`，同样会在末位咬人。改回之后全部读数
逐字符回归。

顺带一个诚实的记录：**旧代码自己并不"前后向同序"**。旧注释说"反向重算 μ/σ，同样的
float 运算顺序 ⇒ 逐位相同"，但旧 `lnFwd` 用的是 double 除法、旧 `lnBwd` 用的是
`(xp[j] − mu) / r`（float，`mu = (float)m`）—— 两处并不逐位相同。这一轮**没有改它**
（改它就是改数值，得单独一轮 A/B），只把这个事实写进 `SeqLayerNorm::forward` 的注释里。

**接线里唯一"顺序真的会改数值"的那处：`clamp`。** 前向/反向/SGD/RMSProp/Adam 的顺序
都不影响结果（每个张量独立更新），但 `Optimize::clamp` 对越界项会**从 RNG 重采样**
（`util.hpp`）—— 顺序变了，"哪个参数拿到哪个随机数"就变了（值集合相同、分配不同）。
抽类时顺手把 LN 的 `clamp` 写成"跟着块走"（更自然），一处**顺序不等价**就是这么来的；
现在按旧顺序原样保留：`embed → outProj → 各块 FC → pos → 各块 ln1,ln2`，
并在代码里写了为什么。这一类"看起来纯风格"的顺序，正是纯重构最容易漏掉的东西。

### 8.4 怎么量：本机的读数口径（2026-10，**先读这一节再看任何 ms/ns 数字**）

这台机器（i7-12650H，6P+4E 大小核笔记本）上，**同一个二进制、同一份输入**的耗时能在几小时内
漂好几倍。实测同一个 `test_transformer.exe`：

| 时刻 | 读法 | 耗时 |
|---|---|---:|
| 会话开始 | ctest | **0.60 s** |
| 几小时后 | ctest（同分钟连测 2 次） | **3.38 / 3.38 s** |
| 几小时后 | 直接跑（5 次） | 3.53 / 3.61 / 3.66 / 3.84 / 4.29 s |
| 同一进程内 9 轮 | `probe_seq_cost [B]` 的区间 | forward 13.3~20.6 ms（**2.3× 内漂**） |

⇒ 因此本工程所有计时结论按下面的口径读/写：

1. **只比"同一进程、同一轮"里的成对量**：每轮交替测各变体（顺序翻转），报**中位数**。
   跨会话/跨机器的绝对值只能当量级，不能拿来做决策。
2. **每轮带一条对照通道**（固定小负载），把它的**跨度**一起印出来 —— 那就是这一轮读数的可信度。
   实测跨度 14%~1057%；跨度大的那几轮里，分量之和甚至会超过整体（`[G]` 里出现过 111%）。
3. **不要用 `start /affinity … /wait` 量墙钟**（本文件作者踩过）：它不一定等到子进程结束，
   会给出"固定核心后快 8 倍"这种**假读数**。要用 `Start-Process -PassThru` + 设
   `ProcessorAffinity` + `Wait-Process`，或者干脆让程序自己打印进程内计时。
4. **记录 ISA 开关**：本机同样代码，SSE2 基线比 `/arch:AVX2` 慢 **2.4~2.7×**（仓库用
   `CHESS_ENABLE_AVX2` + CPUID 探测，本机构建里 `RL_CORE` 确实带 `/arch:AVX2`）。
5. 结论要写成**结构性**的（算法/编译器语义），而不是"X 比 Y 快 N 倍"这种依赖机器的形态。
   例：`/fp:precise` 下 MSVC 不会重排累加链 ⇒ 手写整批三重循环比内核慢（幅度随 ISA 变，方向不变）。

配套工具：`probe_seq_cost`（**不进 ctest**，计时探针）
```bat
cmake --build <build> --target probe_seq_cost
<build>\probe_seq_cost.exe        :: [B] 专家 fwd/bwd  [C][D] 分量分解  [E] 单件  [F] 容器/内核  [G] fcBwd 内部  [H] ikjk 标量分支
```
它输出 `[B]~[H]` 七组配对读数 + 对照通道跨度；本节 §9.2 的每个数字都出自它。

## 9. 已知限制、未做的事、提速路线

### 9.1 限制

1. **`dIn` 必须是 `SeqLen` 的整数倍**（按格子切 token 的前提）。
   PPO 的 `1710 = 19×90` ✓；**SAC/DQN 的 `1263 = 17×90 + 3` ✗**（3 个规则上下文是
   额外追加的标量）—— 那两支要用得先改编码口径。
2. **没有 mask / dropout / padding**：本任务没有变长序列，所以不需要；接别的用途要补。
3. **不能在同一个实例上并发前向**：中间量缓存在成员上（与仓库其它层同一种约定）。
4. **前向/反向必须成对**：缓存是"最近一次前向"的；单独调 `backward` 会用到陈旧缓存。

### 9.2 代价在哪里：**反向占 ~88%，其中 84% 是 14 次 `fcBwd`，而 `fcBwd` 的 ~85% 是 `MM::ikjk`**
【实测，`probe_seq_cost`，3 次独立运行取中位数，每次 9 轮交替 + 对照通道】

> ⚠ 本节 2026-10 重写过一次。原版写的是"函数调用与缓存未命中主导"+"把 FC 改成整批**预计压到
> 1/5**"——**那个预测是错的**（实测整批只值 1.00~1.13×）。原因见 §8.4：绝对耗时在同一台机器上
> 都能漂 5~6 倍，而当时的"分解"是**跨会话把各分量相加**得到的，不是同一轮里的比值。

```
一次 forward (13.9 / 14.8 / 15.0 ms)
  ├─ 12 次逐 token FC            26~29%
  ├─ 8 次单头注意力              43~45%
  ├─ 4 次 LN                     2~3%
  └─ 其余 (逐 token 拷贝 / gather / scatter / 残差 / outProj / embed)  ~25%

forward + backward (125~127 ms)  ⇒ backward = forward 的 7.35 / 7.46 / 8.11 倍
  backward 的构成:
  ├─ 14 次 fcBwd                 82~86%     ← 主项
  ├─ 2 次 attnBwd (4 头)          8~11%
  └─ 4 次 LN 反向                 ~1%

fcBwd 内部 (64→64, 每项 = T=90 个 token 一次):
  ├─ 逐 token 拷贝 in/out         ~1%
  ├─ forward 刷新缓存 (D8)         3~5%
  ├─ l.backward 整体              82~111%*
  │    ├─ MM::kikj (反向 GEMV)     2~3%
  │    └─ MM::ikjk (外积 dW)      **84~92%**
  └─ e.zero()/o.zero()            ~0%
  (* 分量之和在漂移大的一轮里会超过 100%，见 §8.4——这正是"同一轮比值"的重要性)
```

**根因（代码事实 + 实测）**：`iFcLayer::backward` 每次调用做一次 `MM::ikjk(g.w, e, x)`，
在 batch=1 的训练里 `kdim == 1`，也就是**单样本的外积**。而 `MM::ikjk`：

1. 它的 SIMD 派发要求每个维度 `>= step<T>()`（AVX2 是 8），而 `x1Col == x2Col == 1`
   ⇒ `mmShapeOk` 为假，**一定走标量分支**；
2. 那条标量分支的 `j` 循环里**重复读 `x1row[k]`**（`kdim=1` 时就是 `x1[i]`），
   而三个指针**都没有 `__restrict`** ⇒ 编译器必须假设 `xrow[j] += …` 可能改写 `x1d`，
   于是既不能把它提到循环外、也不能向量化。

实测（同一进程、同一轮，`probe_seq_cost [H]`）：

| 形状 | `MM::ikjk` | 手写（把 `x1` 的读提到 `j` 循环外） | 比值 |
|---|---:|---:|---:|
| `(64×64) += (64×1)(64×1)ᵀ`（一个 FC 的 dW） | **12.1~15.8 ns/MAC**（49.6~64.9 µs/次） | 0.55~0.64 ns/MAC（2.25~2.63 µs/次） | **22~25×** |
| `(360×1710) += (360×1)(1710×1)ᵀ`（TB/MLP 的真实 FC 形状） | **12.1~20.6 ns/MAC**（**7.4~12.7 ms/次**） | 0.94~1.65 ns/MAC（0.58~1.02 ms/次） | **12~13×** |
| 参照：`MM::ikjk` 在 `kdim=64`（真的整批 GEMM）上 | 0.66 ns/MAC | — | — |

所以差的不是算力、也不是容器，而是**写法与别名假设**；而且这两种写法**逐位等价**
（把 `x1` 的读提前，不改任何加法顺序；`[H]` 里两者在同一个零初值上的最大差 = **0.000e+00**）。

⇒ **修正后的提速路线（按实测收益排序）**：

1. **`MM::ikjk` 标量分支：把 `x1` 的读提到 `j` 循环外 / 加 `RL_RESTRICT` / `kdim==1` 特判**
   ——**【2026-10 已改，见下】**。它占 backward 的 ~85%、backward 又占一次训练步的 ~88%。
   ⚠ 这是**仓库共用**的 kernel（每个 FC 层的反向都走它，见
   `tb_expert_training_2026_10.md` §10.8），所以改动按"两棵源码树两个二进制"的 A/B 验。
2. **整批反向**：`dX = dY·W`（`ikkj`）、`dW += dYᵀ·X`（`kdim=T=90` 的真 GEMM）——
   14×90 = 1260 对小 GEMM 变成 28 个真 GEMM。第 1 条做完之后这一条还有多少收益要重测。
3. **注意力矩阵化 / 反向不重跑前向（D8）**：注意力占 forward 的 43~45%、`attnBwd` 在修完
   第 1 条后升到 backward 的 ~27%、`forward 刷新缓存` 占 `fcBwd` 的 17% ⇒ 现在才轮到它们。
4. 逐 token FC → 整批：**实测只有 1.00~1.13×**（`[F]`），不要为了它去换容器或改结构。

#### 9.2.1 已落地的改动：`MM::ikjk` 的 `kdim == 1` 快速路径（2026-10）

### 9.4 位置编码：可学 1D / 可学 2D 行列 / RoPE（2026-10 补）

`SeqPosEnc`（`seq_transformer.hpp` 顶部）把位置编码抽成一个类，三种模式**可切**：

| 模式 | 参数 | 说明 |
|---|---:|---|
| `LEARN_1D`（**默认**） | 90×64 = 5760 | 与改动前**逐位相同**（同一处分配、同一处 `Random::uniform`、同样的加法循环）⇒ 存量权重与既有读数不变 |
| `LEARN_2D` | (10+9)×64 = 1216 | 行嵌入 + 列嵌入：`pos(t) = row[t/9] + col[t%9]`（棋盘 `canonicalCell = x*9+y`）。**同一行/同一列共享参数** |
| `ROPE` | 0 | 对 Q/K 做旋转（`base=10000`，头内 (2m,2m+1) 成对），注意力只依赖**相对位置** |

**为什么值得做**：1D 的 90 个位置向量彼此**完全独立**（相邻格之间不共享任何参数），而这
张棋盘的行列结构是先验；2D 把参数量降到 1/4.7，并把"同行/同列"变成共享结构；RoPE 则连
位置参数都不要，且天然表达"相对距离"。**代价（诚实记下）**：2D 的位置向量 = `row[r]+col[c]`，
两格相同当且仅当 `row[r]−row[r'] = col[c']−col[c]` —— 这**不只**发生在同行同列，所以 2D
的表达力确实被参数共享约束了；1D 没有这个限制。**哪个更好只能靠读数回答**（§9.7 的 A/B）。

**权重文件自描述**（为什么必须）：`LEARN_1D` 写出的字节**保持原样**（一行张量，FNV 指纹
`9a5483d39a42a333` 不变）；另两种模式先写一行标记 `POS2D` / `POSROPE`。`read` 按"下一行首字符
是不是字母"判格式并与专家当前模式**比对，不一致就 abort**（`test_transformer [6g]` 用子进程
退出码钉住）。这条挡的是"改了结构却不改权重格式 ⇒ 存量权重被静默错位读入"——与 tb 文档
§9.3 方案 B 同一个坑。

**验证（`test_transformer [6]`，全部通过）**：

| 读数 | 值 |
|---|---|
| 默认模式 = 1D、参数量 5760、FNV 指纹与改动前一致 | ✅（§8.2 的口径） |
| 2D 参数量 1216（组数 2）、总参数 91,731 → 87,187 | ✅ |
| 2D 位置向量 == `row[r]+col[c]` 参考实现 | **0.0**（逐位） |
| 2D 行/列嵌入的解析梯度 vs 有限差分 | 最差 **8.6e-4**（4 项）；输入梯度 8.1e-5 |
| RoPE 正交性 \|Q\|² 相对差 / 逆旋转还原 | **1.6e-9** / **4.8e-7** |
| RoPE 定义性质 `s(i,j) = s(i+Δ,j+Δ)`（分量层，量级 19.9） | **1.9e-6** |
| 端到端对照：同样平移后重叠区输出差 | RoPE **8.3e-3** vs LEARN_1D(位置向量×100) **3.32** |
| RoPE 模式下 wq/wo/embed 的 FD | 2.4e-4 / 7.7e-6 / 2.5e-6 |
| 往返 + 模式标记（1D 无标记、2D/RoPE 有）+ 模式不匹配响亮失败 | ✅（子进程退出码 = 0xC0000409） |

> ⚠ **端到端那条"平移不变"不是精确性质**：特征为 0 的格子过了 `embed` 之后**带着 bias**
> （b ≠ 0）也参与注意力，而它的位置在平移后变了 ⇒ 端到端天生不为 0（实测 8.3e-3）。
> 所以定义性质用**分量层**钉（1.9e-6），端到端只当对照。
> ⚠ 测试写法上踩过两次坑（都已修，记在这里）: (1) 换模式后**必须先跑一次前向再 backward**
> （缓存是"最近一次前向"的）；(2) 逐**分量**比 `s(i,j)` 是**错的数学** —— RoPE 在头内把
> (2m,2m+1) 成对旋转，只有**整段点积**才有相对性。

### 9.5 dropout（2026-10 补）

三处标准位置都做了（倒置式：保留 1−p、保留项乘 1/(1−p) ⇒ **推理不需要任何缩放**）：
注意力概率 P（softmax 之后、乘 V 之前）、残差支路 1 的输出 M、残差支路 2 的输出 F。

三条纪律（都是本工程被咬过的地方）：

1. **默认 p=0**：一条随机数都不画、一个缓冲都不分配 ⇒ 存量权重与既有读数逐位不变
   （同 `enableMlpGate` / `HonorHeads` 的处理方式）；
2. 只在 **`inference=false`** 时生效（仓库既有的 `Dropout<Fn>` 层用的是 `withGrad` 当开关，
   而且 mask 的保留概率与缩放不一致 —— 它已被标为死代码并加守卫，见 §9.6）；
3. mask 存在 `BlockCache`，**反向用同一张**；`maskP` 的 P 保持**未丢弃**（softmax 雅可比必须
   用未丢弃的 P，dP 再乘 mask），`dV` 必须用**乘过 mask 的** P。

**验证（`test_transformer [7]`，全部通过）**：p=0 两次前向逐位相同；p=0.5 的**推理**形态与
p=0 输出差 **0**；训练形态两次前向差 1.22（每次重抽 mask）；mask 保留比例 **0.7482**（期望
0.75）、取值只有 `0` 与 `1/(1−p)`；**冻住 mask** 后 wq/wo/embed 的解析梯度 == 中心差分
（5.4e-5 / 7.5e-6 / 5.0e-5）—— 这条同时钉住了"反向用同一张 mask"和"残差那条路没被误乘"。

> ⚠ **`dV` 的 mask 是第一版漏掉的**（只给 dP 乘了 mask，dV 用了未丢弃的 P）⇒ 冻 mask 的
> 有限差分给出 wq 偏大 **15.6%**、embed 偏大 **24.6%** 的**稳定平台**（不是噪声：随 eps 不变）。
> 修好后三项都回到 1.0000。**这就是为什么要有"冻 mask"这个测试开关** —— 不冻 mask 时损失
> 函数不是确定函数，中心差分根本做不了。
> ⚠ 另外，"开了 dropout 之后 Σ|g| 应该变小"是**错的判据**：倒置式把保留项乘了 1.43×，
> 单个 mask 下 Σ|g| 完全可以变大（实测 1.32e4 > 1.23e4）。第一版据此报了假失败。

### 9.6 未接线死代码的守卫（2026-10 补）

`PositionalEncoder` / `Attention<N>`（`attention.hpp`）与 `Dropout<Fn>`（`layer.h`）**从未被
任何生产路径实例化**；`net.hpp` 里还有一条 `LAYER_ATTENTION || LAYER_MHA || …` 的分支，
函数体与 `else` **一字不差**（"看起来在特判、其实什么都没做"）。处理方式：

| 动作 | 说明 |
|---|---|
| `iLayer` 加 `requireWired(name)` 守卫（`ilayer.h`） | 默认**禁止**这三个层被调用：一旦接进 Net 立刻 abort 并打印"要走 Transformer 请用 `seq_transformer.hpp`"。测试/研究要真跑它们时显式 `setAllowUnwiredLayers(true)`（可 grep 的 opt-in） |
| `Dropout<Fn>` 的注释里记下它自己的两处语义问题 | ① `bernoulli(p)/(1−p)` 是"保留概率 p"却按"丢弃概率 p"缩放；② 开关是 `withGrad` 而不是 `inference` |
| 删掉 `net.hpp` 那条空分支 | 不改变任何行为（原来的两个分支代码相同），只是别让读者以为有特殊处理 |

**验证（`test_transformer [8]`）**：默认守卫为假；子进程里直接调用 `PositionalEncoder::forward`
**退出码非 0**（= abort，不是静默跑起来）；打开守卫后它**本身仍然正确**（`o = x + sin/cos(pos)`
差 **0.0**、反向恒等差 **0.0**、`Attention<15>` 输出有限），收尾再把守卫关回去。

**为什么 LN 是"一个类"而位置嵌入还是"一个 `Param` + 五个自由函数"**：LN 有 2 个参数 ×
2 个块 × 2（一层两个 LN）= 8 组状态，且前/反向都要按 token 批量驱动 —— 它有自己的
**算法**（逐 token 归一 + 那份雅可比）；位置嵌入只有一个"按元素累加"的梯度，没有算法，
用 `Param` + 循环就够了。抽类的判据是"有没有自己的算法/契约"，不是"参数有几组"。
也**不**复用 `layer.h` 的 `LayerNorm`：那些是 `iFcLayer`（`(D×1)` 向量进/出），要跑
`(T×D)` 就得逐 token 调、代价是 T 次拷贝 **+ 反向里为每个 token 重跑一次前向**（正是
本文件 D8 那条）—— LN 的反向只有 20 行，"复用"换不来什么，拷贝/重跑却是实打实的。
真正出现**第二个**调用方时再把它挪到自己的头文件（本工程惯例：第二份拷贝出现才抽文件，
见 `expert.hpp`）。

### 10.2 必须守住的不变量

| 不变量 | 谁在钉它 |
|---|---|
| `dIn == SeqLen × featDim`、`tokDim % Heads == 0`、`dff == 3×tokDim` | 构造函数（不满足则 **abort**） |
| 状态是**平面优先**（`state[f·SeqLen + t]`） | `gather`/`scatter`；改编码布局会静默错位 |
| `Σ_j P[i][j] == 1`（逐行） | `test_transformer [2b]`（常量 token ⇒ 输出逐位相同） |
| 关位置嵌入 ⇒ 对 token 置换等变 | `test_transformer [2a]`（`usePos=false`） |
| 位置嵌入真的进入计算 | `test_transformer [2c]`（正对照） |
| 解析梯度 == 有限差分（逐参数组） | `test_transformer [1]`（21 项） |
| 权重往返逐位一致 | `test_transformer [3]` |
| `ei` 用 **`+=`** 累加（与其它层一致）；`pos.g`/LN `g` 也累加 | 代码 + [1] 的输入梯度项 |
| `SeqLayerNorm::forward(X, Y)` **要求 `Y` 已按 `(T × dim)` 分配**（这一层不做分配） | 类头注释；每个 token 前向都调它，分配会进热路径 |
| `SeqLayerNorm::backward` 的 `dX` 是 **`+=`**、不返回也不清零；`γ/β` 的梯度也是累加 | `test_transformer [5c1]/[5c2]` |
| LN 的**写序**：每个块先 `ln1`（γ 再 β）后 `ln2`，块按序 | `test_transformer [3]` 的 FNV 指纹 + `[5d]` 的第一/第二行 |
| 反向紧跟对应的那次前向（缓存生命周期 = 最近一次前向） | 调用方契约（`SparseMoE` 逐样本 forward→backward） |
| 同一实例不可重入 | 成员缓存；多线程 = 各自建实例 |
| `withGrad=false` 时 `SeqParam::g` 为空 ⇒ 优化器函数首行 guard | `SeqPosEnc::SGD/RMSProp/Adam` 的 `if (emb[p].g.totalSize == 0) continue;` |
| **位置编码模式必须与权重文件一致** ⇒ 不一致时 `read` 响亮失败（不是静默错位） | `SeqPosEnc::read` 的标记行 + `test_transformer [6g]`（子进程退出码非 0） |
| 2D 位置编码要求 `POS_ROWS × POS_COLS == SeqLen` | 构造函数（不满足则 abort） |
| **RoPE 是正交的、且作用在 Q/K 上**：前向旋转、反向用转置 | `test_transformer [6e]`（\|Q\| 不变 1.6e-9 / 逆旋转还原 4.8e-7 / `s(i,j)=s(i+Δ,j+Δ)` 1.9e-6） |
| **dropout 默认 0 ⇒ 不消耗随机数、不分配缓冲** | `test_transformer [7a]/[7b]`（p=0 与推理形态逐位相同） |
| dropout 的 **mask 只作用在它该作用的那条路**（残差那条不动）、且前后向用**同一张** | `test_transformer [7e]`（冻 mask 的中心差分）—— 第一版 `dV` 用了未丢弃的 P，就是被这条抓出来的 |
| 反向是**累加**的 ⇒ 读梯度之前必须清零 | `test_transformer [6d]/[7e]` 的 `zeroExpertGrads`（第一版漏了，读到"两次反向之和"） |
