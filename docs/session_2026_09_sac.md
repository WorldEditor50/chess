## 3. 下一步验证清单（新会话直接开工）

> 通用前提：**同一 seed + 同一 `--mcts-srand`**（否则比较无效）；**改完源码先确认二进制重编**；
> 20 局只够判大效应（±20 点），小效应一律 200 局 × 多种子。
>
> **状态（2026-09 第二轮，见 [`sac_critic_diagnosis_2026_09.md`](sac_critic_diagnosis_2026_09.md)）**：
> * **① 已做** —— |Q| 的三个值（0.031/2.04/5.6）被证明是**同一个与棋局无关的常数**
>   在不同 α 与钳位下的样子；**|Q_target| 在所有配置里都是 0.072~0.097（随机初始化尺度）**，
>   自举项里的游戏信息恒为 0。α 的方向由"目标熵可不可达"决定（按着法算达不到 ⇒ 单向推走）。
>   clamp×huber 扫描：**|Q| = clampTarget，得分率与 |Q| 无关（平的）**，huber 逐位无差别。
> * **② 已做** —— 还原版打开 `clamp=2 huber=1`：**|Q| 5.6 → 2.0，得分率 63.3% → 68.3%，
>   Fisher p = 1.0（不显著）**；支持"发散程度与棋力不是简单反比"，`arena_..._report.md`
>   §5.2 的因果链需要重述。
> * **③ 已做**（200 局 × 4 种子配对，见新文档 §11）。
> * **④ 已落地**（界面奖励曲线换成学习口径 + 曲线名/逐局明细标出口径，
>   见新文档 §8 与 `test_match [2.19]`）。

### ① 最新实现的 critic 尺度：为什么曾经趴在 \|Q\|≈0.035？（部分已有答案，剩下的是"新状态健不健康"）

* **现状（已更新）**：根因 = α 口径（P5/P6），**已修**。修好前后：\|Q\| **0.034 → 2.01**
  （最大 0.061 → 2.16），策略熵几乎不变（≈1.10 ⇒ 接近均匀）。
* **新出现的问题**：2.01 紧贴 `clampTarget=2` 的边界 ⇒ 目标**长期被夹**，critic 是"有信号但饱和"。
  这算不算健康、要不要放宽或软化钳位，**没有答案**。
* **建议做法**
  1. 在 `learnBatch` 里记录**训练中**的分布（现在只有"最后一次"的快照）：`y` 的夹前/夹后、
     `V(s')`、`α`、`|td err|`。`m_maxAbsTarget` / `m_maxAbsTdErr` 已有，需要的是均值与直方图。
  2. 用它回答三个问题：`y` 有多少比例被夹？`V` 的量级是不是被 `α·H` 项撑起来的？`α` 轨迹长什么样？
  3. 扫 `clampTarget ∈ {2, 3, 4, 0(不夹)}` × `huberDelta ∈ {1, 0}`，看 \|Q\| 落在哪里、棋力怎么变。
* **命令**
  ```bat
  :: 当前默认（\|\|Q\|\| 与策略熵每次都会打印）
  build\...\bench_sac_learn.exe --games=20 --plies=200 --mcts-sims=200 --sims=256 --pre-train=64
  :: 消融
  ... --clamp=3   /  --clamp=4   /  --clamp=0   /  --huber=0
  ```
* **验收标准**：给出"\|Q\| 区间 → 对 MCTS 得分率"的曲线；结论必须带两种子。
* **陷阱**：`--clamp=0` 会退回无约束（59e5233 那种发散），别把它当"更健康"的默认。

### ② 给"59e5233 还原版"单独做"打开 clampTarget/Huber"实验

* **现状**：还原版 `clampTarget=0 / huberDelta=0`（无约束），训练后 \|Q\| 均值 **5.63**（最大 6.08）
  仍能对 MCTS 拿 65%（7 胜 1 负 12 和）。而"最新实现 + 同样无约束"在本轮工具里是 37.5%
  （与有约束逐位相同）—— 说明**发散程度与棋力不是简单反比**，值得单独量。
* **假设**：给还原版打开约束（2/1）会压住发散；可能是①棋力不变（Q 的**排序**没坏，只是量级大）；
  ②棋力下降（PUCT 的探索项被压没了）；③棋力上升（搜索重新用上先验与访问计数）。
* **命令**
  ```bat
  :: 还原版基线（无约束）
  build\...\bench_sac_learn.exe --games=20 --plies=200 --mcts-sims=200 --sims=256 --pre-train=64 ^
      --legacy --label=legacy-noclamp
  :: 打开约束（工具会覆盖派生类钉住的值，并打印实际生效值核对）
  ... --legacy --clamp=2 --huber=1 --label=legacy-clamp
  ```
* **读数**：胜负和、\|Q\| 均值/最大、`rewardShape` 默认下的每局奖励、平均手数。
* **验收标准**：两种子；若 \|Q\| 从 5.6 掉到 ~2 而得分率不变，则"发散"对**这个搜索**无害 ——
  那将推翻 `arena_sac_vs_ppo_report.md` §5.2 的因果解释（当时是 73.3%→32.5%），需要写明为什么两次不同。
* **陷阱**：还原版同时是"叶子走全量、不让从搜索学"，别把它的差别混进结论（一次只动一个变量）。

### ③ 奖励塑形要下结论：200 局 × 多种子**配对**复测

* **现状（只能是"方向对、未证实"）**：20 局/档里 `--reward-shape=2` 让还原版从 65.0% → 72.5%
  （胜 7→10、和 12→9、将死 7→11），但 **Fisher p=0.52**；`--reward-shape=1`（材质清零）65.0%（不变）；
  `--gamma=0.997` 70.0%（和棋仍 12 局）。
* **同时要判的还有 P11**：`--no-sparse-leaf`（未训练对照 70.0% vs 稀疏 52.5%，只有一个样本）。
* **命令（配对：同 seed / 同 mcts-srand / 交替为同一批配置）**
  ```bat
  foreach seed in 20240901 777 31337 424242 (每个种子 50 局):
    bench_sac_learn.exe --games=50 --plies=200 --mcts-sims=200 --sims=256 --pre-train=64 ^
        --seed=<s> --mcts-srand=12345 --legacy --reward-shape=0  --csv=out\s<seed>_shape0.csv
    bench_sac_learn.exe --games=50 --plies=200 --mcts-sims=200 --sims=256 --pre-train=64 ^
        --seed=<s> --mcts-srand=12345 --legacy --reward-shape=2  --csv=out\s<seed>_shape2.csv
  ```
* **验收标准**：合池 200 局；报告**得分率差 + Wilson 区间 + 分胜负局的 Fisher**；
  预先声明"差 < 5 个百分点就判为无实际意义"，避免事后解释。
* **两个 agent 都要跑**：上面那套命令用的是 `--legacy`（塑形当初是在它身上提的），
  但 α 口径修好之后**最新实现**才是主角（它现在 77.5%），塑形对"critic 有信号"和
  "critic 曾经死掉"这两支的意义不同 —— 去掉 `--legacy` 再跑一遍同样的矩阵。
* **陷阱**：`--plies` 会影响"判和"占比（300 才是界面默认）；若要推广到界面结论，用 `--plies=300`
  （代价大约 1.5×）。另：**报告每局奖励必须说明是哪个口径**（曲线口径还是学习口径）。

### ④ 界面奖励曲线换成**学习口径**

* **现状**：`ChessBoard::playMatchGame` 用 `chess.moveForward(step, totalReward)` 的
  **黑方视角记账**再换算成走子方视角，量纲是"材质×1"；agent 学的是 `computeReward()`
  （材质×0.1 + 每步代价 + 终局 ±1）。两者差 10 倍（P7）。
* **做法（建议）**
  1. 奖励曲线的取数改成"**agent 自己的** `computeReward()` + 终局 `terminalReward()`"
     （`aiThinkForAgent` 那条路径本来就有 agent 指针；Alpha-Beta / MCTS 保留 engine 口径并**标注**）。
  2. 界面上把口径写出来（曲线标题/标签）：`环境奖励(学习口径: 材质×0.1 + 每步代价 + 终局±1)`。
  3. 若担心破坏既有读数，可**两条都画**（学习口径 + engine 口径），但要明确谁是主。
* **验收标准**：一局里"曲线上涨的幅度"与"agent 学习到的 reward 总和"逐点一致（写断言，
  放在 `test_match` 的奖励记账节）；导出 CSV 的表头写明口径。
* **陷阱**：`agentrollout` 的终局值是**覆盖**即时奖励（不是相加），换算时别重复计；
  另外这条改动会改变界面上历史读数的可比性（旧截图/旧 CSV 不可直接比）。

## 4. 方法学教训（本轮新增，比结论更值钱）

1. **"回显开关"的检查永远通过**：开关没生效（P2）时，任何"读开关值"的检查都是绿的。
   要在**产物**里读事实（网络里的层类型、`learnSteps` 计数器、落盘文件名）。
2. **"数学上看着等价"不算数**：`TanhNorm<Linear>` + r=1 看着就是 tanh，实测差 8.9e-06（P3）。
   判据只能是"同一输入比输出"。
3. **滚动窗口不能当全量分析**：导出的是最后 2000 点（P8），用户据此提的"第 46 轮那个尖峰"
   在文件里根本不存在。**导出/分析口径不要复用显示口径**。
4. **对照组必须配对**：同一 seed + 固定对手随机流（`--mcts-srand`），否则测的是"换了一副牌"；
   同一命令两次能差 20 个百分点（62.5% vs 82.5%）。
5. **改了源码要确认二进制真的重编**（本轮踩两次，见 P12-②）：一次让"`--legacy-net` 等价"变成了
   空验证，一次让"α 口径改了没差别"变成假结论。**结论出来前先确认"打印出来的实际生效值"。**
6. **显示口径 ≠ 学习口径**（P7）：曲线上的比例解释不了学习信号的比例。
7. **终局类型必须分开**（P9）：将死 / 困毙 / 吃将 / 和棋成因（手数上限 vs 60 回合 vs 重复）
   混在一个"胜"里会把结论说反。
8. **20 局只够判大效应**：本轮唯一被两种子复现的是 α 口径（+40 点量级）；
   材质塑形那种 7.5 点的差需要 200 局。
9. **默认值也是"结论"**：α 口径那条默认值是上一轮以"α 恒为初值"为由改的，方向恰好相反（P5）。
   数据驱动的默认值必须写清**测量协议**，否则下一个人无法判断它是否仍成立。
