## 1. 模块定义与代码事实

### 1.1 前向 / 反向（`src/rl/layer.h:858-938`）

```
前向:  o1 = W·x            (继承自 iFcLayer 的 w，含可选 bias b)
       o1 *= r             r = 1 - 1/outputDim            (layer.h:871)
       o2 = tanh(o1)
       o  = Fn::f(o2 + b)  b 在 tanh **之后**

反向:  d1 = Fn::df(o)·e
       dL = r·(1 - o2²)·d1            (= ∂L/∂o1，链式法则的精确结果)
       ei = Wᵀ·dL                      (= ∂L/∂x，交给上一层)
       g.w += dL·xᵀ ;  g.b += d1
```

* 它**不计算任何统计量**（没有均值、没有方差）——这一点是它与 `LayerNorm`/`RMSNorm` 的根本区别（§3）。
* 它能算 `∂L/∂x`（`ei`），所以可以放在骨干之后（DQN 就是这用法）。
* 它继承了 `iFcLayer` 的 `w`/`b`/优化器/`paramCount`，只覆写了 `forward`/`backward`。

## 2. `r = 1 − 1/D` 的血统

**【历史】三条 commit 就把它钉死了**（上游 `D:\home\lab\snakeAI`，文件在 `snakeAI/rl/`）：

1. `6ec2854`（"PreNorm"）的 **LayerNorm backward** —— `(1−1/N)` 出现在**梯度**里，还带一个
   `#if 1 / #else` 的对照开关（`#else` 是纯链式法则）：
   ```cpp
   #if 1
       float gamma3 = gamma*gamma*gamma;
       float delta = op[i] - u;
       dy[i] = (1.0 - 1.0/float(outputDim))*(gamma - delta*delta*gamma3)*error;
   #else
       dy[i] = gamma*Fn::d(o[i])*e[i];
   #endif
   ```
   注意 `gamma − δ²γ³ = γ(1 − x̂²)`，`x̂ = δγ` —— 这就是 **RMSNorm 雅可比 `(1/‖z‖)(I − x̂x̂ᵀ)` 的对角元**，
   再乘上 LayerNorm 去均值那个 `(1 − 1/N)`。
2. `662090d`（"gradient normalize, TanhNorm"）把 DQN 里的 `LayerNorm<Sigmoid>` 换成 `TanhNorm<Sigmoid>`，
   **同一个提交**还把优化器固定成归一化版 RMSProp；同提交的 README 写下
   *"Tanh-Norm: an approximation of RMS-Norm, with a better robust performance in off-policy learning"*。
3. `2ea0255`（"TanhNorm"）把那个常数搬进**前向**：
   ```diff
   +    float r;    r = 1.0 - 1.0/float(outputDim);
        Tensor::MM::ikkj(o1, w, x);
   +    o1 *= r;
   -            dy[i] = (1 - d*d)*error;
   +            float d1 = Fn::df(o[i])*e[i];
   +            float d2 = o2[i];
   +            dy[i] = r*(1 - d2*d2)*d1;
   ```

**结论**：搬进前向后，backward 里的 `r(1−o2²)` 已经**不再是手插的因子，而是前向的真导数**（§3 实测验证）。
即：这次重构把"模仿归一化梯度"从"改梯度"变成了"改前向"，模仿因此变得合法。

### 2.1 数学身份与"意义保不住"的三条理由

`(1 − 1/N)` 是**去均值投影** `P = I − 11ᵀ/N` 的对角元。它在 TanhNorm 里：

1. **意义不在数值里，在秩 1 结构里**：`P² = P`、`P·1 = 0`；只取对角 `diag(1−1/N)` 之后
   `P² ≠ P`（`(1−1/N)² ≠ 1−1/N`），也不消灭常数向量 → 已经不是同一个数学对象。
   而 TanhNorm 是逐元素层，非对角项**结构上不可能存在**（这正是"对角化"的代价）。
2. **一致地推到底会更荒谬**：逐元素（每个坐标独立）地看去均值投影，单坐标的对角元应该是
   `1 − 1/1 = 0`（一个元素的均值就是它自己，去均值后剩 0）。所以 `1−1/N` 在逐元素层里
   连"该等于多少"都没有自洽定义。
3. **`N` 没有指称物**：LayerNorm 的 N 是**做均值的那个维**；TanhNorm 从不做均值，
   `outputDim` 只是隐藏单元个数。

### 2.2 效应量：`r` 到底做了什么【实测】

隐藏层 90→64、仓库初始化，显式改 `L->r`：

| r | sat(\|tanh\|>0.9) | sat(>0.99) | per-unit 输出幅度中位 | `∂Q/∂x` | vs r=1 |
|---|---|---|---|---|---|
| 1.0（去掉常数） | 0.389 | 0.121 | 0.7618 | 13.410 | — |
| **1 − 1/64（仓库，0.9844）** | 0.379 | 0.114 | 0.7577 | 13.366 | **−0.33%** |
| 1 − 1/8 | 0.318 | 0.073 | 0.7307 | 12.752 | −4.91% |
| 0.5（= `1/√fan_in`） | 0.083 | 0.002 | 0.5798 | 9.227 | −31.19% |

* `r` 是**常数**，而本仓库默认优化器对恒定缩放免疫（§4.3，实测 1000× → 4.8e-07），
  所以它连"梯度侧的模仿"都传不到参数上；唯一残留的是前向的 1.6% 尺度差 → **−0.33%**。
* 与"真正的平滑杠杆"（扇入缩放）差 **~95 倍**（−0.33% vs −31%）。

### 2.3 该固定还是该可变：**固定**，工作点交给初始化

| 选项 | 判定 | 理由 |
|---|---|---|
| 维持 `1−1/D`（固定，不可训练、不做运行时旋钮） | ✅ **推荐** | §2.1 意义已丢；§2.2 效应量 0.33%；改成可训练是零容量收益 + 高代价 |
| 做成可训练参数 | ❌ | `o = Fn(tanh(r·Wx)+b)` 只依赖乘积 `r·W` → **W 的全局尺度重参数化**，不加容量；在尺度无关优化器下是一条**平坦方向**；且必须改 `write/read`（`layer.h:248-268`，只存 w、b）、`copyTo`/`softUpdateTo`（`:229-246`，**否则 DQN 的 QTargetNet 不再镜像 QMainNet**，见 `dqn.cpp:81/229`）、`paramCount`/`initParams`/`RMSProp`/`Adam`/`SGD`/`clamp`，再加权重格式 v3 + `test_weights` |
| 暴露成"可变但不训练"的公开成员 | ❌ | 现状就是这个，而 `r` **不被序列化**（load 时由构造函数按 `outputDim` 重算）→ 手改 `r` 存盘再 load 得到**另一个网络** |

**迁移已实测等价**【实测】：把 `o1 *= r` 换成初始化时 `w *= r`，同一份权重下

```
forward   max|Δo|              = 1.19e-07
dL/dx     max|Δ|               = 1.79e-07     |e_new|/|e_old| = 1.000000   ← 给骨干的梯度不变
dL/dW     max|r·g_new − g_old| = 3.35e-08
```

（`W' = rW`、`dL/dW' = dL/dW / r` ⇒ `dL/dx = W'ᵀdL' = WᵀdL` 对 x 不变；W 自己的梯度只多一个常数因子，
RMSProp 约掉，纯 SGD 下函数轨迹也相同，因为 `Δ(rW) = r·ΔW`。）

> **兼容性注意**：`weights/` 里的旧存档是按"r 在前向"训出来的。若彻底删掉 `r`，
> 旧档 load 进来会差 1.6% 的函数（饱和 0.389→0.379）。要保留兼容就在 `read()` 里补一次
> `w *= r`；**最小风险做法是 `r` 原样不动，只加 `initParams()`**。

## 3. 梯度正确性审计【实测】

FD（中心差分，eps=1e-2，8×8 方阵层以避开 `LayerNorm<Pre>` 的形状断言，见 §10.5）：

**`Fn = Linear`**

| 层 | err ∂L/∂w | err ∂L/∂b | err ∂L/∂x |
|---|---|---|---|
| **`TanhNorm<Linear>`** | 5.8e-06 | 4.1e-07 | **1.1e-05** |
| `RMSNorm<Linear>` | 1.3e-01 | 4.1e-07 | 2.5e-01 |
| `LayerNorm<Def,Linear>` | 1.1e-02 | 4.1e-07 | **3.7e-01** |
| `LayerNorm<Pre,Linear>` | 7.2e-06 | 4.3e-06 | 2.6e-01 |
| `LayerNorm<Post,Linear>` | 1.3e-01 | **1.6e-01** | 3.3e-01 |
| `iFcLayer`（裸线性） | 3.5e-06 | 4.1e-07 | 3.4e-06 |

**`Fn = Sigmoid`**：`TanhNorm` 2.29e-06 / 3.46e-06 / 4.50e-06；`RMSNorm` 2.14e-02 / 4.36e-06 / 3.53e-02；
`LayerNorm<Def>` 9.76e-03 / 1.26e-06 / 5.89e-02；`LayerNorm<Post>` 4.39e-02 / 3.55e-01 / 9.36e-02。

**三条解读**

1. **TanhNorm 是唯一三项全对的**（1e-5 量级 = float 噪声）。原因很干净：它**没有任何数据相关统计量**，
   所以没有"统计量 stop-gradient"这种不一致。
2. 其它层的主要误差来自**统计量被 stop-gradient**（RMSNorm 的 `gamma` 是成员标量、LN 的 `u`/`sigma` 同理），
   即它们的解析梯度**不是自己前向的梯度**。这是全仓共有的近似，不是笔误。
3. `LayerNorm<Def>` 的 `∂L/∂x` 还有一处**内部不一致**：`backward` 里 `kikj(ei, w, dy)` 用的是
   **未居中、未乘 gamma** 的 `dy`，而 `g.w` 用的是居中后的 `e` —— 同一层里两处用了不同的导数。
   实测它交给骨干的 `∂L/∂x`：

   | W 尺度 | ‖ei_code‖/‖ei_ref‖ | cos | 1/gamma |
   |---|---|---|---|
   | 0.02 | 0.013 | 0.906 | 68.5 |
   | 1.00 | 0.971 | 0.978 | 1.06 |
   | 5.00 | 6.720 | 0.968 | 0.15 |

   即"幅度被乘除掉了本层自己的 `1/std`（**逐局面变化**，RMSProp 约不掉），方向还差 2–9%"。
   `LayerNorm<Post>` 另有 `g.b` 多乘一次 `Fn'` 的问题（err ∂L/∂b = 1.6e-01）。
   （`TransformerBlock` **内部**的 LayerNorm 反向是**完整正确**的，带 mean/x̂ 项，见 `transformer.hpp:223-246`、
   `:262-278` —— 所以问题只在"被当成 FC 层单独使用"的 `LayerNorm<Fn>`。）

## 4. 与 `RMSNorm` 的关系：对角化，不是等价

### 4.1 数学

真 RMSNorm：`y = op/‖op‖` ⇒ 精确雅可比 `∂y/∂op = (1/‖op‖)·(I − ô·ôᵀ)` —— 一个**正交投影**。
本仓库实现（`layer.h:815-852`）把统计量 stop-gradient，只剩标量增益 `γ = 1/RMS(op)`，
漏掉了投影项：实测 `∂L/∂w` 误差 34.9%（Linear）/ 0.8%（Sigmoid），
**补回 `(I − ôôᵀ)` 后降到 8.8e-06**【实测】。

TanhNorm 取的是**对角** `1 − x̂²`，并用 `x̂ := tanh(r·Wx)`；因为 `1 − tanh²` 恒等于 tanh 的导数，
"RMSNorm 投影对角元"和"tanh 导数"是同一个函数 —— 这就是 §2 里那个设计的自洽之处。

### 4.2 反向同构 ≠ 机制等价

```
RMSNorm : dy_i = γ · Fn'(o_i) · e_i          → ei = Wᵀdy ; g.w += dy·xᵀ
TanhNorm: dL_i = r(1-o2_i²) · Fn'(o_i) · e_i → ei = WᵀdL ; g.w += dL·xᵀ
```

| | `RMSNorm`：`γ = 1/RMS(op)` | `TanhNorm`：`r(1−o2²)` |
|---|---|---|
| 依赖谁 | 输入的整体幅值（统计量） | 本层自己的输出值 |
| 粒度 | 逐样本、**全层同一标量** | 逐样本 × **逐单元** |
| 范围 | (0, ∞)，小幅值会**放大** | (0, r]，**只会缩小** |
| 数学性质 | 塌掉径向自由度（`N(c·x)=N(x)`，实测逐位不变） | 渐进饱和，**无**不变性 |
| 类比 | 预条件器 / 尺度不变 | 有界的软化 clamp（值域约束） |
| 对权重衰减 | 使其对前置权重**无效**（尺度不变） | **有效**（去饱和=真的改函数） |

### 4.3 优化器交互（决定了"什么能传到参数上"）【实测】

`Optimize::RMSProp`（`optimize.h:64-76`）第一件事是 `dw /= ‖dw‖₂+1e-8`，且更新是 `m/√v`：

| 实验（200 步，同一批方向） | 结果 |
|---|---|
| 梯度 ×1 vs ×1e-3，`clipGrad=true` | 轨迹差 **4.768e-07**（逐位相同） |
| 梯度 ×1 vs ×1e-3，`clipGrad=false` | 4.885e-03（只差 `+1e-9` 的 eps，200 步累积） |
| 平稳梯度 `clipGrad` true vs false | 2.872e-03（**基本 no-op**） |
| 梯度尖峰 ×50 的单步最大位移 | 两者**都是 0.03162**（= `lr/√(1−ρ)`，由 RMSProp 自己给出） |

**三条推论**
1. **恒定缩放（整体或逐坐标）在 `m/√v` 里被约掉** → 任何"让梯度变小/变大"的常数在此优化器下空转。
2. **只有"非均匀"的门控能传到参数上** —— 这解释了为什么 `r`（常数）无效而 `tanh`（逐 (单元,局面) 变化）有效。
3. `clipGrad` 的"对 bootstrap 尖峰的信赖域"其实是 RMSProp 给的；这与 `training_optimization.md §7.13`
   的实测（"既不害也不帮忙"，用的是平稳监督任务）一致 —— 那个场景正是 `clipGrad` 最没用的场景。
   另外 `RMSNorm` 的 `γ` 在单样本下会被 `clipGrad` **完全约掉**：实测 `RMSNorm<Linear>` 与裸
   `Linear`（同权重）的单位化更新方向差 **2.98e-08**。

## 5. 在 DQN 里为什么有效

### 5.1 DQN 的三条结构事实【代码】

* **目标是自己造的**：`qTarget[i] = r + γ·max_a' Q_target(s')`（`dqn.cpp:160`，γ=0.99），
  即目标 99% 来自网络本身，`τ=0.01` 的软更新只是把回路增益压慢（`:186`）。
* **每次更新只有一个动作有误差**：`qTarget = out; qTarget[i] = …`（`:132-167`）→ 对头是秩 1 更新，
  对骨干的信用分配**完全靠 `∂L/∂x`**。
* **值尺度有语义、且头必须能表达它**：`R_max/(1−γ)`；上游 `snakeAI/docs/bcq_divergence_analysis.md:46`
  算过"三步最优路径 1.5+0.99·1.5+0.99²·1.5 ≈ 4.47，Critic 受 Sigmoid 限制永远无法输出正确值"；
  本仓库 `issues_review.md` 的 B18 与 `dqn.cpp:12-22` 是同一课（Sigmoid 头 → Q 卡在 0.000）。
  **⇒ 值域约束要放在隐层，头保持无界** —— TanhNorm 正好只在隐层。

### 5.2 三条机制 + 一个混淆项

1. **自举稳定器**：有界 + 饱和的隐层把 `Q` 的量纲钉住（§6.3 的 `max|Q|` 差 40–400×）。
2. **它是唯一梯度精确的归一化层**（§3），而它替换掉的那个层（`LayerNorm<Sigmoid>`）交给骨干的
   `∂L/∂x` 幅度错了 `1/std` 倍（0.013×–6.7×，逐局面变化）—— DQN 骨干只通过 `∂L/∂x` 学习，
   所以**当初那次"明显变快"里有一份是"把错梯度通路换成对的"**，不能全记在 tanh 头上。
3. **优化器配合**：RMSProp 的尺度无关（§4.3）把"饱和 → 梯度小"的代价清零 → 白拿有界性。
4. **混淆项**（【历史】`662090d`）：同一次观察同时动了三件事（`LayerNorm→TanhNorm`、
   `gradient normalize`、以及随后一批梯度 bug 修复），所以那次观察**分不出因果**。

### 5.3 几何实测（90→64→128，同种子同初始化，只换隐层）【实测】

| 隐层 | ‖h‖ max/mean | 初始 Q 范围 | `\|∂Q/∂x\|` | `\|∂Q/∂θ\|`(隐/头) |
|---|---|---|---|---|
| **`TanhNorm<Sigmoid>`** | **1.11** | **[−9.19, 9.19]** | **4.36** | **2.75 / 4.77** |
| `LayerNorm<Sigmoid>` | 1.04 | [−9.52, 9.54] | 7.47 | 2.65 / 4.85 |
| `Layer<Sigmoid>` | 1.13 | [−10.47, 11.01] | 5.90 | 3.36 / 5.08 |
| `Layer<Tanh>` | 1.08 | [−12.43, 14.08] | 12.79 | 7.29 / 6.40 |
| `Layer<Relu>` | 1.62 | [−23.41, 25.71] | 18.92 | 10.60 / 10.63 |

### 5.4 自举稳定性（合成，**不是收敛实验**）【实测】

同一个 DQN 更新规则（batch=32 累积 → `RMSProp(lr=.01,.9,0,clip=true)`；每 256 步 τ=0.01；γ=0.99），
目标故意设成**不可拟合**（128 个动作各有独立的随机非线性目标），观察 `max|Q|`：

| 隐层 | 250 步 | 1000 步 | 4000 步 | max\|Q\| |
|---|---|---|---|---|
| `TanhNorm<Sigmoid>` | 49.6 | 119.7 | 143.0 | 150.1 |
| `LayerNorm<Sigmoid>` | 47.3 | 118.6 | 143.6 | 150.5 |
| `Layer<Sigmoid>` | 40.8 | 188.7 | 711.6 | 911.5 |
| `Layer<Tanh>` | 18.5 | 143.1 | 670.4 | 862.5 |
| `Layer<Relu>` | 82.7 | 1522.1 | 28824.6 | 59656.9 |
| `Layer<Linear>` | 58.0 | 1279.7 | 27478.4 | 57268.2 |

**结论**：有界隐层把自举爆掉的速度慢 **6–400×**。
**局限（必须写清楚）**：这个合成任务把 `r` 定义成 TD 残差 ⇒ `r ≈ 0` ⇒ 值尺度退化（任意尺度都是不动点），
所以它测的是**稳定性**，**不是收敛速度**。把 `r` 改成链条 MDP 的 O(1) 奖励后重跑才能测"更快"。

## 6. 起作用的是哪个操作

### 6.1 拆解【实测/推断】

| 操作 | 作用机制 | 实测 | 判定 |
|---|---|---|---|
| **`tanh` 的导数门控 `1−o2²`** | 逐 (单元,局面) 自适应加权：饱和处不学、线性区照常学 | 动态范围 **0.0007→1.0（1400×）**；方差 99.4% 在"局面之间" | **核心** |
| **`tanh` 的有界性 `\|o2\|<1`** | 特征/值尺度硬上界 → 掐断自举正反馈 | 初始 Q ±9.2（Linear ±33）；爆掉慢 40–400× | **核心** |
| **"没做归一化"（无统计量）** | 梯度精确，不喂错梯度 | FD 1e-5 vs RMSNorm 13–35% / LN 1–37% | **核心**（也是历史混淆项） |
| `Fn = Sigmoid` | 第二道压缩 | 每单元幅度 ÷3.1、`∂Q/∂x` ÷2.9（13.29→4.52） | 配角（换分辨率） |
| `+b`（tanh **之后**） | 只平移输出，动不了 tanh 工作点 | — | 配角 |
| `r = 1−1/D` | 常数 → 被优化器约掉 | `∂Q/∂x` −0.33%；×1000 梯度 → 4.8e-07 | **惰性** |
| `W·x` | 任何 FC 层都有 | — | 不是它 |

### 6.2 门控的方差分解：它到底在哪个轴上起作用【实测】

16384 个 (单元,局面) 对上的 `1−o2²`：

```
gate:              p1 0.0007   p10 0.0163   median 0.3329   p90 0.9586   max 1.0000
每单元平均 gate:    0.3654 ~ 0.4823（64 个单元几乎一样）
每单元局面间波动:   std/mean = 0.742 ~ 0.916
方差分解:          单元之间 0.6%   |   局面之间 99.4%
```

* **"每单元平均饱和"只占 0.6%**，而这一部分恰好是 RMSProp `÷√v` 会吸收的那类（§4.3）。
  ⇒ 所以"用 tanh 把某些单元压小"这种静态解释是**错的**。
* 起作用的是那 99.4%：同一个单元在不同局面上门控从 0.001 到 1.0 变 ⇒ 一个**样本自适应（局面自适应）的梯度加权**。
* 与 RMSNorm 的分工对照（两者都是"自适应重加权"，轴不同）：

  | | 重加权沿哪个轴 | 谁被压下去 |
  |---|---|---|
  | RMSNorm `γ=1/RMS(op)` | 逐样本、**跨单元统一** | ‖op‖ 大的样本（整条样本被压） |
  | TanhNorm `1−o2²` | **逐 (单元, 样本)** | 该单元已饱和的那些局面（该单元此行由其余局面决定） |

### 6.3 `tanh → Sigmoid`：把 sigmoid 关进活跃区，但"活性"是搬家不是创造【实测】

`RL::Sigmoid` 是 1.702 缩放版（`activate.h:8-11`，导数峰值 0.4255），活跃带约 `|z| ≲ 1.5`。
`|tanh| < 1` 且 `|b| ≤ 1` ⇒ sigmoid 的 argument 被**结构性**限制在 `|o2+b| < 2`：

```
                                   |sigmoid argument| > 2      > 4
TanhNorm<Sigmoid> (仓库配置)              0.0%                 0.0%
Layer<Sigmoid>   (单层 sigmoid)          26.2%                 2.6%
```

**正面（成立）**：消除了单层 sigmoid 的深尾（那 2.6% 的 `σ'<0.01` 坐标在那些局面上完全不学，
正是 B18 病理的隐层版）。

**但总增益反而下降**——局部增益 `∂o_j/∂(Wx)_j` 的分布：

```
hidden layer                  p1      p10   median      p90      max    <0.02   <0.1   deadU
TanhNorm<Sigmoid> (仓库)   0.0001   0.0028   0.0764   0.3262   0.4188   0.281  0.555   0.000
TanhNorm<Linear>           0.0007   0.0157   0.3434   0.9444   0.9844   0.115  0.281   0.000
Layer<Sigmoid>             0.0007   0.0112   0.1709   0.4103   0.4255   0.145  0.376   0.000
Layer<Tanh>                0.0003   0.0106   0.3029   0.9498   1.0000   0.144  0.314   0.000
Layer<Linear>              1.0000   1.0000   1.0000   1.0000   1.0000   0.000  0.000   0.000
Layer<Relu>                0.0000   0.0000   1.0000   1.0000   1.0000   0.465  0.465   0.000
```

* **中位增益 0.076**（单 sigmoid 0.171、单 tanh 0.303、线性 1.0）；
* **近死区（<0.02）比例 28.1%**，是所有饱和方案里**最高**的（单 sigmoid 14.5%、单 tanh 14.4%）。
* 原因：#两个饱和函数的导数相乘。tanh 那 37% 的饱和样本已经把它自己的导数压到 ~0，
  不管 sigmoid 多"活跃"，乘积都是 0。**`|tanh|<1` 保住的只是 sigmoid 的 argument，付账的是 tanh 的导数。**
* 自洽性检查：sandwich 的最大增益 `0.4188 = 0.4255 × r = 0.4255 × 0.9844` ✓。

**它在 DQN 上仍净收益的原因**：优化器尺度无关 ⇒ "增益小"不付代价；而自举 TD 对"Q 平滑/尺度稳定"
敏感、对"特征分辨率"不敏感 —— 这正好对应上游 README 里"off-policy 用 TanhNorm / on-policy 用 layer-norm"的分工。

## 7. 工作点：唯一的真旋钮

`W ~ U(-1,1)`、fan-in=90、状态为 ±1/7 稀疏 ⇒ `std(Wx) ≈ 1.9`；而 `r ≈ 1` 不调它。
实测（隐藏层 90→64，256 个局面）【实测】：

| W ~ U(−a,a) | sat(\|tanh\|>0.9) | sat(>0.99) | per-unit 幅度中位 | `∂Q/∂x` | Q[min..max] |
|---|---|---|---|---|---|
| 0.25 | 0.000 | 0.000 | 0.3662 | 5.374 | [−12.26, 10.25] |
| 0.50 | 0.080 | 0.002 | 0.5705 | 8.819 | [−15.70, 13.00] |
| **1.00（仓库）** | **0.373** | **0.111** | 0.7564 | 13.665 | [−18.78, 14.48] |
| 2.00 | 0.662 | 0.428 | 0.8746 | 19.397 | [−14.86, 18.90] |

* 仓库初始化下 **37% 的 (单元,局面) 已在 `|tanh|>0.9`、11% 在 `>0.99`** → 门控大面积接近 0。
* 仓库里**已经有**这个问题的正解：`src/rl/ppo.cpp:20-36` 的 `scaleLayerInit`
  （注释原文："d 维输入下 pre-activation 的标准差约 sqrt(d/3) … Tanh 直接饱和, 梯度接近 0,
  网络看起来'能跑但不学'… 按 1/sqrt(fan_in) 再缩放一遍, 把标准差拉回 ~0.6"），
  `sacazagent.cpp` 用同一套。实测等价效果：饱和 0.389 → 0.083、`∂Q/∂x` −31%。
  **但 chess 侧的 DQN/BCQ 从未接上这套**（只有 PPO 接了）。
* **风险边界**：float32 的 `tanh` 在 `|arg| ≳ 9` 时返回精确 ±1，`1−o2²` 会精确为 0
  （该 (单元,局面) 梯度因子为 0）。实测门控 p1 = 0.0007、min 打印 0.0000 —— 目前稀疏，
  但把尺度调大/权重长大后会出现。要保险就在 backward 给 `1−o2²` 设下限。

## 8. `Fn` 的取舍（`Sigmoid` vs `Linear`）

【实测】同一组权重、同一批局面：

| 层 | per-unit 输出幅度(min/med/max) | `∂Q/∂x` | 初始 Q[min..max] |
|---|---|---|---|
| `TanhNorm<Linear>` | 0.7195 / 0.7581 / 0.7964 | 13.289 | [−16.41, 14.54] |
| `TanhNorm<Sigmoid>` | 0.1759 / 0.2450 / 0.2815 | 4.524 | [−9.01, 9.10] |

外层 Sigmoid 把每单元可用幅度砍到 **1/3.1**、`∂Q/∂x` 砍到 **1/2.9**，并且**不提供 tanh 之外的有界性**
（tanh 已经界住了）。这些效应在 §6.3 的增益分布里进一步体现（近死区 11.5% → 28.1%）。
**取舍**：要更平滑稳定的 Q（自举）就保留 Sigmoid；要分辨率/幅度（细分辨策略头、BC）就用 `Linear`。
`σ(1.702(tanh+b))` 每单元实际取值区间宽度约 0.46（b=0 时 0.269~0.731），实测只用到 0.245 的变化。

## 9. 性能特性【实测】

探针把"同一个数学"写成三档（输出**与梯度逐位相同**，`dOut 0e+00 / dGw 0e+00`；交错多轮取最小值）：

```
shape         fwd cur  fwd +pre   fwd fus | fwd+bwd cur      +pre     fused   (ns/call)
DQN 90->64       1648      1649      2052 |       13013     12324     12793
90->256          6611      6591      8389 |       49906     49484     51202
256->256        11411     11015     12860 |      129570    127639    127180
```

* **`dL`/`dy` 常驻成员**（原本每次 backward 两次堆分配 + 两次 fs）→ 生产形状 fwd+bwd **−5.3%**，
  梯度逐位不变，零风险，**不动权重格式**。
* **手工融合逐元素循环是负优化**：前向 **+13% ~ +27%**。而且 DQN 的**推理路径是纯前向**
  （选点 + 搜索展开/叶估值），融合会直接伤到最需要快的路径 → **不要做**。
* 踩坑记录：把 tanh 融进 `Fn` 的循环时**必须仍然写 `o2[i]`**（backward 需要 `1−o2²`）。
  第一版融合漏写 `o2`，backward 用了陈旧 cache：实测 `o2 diff = 1.0`、梯度偏 0.18。
  **可省的只有 `o1 *= r` 那一趟和 `RL::tanh` 的临时量，`o2` 这个 cache 不能省。**
* 热点：backward 占 84–90%（`kikj`/`ikjk` + `g.zero()` 的带宽）；前向在 90→64 这种小形状上，
  逐元素超越函数（64 次 `std::tanh` + 64 次 `std::exp`）是大头 ——
  `RL::tanh`（`util.hpp:196-203`）是**标量循环**，仓库没有 tanh/exp 的 SIMD 内核（GEMV 有 AVX2）。
  想再压前向只能从这里下手（需要多项式近似 + 定容差）。

| 10.1 | `supportsSparseLogits()` 继承为 `true` | `iFcLayer::supportsSparseLogits()`（`layer.h:54`）为 true，而 `sparseLogits()`（`:122-169`）算的是 `Wx + b` —— **既没有 `r` 也没有 tanh** | 目前只靠 `subsetSoftmax()==false`（`iLayer` 默认）挡住 `Net::sparseOutputSupported()`。**一旦有人按 `supportsSparseLogits()` 分流就会静默算错**。建议显式 `return false`（R1 线上值得加这个防御） |

| 10.5 | 同一文件里 `LayerNorm` 家族的问题 | `LayerNorm<Pre>::backward` 用 `outputDim` 分配 `dL` 再喂 `kikj` → `inputDim ≠ outputDim` 时**直接打爆 `MM` 形状断言**（实测触发 `tensor.hpp:1110`）；`LayerNorm<Post>` 的 `g.b` 多乘一次 `Fn'`；`LayerNorm<Def>` 的 `∂L/∂x` 内部不一致（§3） | 独立使用这些层时行为错误；`test_grad_main.cpp` 只覆盖 TanhNorm 那条生产路径 |
| 10.6 | `RMSNorm` 是死代码 + 反向不完整 | 全仓零调用点；`∂L/∂w` 误差 13–35%（统计量 stop-gradient，缺 `(I−ôôᵀ)`） | 一启用就会静默训练一个"不是自己前向梯度"的梯度 |

## 13. 未决问题（需要真实训练 A/B，不能靠局部分析定）

1. **初始化尺度的最优值**：本分析只证明"37% 饱和"与"−31% `∂Q/∂x`"这两个端点，`a = 0.5` 是否最优
   需要训练对照。协议建议照 `docs/training_optimization.md §7.13` 那种受控 2×2/多档网格；DQN 的胜率
   不是灵敏探针（该文档已记录"分辨力不足"），应改用留出 CE / TD 误差 / 训练-验证间隙。
2. **`Fn` 的选择**：`Sigmoid` 换 `Linear` 是否真的更好（分辨率 ↑ 但 Q 变陡）—— 需要 A/B。
3. **`r ≠ 1` 是否更好**：若历史上扫过 `r` 并发现有效，那它是"init 尺度"在起作用（§2.3），
   应搬进 init 而不是留在前向。
4. **端到端棋力/收敛速度**：本仓库与上游 snakeAI 都**没有** TanhNorm 的受控 A/B 记录
   （关键词全查过）。上游 `snakeAI/rl/dqn.cpp` 的三个变体（`#if 0` 分支）与本仓库
   `src/rl/dqn.cpp` 的四个 `#if` 分支正好是天然的对照起点；蛇的回合短、训练快，比象棋几千局现实。
5. **上游 `snakeAI` 生效分支仍是 `Layer<Sigmoid>` Q 头**（`snakeAI/rl/dqn.cpp:33-40`），
   与 chess B18 是同一个结构性问题，建议照 chess 的修法换 `Linear`。
6. **`train()` 侧的衔接**：chest 侧 PPO 已接 `scaleLayerInit`，DQN/BCQ 未接 ——
   要接就得同时决定"是否也缩 head"（head 的 fan-in 缩放会改变初始 Q 量纲，见 §5.3）。
