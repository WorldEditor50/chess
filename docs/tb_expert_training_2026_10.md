# TB 专家骨干的"难训练"：实测归因与 2026-10 的四处代码改动

> 本文是一次**用户驱动**的调查 + 改动的记录：用户报"用 TB 专家的 PPO agent 比用 MLP 专家的
> PPO agent 更难训练"（实测口径：行为克隆 AB level=4 软目标，与 MCTS 对弈）。本文只写
> **实测/代码事实**、改动与它们的代价；**没有得出的结论**单列在 §8。
> 所有读数都在本机（MSVC Release + AVX2）跑出来，复现命令在 §7。

---

## 0. 一句话结论

**"TB 骨干学不动"这个假设不成立** —— 我第一次把 TB 骨干的 BC 读数跑出来之后，它与 MLP 骨干
**几乎逐项相同**（训练 CE 3.649→2.046 vs 3.662→2.068；留出 top-1 31.5% vs 30.0%），
差的**代价**：三臂各跑 56 次更新、同机空载顺序跑，训练段 TB **159.8 s** / MLP **4.5 s**
（35.5×；含每轮的 train/holdout 评测前向，见 §4 的代价表），
而 TB 的 actor 有 **52.4 M** 参数、其中 **90.4% 是注意力**，而这条支路在初始化时
**只贡献 1.45e-06 的输出方差**（功能上是死的）。再加上界面给两支 PPO 的**模拟预算不同**
（TB 400 / MLP 1600，而模拟次数是本工程唯一测出过棋力的杠杆），
**"TB 更难训练"的账主要记在"每单位算力买到的学习量"和"搜索预算"上，不在"梯度学不到东西"上。**

## 2. 初始化几何：90% 的参数在初始化时不参与函数（实测）

探针 `probe_tb_init`（独立编译，只依赖 `src/rl` 头文件），d_model = `STATE_DIM` = 1710，
喂一个**真实的稀疏局面编码**：

| 量 | 实测 |
|---|---|
| `\|x\|`（局面编码） | 11.53 |
| `\|attn_out\|` = `\|x_res1 − x\|` | **0.0170** |
| `\|ffn_out\|` = `\|o − x_res1\|` | 8.16 |
| **注意力支路占块输出方差** | **1.452e-06** |
| head0 的 `z`（114×114，全局 softmax） max/uniform | **1.273**（几乎均匀） |
| 两个不同局面之间 `\|d(attn)\|` | 0.0247（**几乎不随输入变化**） |

原因（代码事实，两处叠加）：
1. `ScaledDotProduct::forward` 里 `z = q·kᵀ/√d_k` 是**单 token 的外积**（114×114），
   而 `softmax(z)` 是 `util.hpp:465` 那个**对整张张量求和**的全局 softmax ⇒ `Σ_ij z_ij = 1`
   ⇒ 每行的质量只有 `1/d_k` ⇒ 单头输出 ∝ `|v|/d_k`（114 倍衰减）；
2. 初始化时 `scaleExpertInit` 把 q/k/v/wo 都按 `1/√d_model` 缩过，scaled logits 的标准差 ≈ 1/3
   ⇒ softmax 几乎均匀 ⇒ 各 head 的输出退化成**近似常数向量**。

⇒ 实际在跑的是一个 **"恒等残差 + 一个 360 宽的 GELU FFN（~1.2 M 有效参数）+ 一个常数偏置"**，
而它的名义容量是 12.9 M。

**参数构成（实测，`test_ppo_backbone` [3] 钉住）**：

| 部分 | 参数量 | 占比 |
|---|---:|---:|
| 注意力（3·d² qkv + d² wo） | 11,696,400 | **90.4%** |
| FFN（d→360→d） | 1,233,270 | 9.5% |
| LayerNorm（4·d） | 6,840 | 0.05% |

按乘加（MAC）也是同一个比重 —— 单专家前向 = **13.3 M MAC**，其中
**注意力 90.8%**（qkv 投影 8.77 M = 66%、`wo` 2.92 M = 22%、外积 `q kᵀ` 与 `z v` 各 0.195 M = 1.5%），
**FFN 9.2%**。
> ⚠ **更正**：本文早先写过"35.3 M MAC / 注意力 96.5% / `q kᵀ` 占 62.9%" —— 那是把 `d_k×d_k` 的
> **外积**按 `d_k³` 算错了。正确的外积每头只有 `d_k² = 12,996` 次乘加，全专家 0.195 M，
> 所以"秩 1 结构被浪费"这件事**只有 1.5% 的量级，不是效率问题**。
> 交叉验证：修正后的 TB/廉价专家 = 13.3/2.93 = **4.55×**，与 §4 实测的"同一次更新 5.4×"量级一致；
> 若按错的那个数（12×）就会与实测矛盾。

### 2.1 顺带修掉的一处**静默降级**（代码事实）

`PPO_MOE_TB_HEADS` 原来写 **16**（注释还写"1440/16 = 90 维/头" —— 1440 是 `DQNABAgent::STATE_DIM`，
根本不是这个 agent 的 d_model），而 `TransformerBlock<16,360>` 的第三个模板参数 `HonorHeads`
**默认 false** ⇒ 走"头数必须整除 d_model"的老规则。`1710 = 2·3²·5·19`，16 ∤ 1710 ⇒
**实际只跑 15 个头**（d_k = 114）。也就是"请求 16 / 实用 15"，而**一个读数都不会变**
（只是慢一点、容量少一点）—— 这与 `dev_sacmoetb_2026_09.md` §1 记过的同类缺陷（那次是 15/3）同型。

修正：**`PPO_MOE_TB_HEADS = 15` + 显式 `HonorHeads = true`**（`1710 = 15 × 114`，整除、覆盖满）。
**兼容性**：结构与参数总量不变（actor 仍是 52,388,888）⇒ 存量权重仍可载入、同一份权重的前向输出
逐位不变；只有"从随机初始化重训"的初始权重会变（原来构造 16 个 head 再丢掉 1 个）。

## 3. 优化器：`clipGrad` 的真实语义（实测，**并且它不是病根**）

`Optimize::RMSProp(..., clipGrad=true)` 做的是

```cpp
if (clipGrad) { dw /= dw.norm2() + 1e-8; }      /* rl/optimize.h:68 */
```

—— **不是裁剪，是把每层的梯度张量归一化到单位长度**。实测（`probe_tb_init` / `test_ppo_backbone` [4]）：

| 输入的梯度尺度 | `legacy` 的一步 `\|Δw\|` | `none` 的一步 `\|Δw\|` |
|---|---:|---:|
| `\|g\| ~ 1` | 0.0154919 | 0.0154919（**完全相同**） |
| `\|g\| ~ 1e6` | 0.0154919 | 0.0154919（**完全相同**） |
| `\|g\| ~ 1e-14` | 0.0153788（照常一步） | 3.26e-08（几乎不动） |
| `\|g\| ~ 1e-30` | 1.25e-09（≈ 0） | ≈ 0 |

**为什么前两行相同**：RMSProp 自己逐坐标归一（`v[i] = ρv + (1−ρ)dw²`，`Δw = −lr·dw/(√v+ε)`），
任何**整张量的等比缩放**都被 `√v` 抵消。⇒ **换裁剪口径修不了训练**。
（`legacy` 与 `none` 真正有差别的区间只有 `|g| ∈ [1e-16, 3e-9]`：那时 `none` 的 `√v` 被 `1e-9`
的 epsilon 顶住而"冻结"，`legacy` 因为先把 `dw` 放大 1e8 倍反而还在工作区间里 ——
**方向是 legacy 让极小梯度活得更久**，不是它把梯度抹掉。）

那 TB 到底吃了优化器什么亏？**是 RMSProp 的逐坐标归一本身**：每个坐标每步都按 ≈ ±lr 走，
与它的梯度大小、与它对函数的贡献无关。实测一个 BC 批（32 条样本）之后 TB actor 的逐张量梯度：

| 张量 | `\|g\|` | 与最重要的那一项之比 |
|---|---:|---:|
| `ffn_up`（1710→360） | **3.54** | 1× |
| `ffn_down`（360→1710） | 1.54 | 1/2 |
| Tanh 头（1710→64） | 11.7 | — |
| Softmax 头（64→8100） | 2.27 | — |
| 门控 `g_wg` | 1.42 | — |
| **注意力 `wo`（1710²）** | **5.7e-03** | **1/620** |
| **注意力 `wq` / `wk`** | **7.0e-04 / 7.2e-04** | **1/5000** |
| 注意力 `wv` | 1.8e-02 | 1/197 |
| LN1 γ | 7.0e-05 | 1/50000 |

（对照 MLP 骨干：8 个专家的 `l1` 是 0.37~0.62、`l3` 是 0.08~0.18。）
⇒ 占 **90.4% 参数**、对输出只贡献 **1.45e-06 方差**的注意力，与承载全部信号的 FFN
**拿到一样大的步长**（都 ≈ lr/坐标）。这不是"梯度太小所以学得慢"，而是
**"梯度大小的信息在这条骨干上已经不再决定谁被学"**。

## 4. 受控 A/B：BC 学习质量几乎相同，代价差 25 倍（本次实测）

协议（两支**逐字相同**，只换专家）：`train_bc --positions=1000 --depth=4 --soft=1 --soft-depths=4
--epochs=8 --batch=64 --lr=0.002 --seed=20240901 --holdout=5`。

| 读数 | MLP 专家（E=8/top-2） | TB 专家（E=4/top-1） | 廉价专家（E=4/top-1，无 MHA） |
|---|---:|---:|---:|
| actor 参数量 | 2,448,204 | 52,388,888 | **12,346,088** |
| 克隆前 CE（训练 / 留出） | 3.6623 / 3.6516 | 3.6490 / 3.6481 | 3.6654 / 3.6717 |
| 克隆后 CE（训练 / 留出） | 2.0677 / 2.6917 | 2.0463 / 2.6845 | **1.7511 / 2.5460** |
| CE 下降倍率（训练 / 留出） | 1.77× / 1.36× | 1.78× / 1.36× | **2.09× / 1.44×** |
| 留出 top-1 | 3.5% → 30.0% | 1.5% → 31.5% | 1.5% → **32.5%** |
| 留出 P(老师着法) | 0.027 → 0.190 | 0.027 → 0.179 | 0.027 → **0.191** |
| KL(CE−H(t)) 留出 | 3.095 → 2.135 | 3.091 → 2.128 | 3.115 → **1.989** |

**代价（三臂各跑 56 次更新，同机、先后、空载，同一份脚本的"训练段"耗时）**：

| 骨干 | 训练段 | 相对 MLP | 说明 |
|---|---:|---:|---|
| MLP 专家（2.45 M） | **4.5 s** | 1× | |
| 廉价专家（12.35 M，无 MHA） | **29.8 s** | 6.6× | |
| TB 专家（52.39 M） | **159.8 s** | **35.5×** | |

（这一栏含每轮的 train/holdout 评测前向，而评测本身也随骨干变贵；in-process 的裸读数见 §3：
一次 BC 更新（batch=32）TB **1.374 s** vs MLP **0.050 s** = 27.5×；仓库已有的 `learnBatch(4)`
读数是 131.4 ms vs 0.78 ms/样本 = 169×。三个口径的倍数不同是正常的 —— 它们量的分别是
"含评测的端到端"、"纯更新"、"单样本 fwd+bwd+优化器"。）

**这张表是本轮最直接的读数**：三臂的 CE 轨迹同量级（TB 与 MLP 几乎逐项重合），而
**删掉那条死支路**（`Layer<Gelu>` 专家，无 MHA）之后，同一次更新便宜 **5.4×（TB 对廉价）**，
克隆保真度**每一项都更好**（留出 CE 2.546 vs 2.685、top-1 32.5% vs 31.5%、KL 1.989 vs 2.128）。
⚠ 它是"BC 保真度"，**不是棋力**（`docs/behavior_cloning_2026_10.md` §7 已经给过反例：
一致率涨 9 倍而胜率一动没动）。

**裁剪口径的 A/B（同协议、单 seed）** —— 用来验证 §3 的"这不是解药"：

| 骨干 | `--grad-clip=legacy`（默认） | `--grad-clip=global --grad-clip-norm=1.0` |
|---|---|---|
| TB 专家 | 训练 CE 2.0463 / 留出 2.6845 / 留出 top-1 31.5% | 训练 2.0483 / 留出 **2.6605** / top-1 28.5% |
| 廉价专家 | 训练 CE 1.7511 / 留出 2.5460 / 留出 top-1 32.5% | 训练 1.8788 / 留出 2.6089 / top-1 30.5% |

⇒ TB 那一支**几乎重合**（留出 CE 差 0.024，top-1 差 6/200 局量级 = 噪声）；廉价那一支 global
略差（留出 +0.063 nats）。**单 seed、两臂各一次，不足以说"哪个更好"** ——
能说的是：**换裁剪口径没有把 TB 变好**，与 §3 的尺度不变性分析一致。

标签熵 `H(t)` 实测 **0.528（训练）/ 0.557（留出）** —— 这是 depth=4 软目标的第一份读数
（此前只有 depth=2 的 0.1733 与 depth=3 的 ~0.46）。

另一个**合成蒸馏**对照（256 个局面、batch=32、120 次更新、同一 lr/batch）：

| | 批 CE 轨迹 | 每次更新 |
|---|---|---:|
| MLP 专家 | 3.88 → 1.61 | **0.050 s** |
| TB 专家 | 3.88 → 1.77 | **1.374 s（27.5×）** |

⇒ **两条曲线同量级；代价差 25~27 倍。** 这就是"更难训练"的准确含义：
同样多的棋局/时间，TB 买到的是 1/25 的学习量。

## 5. 还有两条与骨干无关、但会直接污染"谁更强"的对照口径

1. **界面给两支的模拟预算是 400 vs 1600**（`chessboard.cpp:294/306`，使用点 `:3854/:4266` 与
   `:3868/:4515`；训练自对弈同样 `BG_TRAIN_SIMS=400` vs `PPO_MLP_SIMS=1600`，`:6835/:6864`）。
   这是"用便宜的算力换更多模拟"的**设计选择**，但它让"骨干谁强"在界面口径下无法回答 ——
   而本工程唯一测出过棋力的杠杆就是模拟次数（40/64/120 → 42.2% / 50.0% / 62.5%）。
   ⇒ 要做骨干对照必须**等模拟**（新加的 `--backbone-ppo-a/-b` 就是为这件事）。
2. **BC 只训练 actor，critic 一个字节都不动**（`bcApplyGradients` 只碰 actorP），
   而 MCTS 的叶子值就是 `ppo.value()`（`ppomcts_agent.cpp:715/744`）⇒
   只做 BC 的会话里，**双方的搜索都是由随机初始化的 critic 驱动的**（TB 那个是 52.4 M 参数的
   随机函数，MLP 那个是 2.4 M 的）。这一点对"模拟次数更多的一方"是额外优势。
3. 和棋口径：界面每局上限 **300 手**，到顶判和（`chessboard.h:513`、`chessboard.cpp:5046-5049`）。
   本仓库踩过两次"全和棋 = 判别力 0"（`bench_dqnmcts_moe` 首测 0 胜 0 负 16 和；
   `moe_gate` A 臂 8/8 截断和棋 ⇒ `50.0% [50.0%, 50.0%]`）。低棋力 + 手数上限的读数里，
   "和棋"经常是**没下完**，不是棋力。

## 6. 本轮的四处代码改动

| # | 改动 | 文件 | 默认行为 | 代价 |
|---|---|---|---|---|
| 1 | TB 头数口径：16 → **15** + 显式 `HonorHeads = true` | `rl/ppo.h` | 结构/参数量不变，存量权重可载 | 无（注意力元素 194,940 → 194,940，d_k 不变） |
| 2 | BC 路径接上 `finalizeMoeBatch()` | `src/bcagent.hpp` | `moeLossFreeBias=false` 时只多记一个计数 | 每批一次（读数级） |
| 3 | 梯度裁剪口径三档 + 梯度范数读数 | `rl/optimize.h`、`rl/ilayer.h`、`rl/layer.h`、`rl/attention.hpp`、`rl/transformer.hpp`、`rl/expert.hpp`、`rl/moe.hpp`、`rl/sparse_moe.hpp`、`rl/net.hpp`、`rl/ppo.{h,cpp}` | **默认 legacy，逐位不变**；范数读数默认**不算** | 只在打开时读一遍梯度 |
| 4 | 新骨干 `Backbone::LayerExperts`（无 MHA 的廉价专家） | `rl/ppo.h`、`rl/ppo.cpp`、`train_bc` / `train_ppo` / `bench_agent_arena` | 只有显式指定才用；**界面未接线** | 无 |

细节：

* **(1)** 见 §2.1。自检面板现在会打"请求 / 实用 / d_k / 注意力元素"，并在
  `请求 != 实用` 时打一行**警告**（这就是让同类偏差"当场可见"的那条读数）。
* **(2)** BC 以前**只注入辅助损失、不跑无辅助损失偏置的控制回路**，也不把 BC 的前向计入
  "训练侧" —— `docs/behavior_cloning_2026_10.md` §7 自己把前者列成已知缺口。
  现在 `BC::update` 在批边界调 `finalizeMoeBatch()`（顺序与在线三条学习路径一致：
  **必须在 `addAuxGradient` 之前**，后者会清批统计）。
* **(3)** `GradClipMode { PerTensorUnitNorm(默认) | GlobalNorm | None }` +
  `iLayer::gradNorm2()/scaleGrad()` + `Net::RMSPropMode()/gradNorm()/gradNormReport()` +
  `PPO::gradClipMode/gradClipNorm/trackGradNorm/actorGradNorm` +
  `train_bc --grad-clip= --grad-clip-norm=`、`train_ppo --grad-clip= --grad-clip-norm=`。
  **必须说清**：由 §3 的实测，这一档**不是**训练问题的解药（RMSProp 会把整张量的等比缩放
  全部抵消）；它的价值在于 ① 把"clipGrad 其实是归一化"这件事写进 API 而不是注释；
  ② 让"关掉裁剪"的对照能只靠命令行跑；③ 提供**此前不存在的**梯度范数读数。
* **(4)** `Layer<Gelu>` 专家（`ExpertFactory<Layer<Fn>>` 早就注册过，**不需要新写专家类**）：
  每个专家 `d²+d = 2,925,811` 参数、E=4/top-1 ⇒ MoE 11.7 M、actor 12.35 M（比 TB 小 4.24×），
  每专家前向 MAC 2.93 M（TB 是 13.3 M，**4.55×**）。它就是"把 §2 那条死支路删掉"的对照臂。
  目前**只接工具**（`--agent=ppo-layer` / `--backbone=layer` / `--backbone-ppo-a|b=layer`）：
  加一个界面 agent 要动十几个构造点，不该和"验证结构假设"混在一轮里。

> 触发：§2 的"注意力支路是死的"读数是**结构**问题还是**实现**问题？本轮把它分开量清了。

### 9.1 结论

**前向/反向的公式是对的（首次被数值证实）；不合理的是"把它当注意力用"这件事本身。**

| 判定 | 内容 | 证据 |

### 9.2 为什么"没发现"：梯度小到测不出来

生产初始化下，损失对注意力权重的真实灵敏度是 `1e-7 ~ 1e-5`，而 `|L| ~ 1e2` 时 float32
中心差分的噪声地板是 `|L|·1.2e-7 / eps ≈ 1e-5 / eps`（eps=1e-2 时就是 1e-3 量级）——
**信噪比 < 1**。所以：

* 用库的 float 前向做差分时，注意力那几栏全是"数值差分被噪声主导"（`probe_tb_grad2` [1] 实测）；
* 这**不是**梯度算错，而是"这条支路对损失几乎没有影响"的另一种表述；
* 想验证它只能换成 **double 参考实现**（`probe_tb_grad3` 的做法），结论是公式正确。

⇒ **仓库里"注意力梯度对不对"这件事，在 2026-10 之前没有任何证据（正反都没有）**。
建议把 `test_grad` 的抽样扩到注意力四栏（它的取样逻辑只枚举 `iFcLayer`，所以天然漏掉
`ScaledDotProduct`）。

## 10. 真 Transformer 专家（`SeqExperts`）：实现 + 验证 + 读数

> 承接 §9：旧 `TransformerBlock` 的两个结构问题（**没有 token 轴**、**全局 softmax**）
> 都不是"调参能修"的 —— 前者是接口形态错了，后者是归一化轴错了。所以这一节是**新实现**：
> `src/rl/seq_transformer.hpp` 的 `SeqTransformerExpert<SeqLen, Heads, Blocks>`，
> 接成 PPO 的第四种骨干 `Backbone::SeqExperts`（`--agent=ppo-seq` / `--backbone=seq`）。

### 10.1 它做了什么（标准 Pre-LN Transformer 编码器）

| 步 | 内容 |
|---|---|
| 1 | **token 化**：状态是"平面优先"的 `state[plane*90 + cell]` ⇒ 按**格子**切：第 t 个 token = 该格在 19 个平面上的取值（T=90，featDim=19）。`dIn` 不能被 `SeqLen` 整除时**响亮失败**（不静默降级） |
| 2 | `Layer<Linear>` 嵌入 `featDim → tokDim`（默认 64）+ **可学位置嵌入** `(90 × 64)` |
| 3 | 每层：`ln1 = LN(X)` → `Wq/Wk/Wv` → `scores = Q Kᵀ/√d_k`（**90×90**）→ **按 key 轴逐行 softmax** → `O = P V` → `Wo` → `X += M` |
| 4 | 每层：`ln2 = LN(X)` → GELU FFN（`tokDim → 3·tokDim → tokDim`）→ `X += F` |
| 5 | 逐格输出投影 `tokDim → featDim`，按平面优先散回 `(dIn × 1)` ⇒ 仍然满足 MoE "输入输出同维"的契约 |
| 6 | 反向：完整 BPTT；逐 token 调用经过测试的 `Layer<Linear>/Layer<Gelu>`（在每个 token 反向之前**重跑该 token 的前向**把激活缓存刷对 —— `Layer<Fn>::backward` 用自己缓存的 `o` 算激活导数，一个对象被 90 个 token 共用） |

实测结构（`test_transformer` [3]）：**每个专家 91,731 参数**、注意力矩阵 `4×90×90 = 32,400`、
参数构成 `注意力 33,280 / FFN+嵌入 57,939 / LN 512`；PPO 的 actor（E=4/top-1）≈
`4×91,731 + 门控 6,844 + Tanh 头 109,504 + Softmax 头 526,500 = 1,009,772`
—— 比 TB 骨干的 52,388,888 小 **51.9×**。

### 10.4 过程中被测试当场抓住的三个坑（记下来，别重犯）

   表现为"训练段直接崩"（smoke 测试是一行输出都没有就退出）。
2. **位置嵌入的梯度用错了布局**：第一版拿 `dXs`（`(T × featDim)` = 90×19 = 1710 项）
   当位置嵌入（`(T × tokDim)` = 90×64 = 5760 项）的梯度 —— 两者维数不同，索引毫无意义。
   正确的来源是"位置嵌入之后、第一层之前"的那份梯度（`dCUR`）。被 `test_transformer [1]`
   当场抓住（`pos[45][60]`：解析 0 vs 差分 0.33）。
3. **测试自身也会错**：置换等变的方向写反了（拿 `perm⁻¹` 去比，必然"不等变"）、
   `embed.w` 的索引按 1710 写而它的输入维是 19（越界读）。⇒ 审计类工具必须**自带正对照**
   （[2c] 的"开位置嵌入必须不等变"、[3] 的往返逐位相等）才能区分"实现错"与"测试错"。

### 10.5 与旧 TB 专家的逐项对照

| | 旧 TB（`TransformerBlock<15,360,true>`） | 新（`SeqTransformerExpert<90,4,2>`） |
|---|---|---|
| token 轴 | **没有**（输入是单个 `(d_model×1)` 向量） | **90 个格子 token** |
| "注意力"矩阵 | `q·kᵀ` 外积 `114×114`（混的是特征维） | `Q·Kᵀ` `90×90`（query × key） |
| 归一化轴 | **全局** softmax（整张 `d_k²` 求和）⇒ 输出 ∝ `1/d_k` | **按行** softmax（key 轴）⇒ 每行是概率分布 |
| 位置信息 | 无（`PositionalEncoder` 从未被实例化） | 可学位置嵌入（[2c] 证明它在起作用） |
| 深度 | 1 层 | 2 层（`Blocks` 可调） |
| 每专家参数 | 12,936,510（其中 90.4% 是注意力） | **91,731** |
| 每专家 MAC | 13.3 M | ≈ 9.7 M |
| 注意力支路对输出的方差贡献 | **5.6e-07**（初始化时等于死的） | 量级正常（`O(1)`；[2b] 证明逐 token 独立可加） |

### 10.6 明确**没有**得出的结论 / 没做的事

1. **没有棋力读数**。BC 保真度 ≠ 棋力（`docs/behavior_cloning_2026_10.md` §7 的反例）。
2. **界面没接线**（加界面 agent 要动十几个构造点）；目前只有工具能跑
   （`train_bc --agent=ppo-seq` / `train_ppo --backbone=seq` / `bench_agent_arena --backbone-ppo-a|b=seq`）。
3. **SAC/DQN 那条 1263 编码用不了**：`1263 = 17×90 + 3`（3 个规则上下文是额外追加的标量），
   不是 `平面数 × 90`。要用得先改编码口径（把上下文也铺成平面）。
4. **超参没有搜**：token 宽 64 / 4 头 / 2 层 / `d_ff = 3×tokDim` 是**第一版默认值**。
5. **没做的结构项**：RoPE/相对位置、2D 位置嵌入（现在是 90 个独立可学向量）、
   padding mask（本任务不需要）、dropout、梯度检查点（省内存）。
6. 旧的 `Attention<N>` / `PositionalEncoder` 仍然是**未接线的死代码**（只加了注释说明，
   没有删 —— 它们与上游 snakeAI 同源，删除属于 `docs/rl_sync.md` 那条线的事）。
7. **速度还可以再压**：序列专家的前向是逐 token 的标量循环（90 token × 每层 6 个投影），
   没有做矩阵化/批处理。当前读数（**145.1 s**/104 次更新，2026-10-09 抽类当天重测；
   最初那轮 140.9 s 是旧二进制的读数，见 §10.7 末尾）已经比 TB 快 **2.39×**，
   但如果把它接到界面上，第一批该做的就是"整批矩阵乘"（参考 `Layer<Linear>` 的
   `sparseLogits` 那条路：只读需要的那几行）。

### 10.7 过程记录：一次"旧二进制"的假回归（值得写下来）

在收尾跑全量 ctest 时 `test_sacaz` 报了 2 项失败（"Q 朝目标方向移动 / 误差下降"）。
排查结论：**build 目录里的 `test_sacaz.exe` 是 2026-09-23 编的旧二进制**（比当前 HEAD 还早），
而我的构建脚本只编了需要的那几个 target ⇒ 跑的是**旧代码 + 新仓库**。
判据是断言总数：旧二进制报 205 项、重编后是 **473 项**。

处置：① 用 `git stash` 回到基线**并重编** `test_sacaz` → 473 项 0 失败；
② 恢复改动**再重编** → **473 项 0 失败**（同样的 [12a]/[12b] 读数）⇒ 与本轮改动无关。
③ 此后一律用**全量构建**（`cmake --build <build>` 不带 target），避免再有旧二进制混进来。

教训与 §2.1 的头数降级是同一类：**"跑的是哪个二进制"不写在读数里，就必须自己证明** ——
断言总数 / 参数量指纹 / 版本标记都是这类"证明"。

**第二次（2026-10-09 晚，同一天）**：四臂 BC sweep 里的 **seq 臂**也是旧二进制 ——
它跑的是"位置嵌入梯度还没修"的那版 `SeqTransformerExpert`（梯度取 `dXs`(90×19) 而不是
`dCUR`(90×64)）。这次的 tell 比 §10.7 隐蔽得多：**同一次 sweep 里其它三臂都是对的**
（用当前二进制重跑 MLP 臂，`2.6917` 逐位复现），只有 seq 一行差一点点
（`2.0979/2.6545` vs 当前 `2.0936/2.6510`）。定位方式是"把那个已知错法重新注入再跑",
读数**逐位复现**了旧值。⇒ 教训补一条：**"四臂一起跑的，应该都可信"本身就是陷阱**；
跨轮比较任何训练读数之前，先问"这支二进制是什么时候编的"。全过程见
`docs/seq_transformer_design.md` §8.3 与 §5.3 的注。

**顺带一条运行环境的坑（2026-10-09）**：`test_sacaz` 在 ctest 里配了 `TIMEOUT 600`，
机器清闲时跑 **146~147 s**，但那天下午在**机器同时跑别的东西**时同一支二进制跑到了
**>600 s 被 ctest 判 Timeout**（那一次其余 15 个测试全过）。单独重跑它：
**473 项 0 失败**，日志里 [12c] 的读数就是证据 —— "自对弈 16 手用时 70328.7 ms"、
"4 次模拟 2352 ms"，都是纯墙钟、随负载浮动的量。⇒ 见到这个 Timeout 先看**机器在不在忙**、
再看那两行墙钟读数，别先怀疑自己的改动（`test_sacaz` 与 `seq_transformer.hpp` 无任何关系，
只有 `SacazMoETbAgent` 用到 TB 那条线）。

**同时确认的计时口径**（比上面两条更影响结论）：同一台机器上**同一个二进制、同一份输入**
的耗时在几小时内能漂 5~6 倍（`test_transformer.exe`：0.60 s → 3.38 s），同一进程内 9 轮之间
也有 2.3 倍。**所以本工程凡涉及计时的结论，一律只比"同一进程、同一轮、交替测量"的成对比值，
并同时印出对照通道的跨度**；跨会话/跨机器的绝对 ms、ns/MAC 只能当量级。完整口径（含
`start /affinity … /wait` 会给出假读数这个坑）见 `docs/seq_transformer_design.md` §8.4。

### 10.8 `MM::ikjk` 的标量分支：**所有骨干共用**的一个 12~25× 成本（2026-10）

追"序列专家的反向为什么是前向的 8 倍"时，顺着 `probe_seq_cost` 的分量分解一路拆到了
`src/rl/tensor.hpp` 的 `MM::ikjk`，结论对**每个骨干**都成立（`iFcLayer::backward` 每次调用
都做一次 `MM::ikjk(g.w, e, x)`，batch=1 训练里 `kdim == 1`）：

【实测，`probe_seq_cost [H]`，3 次独立运行，同轮成对量】

| 形状 | `MM::ikjk` 现状 | 手写（把 `x1` 的读提到 `j` 循环外） | 比值 |
|---|---:|---:|---:|
| `(64×64) += (64×1)(64×1)ᵀ` | 12.1~15.8 ns/MAC（≈50~65 µs/次） | 0.55~0.64 ns/MAC（2.3~2.6 µs/次） | **22~25×** |
| `(360×1710) += (360×1)(1710×1)ᵀ`（TB/MLP 的真实 FC 形状） | 12.1~20.6 ns/MAC（**7.4~12.7 ms/次**） | 0.94~1.65 ns/MAC（0.58~1.02 ms/次） | **12~13×** |
| 参照：`MM::ikjk` 在 `kdim=64`（整批 GEMM）上 | 0.66 ns/MAC | — | — |

**根因（代码事实）**：
1. SIMD 派发要求每个维度 `>= step<T>()`（AVX2 是 8），而 `x1Col == x2Col == 1`
   ⇒ `mmShapeOk` 为假 ⇒ **标量分支必走**（`simd_ops.hpp:mm_ikjk`）；
2. 那条标量分支（`tensor.hpp` 的 `ikjk`，`xc==1 && x1c==1 && x2c==1` 那一支）在 `j` 循环里
   **重复读 `x1row[k]`**，且三个指针**没有 `__restrict`** ⇒ 编译器必须假设 `xrow[j] += …`
   可能改写 `x1d`，既不能把读提出去也不能向量化。
   同样的代码加上 `__restrict` 或加一个 `kdim == 1` 特判，实测立刻回到 0.47~0.52 ns/MAC。

**这两种改写逐位等价**（只是把 `x1` 的读提前，不改任何加法顺序；`[H]` 在同一零初值上
两者最大差 = **0.000e+00**）⇒ 属于"不用 A/B 论证数值、但**必须** A/B 论证收益"的那类改动。

**为什么值得单开一轮**：一次训练步里 backward 占 ~88%（序列专家实测），而其中 ~84% 是
`fcBwd`、`fcBwd` 里 ~85% 是这个外积，而且它同时影响 PPO（TB/MLP/Layer/seq 四条骨干）、
SAC/AZ 与 DQN 的所有 FC 层反向。

**改动已落地**（`src/rl/tensor.hpp` 的 `MM::ikjk` 标量分支，三条，均为纯写法）：
① 三个指针加 `RL_RESTRICT`（与 `simd/*.hpp` 的 `ikjk(z __restrict, …)` 同一约定）；
② 新增 `kdim == 1` 特判，把 `x1(i)` 的读提到 `j` 循环外；
③ 内层再按 `x2r == 1` 分一条单位步长循环（带运行时步长乘子 `j*x2r` 时 MSVC 不向量化）。

**A/B（两棵源码树 + 两个二进制，同一工具链，两棵树只差这一个块）**：
协议 `--positions=300 --depth=4 --soft=1 --soft-depths=4 --epochs=8 --batch=64 --lr=0.002
--seed=20240901 --holdout=5`（32 次 actor 更新），四臂顺序跑、无并发：

| 臂 | 训练段 | 加速 | 所有读数 |
|---|---:|---:|---|
| `ppo-seq` before → after | 277.5 s → **127.0 s** | **2.19×** | **逐字符相同**（CE / top-1 / P(老师) / 熵 / 梯度范数；去掉墙钟行后差异 = 0） |
| `ppo-mlp` before → after | 17.2 s → **6.7 s** | **2.57×** | **逐字符相同** |

同轮四臂的标注阶段 337.3 / 330.0 / 340.1 / 356.2 s 彼此等价（标注不训练 ⇒ 与 `ikjk` 无关），
所以上面的训练段差值不是同轮抖动。微基准（`probe_seq_cost [H]`）：`ikjk` 在 `(64×64)`
12.1~15.8 → **0.42 ns/MAC**、在 `(360×1710)` 7.4~12.7 ms → **0.552 ms/次**，
与手写版数值差 = **0.000e+00**。

⇒ **结论**：修 `ikjk` 让两个骨干的训练段都快了 **2.2~2.6×**，且**数值一位没动**。
**没有得出的结论**：这**不能**归因 §10.3 那个 TB vs MLP 的 35.5× 代价差（那条差是"同一次更新、
不同骨干"的量级比较，需要另做 A/B）；§10.3 与 `seq_transformer_design.md` §5.3 两张表里的
训练段时间都是**修之前**的读数，引用前要按这次的比例重估或重测。
