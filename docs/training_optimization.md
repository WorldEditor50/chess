# 训练流程优化总结（Phase 0–5）

> 本轮的目标不是"更聪明的算法"，而是**让训练信号真的存在、并且量纲正确**。
> 起点是两个观察：训练损失曲线像低占空比的脉冲；以及"将受威胁时决策很正确，但整体
> 被将死"。两者最终收敛到同一个根因：**奖励的量纲把"赢"压成了次要目标，而价值目标
> 在安静局面里几乎全是 0**——critic 只学会了"将的价值"，没学会"棋的价值"。
>
> 每个阶段都配一个可复现的度量（`test_reward_diag`，headless），每个阶段的数字都是
> 实测的，未做/未验证的部分都明确写在 §7。

---

## 1. 起点：四个被量的现象与它们的根因

| # | 现象 | 根因（读代码 + 实测确认） |
|---|---|---|
| 1 | 训练损失曲线是低占空比脉冲 | 曲线上报的是**一条样本**的损失：`learnSelfPlay` 逐步 `trainStep`（每步 batch=1），循环覆盖后只剩第 64 步的 `(V−target)²`；而那条 target = 最后一步的吃子奖励 ∈ {0,1,2,3,5,**100**}（`ppomcts_agent.cpp`） |
| 2 | 将受威胁时下得对，整体 0:20 被将死 | 奖励只有将附近有强信号（吃將 = 100，且自对弈路径**直接写进轨迹**、经逐手翻号的折现递推放大成 ±100 量级的价值目标）；而终局只有 ±1 —— **吃一个車 (+5) 等于赢五盘棋**，吃光对方 (+35) 是赢棋的 35 倍。这个奖励的最优策略是"吃子"，不是"赢" |
| 3 | 安静局面没有位置感 | 截断的 rollout 一律把终局值当 0，而材质奖励是唯一的稠密信号 ⇒ 绝大多数步的价值目标是 0 ⇒ critic 学成常数 |
| 4 | "搜索空间"只在将附近变小 | 有效搜索空间 = **被访问到的着法数**。将附近有三重原因让它变小（合法分支少 / Q 信号强使 PUCT 收敛 / 结果短程），而一般局面里**展开阶段是 `std::rand()` 随机挑未展开着法**——先验根本没参与"展开哪个孩子" |

## 2. Phase 0 — 先造"能看见真相"的观测量

新增 `test_reward_diag`（headless，不进 ctest），量五件事：跨 agent 的 `computeReward`
一致性、奖励尺度表与不变量、一局随机棋的奖励构成、PPO 的价值目标分布、两种损失口径的差。

**改动前实测**：

```
一方全部非将子力 = 3.5 (value 单位) -> x10 = 35.0, 而 |终局奖励| = 1.0
  >>> 终局 / 一方全材质 = 0.0286          (应 > 1 才算终局主导)
  >>> 吃將的即时奖励 100.0 = 终局的 100 倍 (同一胜负事件两种量级)
一局随机棋: Σ|材质奖励| / |终局| = 32.00
|value target| > 0.1 的样本占比 = 0.0%     <-- 大多数样本对 critic 没有信号
损失口径: 最后一条样本 / 整条批平均 = 1.50  (重尾样本时会差几个数量级)
```

同时把在线路径的损失口径从"最后一条样本"改成"整条轨迹批平均"（`learnSelfPlay` 改为
累积后一次 `applyGradients`），并暴露出 actor 交叉熵 `getLastActorLoss()`。

## 3. Phase 1 — 统一终局、摆正奖励量纲（全部 agent）

**改法**：把奖励尺度集中到 `stone.h` 一处，5 个学习型 agent 的 `computeReward` 全部改为
调用共享的 `stepReward()`：

```cpp
REWARD_MATERIAL_COEF = 0.1f;    // 兵 0.01 / 仕相 0.02 / 馬炮 0.03 / 車 0.05
REWARD_TERMINAL      = 1.0f;    // 胜 + / 负 -
REWARD_STEP_COST     = -0.001f; // 每步代价 (对应 60 回合判和规则)
REWARD_MAX_PLIES     = 120;
```

三条不变量（`test_reward_diag` 当场断言）：

```
|终局| > 一方全部非将子力 x 系数         : 1.0 > 0.35   (2.86x)   ✓
|终局| > 单次最大材质 (吃車)             : 1.0 > 0.05   (20x)     ✓
|终局| > 最长一局 (120 手) 的步长累计    : 1.0 > 0.12   (8.3x)    ✓
```

另外两条口径统一：
* **吃將不再单设 100**（它本来就是终局；单设 100 会让同一事件有 100 与 1 两种量级，
  自对弈路径还会把它直接写进轨迹）。SACAZ 原来就是 0，现在推广到全部 agent。
* 顺带发现 SACAZ 的旧尺度（直接用 `value`）虽然方向正确（单个吃子 < 终局），但**一局
  累积**下来一方全材质 3.5 仍是终局的 3.5 倍 —— 不变量对它是同样成立的，一并修正。

**效果**：`|target| > 0.1` 的占比在一次诊断里先掉到 0.0%（材质缩小 20 倍 + 截断传 0 ⇒
"没有信号"第一次变成可见的数字），随后被 Phase 2 抬到 55–63%。

**顺带修掉的两个真 bug**：
* 损失读数的两个 bug 已在上一轮修（`backward()` 之后取值）；
* 每步代价的步长必须小：最早取 −0.005 时，120 手累计 0.6，会把"200 手判和"压到与
  "快速输棋"同价（诊断 [3] 实测到这个数），改成 −0.001。

## 4. Phase 2 — 修学习目标：自举 + 势能塑形（本轮的核心）

### 4.1 自举

在线路径原来把截断的 rollout 一律传 `finalOutcome = 0`（等于假设"此后双方均势"）。
改成用价值头对最后一手之后的局面估值：`finalOutcome = -V(s_end+1)`（夹到 ±1）。
**自举不需要平移**：critic 学到的目标本来就是 `V + Φ`（塑形后的口径）。

### 4.2 势能塑形（PBRS）：把"棋盘局面价值"接进训练信号

取势能 `Φ(s) = tanh(走子方视角的局面价值 / 2.0) ∈ (-1,1)`，每步奖励加：

```
r'_i = r_i + Φ(s_i) + gamma * Φ(s_{i+1})
```

**为什么不是教科书里的 `γΦ(s') − Φ(s)`**：本工程的价值口径是 negamax 的**逐手翻号**
形式 `V(s_i) = r_i − γ·V(s_{i+1})`，相邻两步走子方互为对手，所以势能项也要跟着翻号。
两条检验（都在测试里）：

1. **平移性**：`V'(x) = V(x) + Φ(x)` 代入递推即得上面的形式。
   实测：塑形与不塑形的 `return[0]` 之差 **精确等于 Φ(s₀)**（差 0.00000）。
2. **策略不变性**：`Q'(s,a) = Q(s,a) + Φ(s)` —— `Φ(s_a)` 那两项**恰好相消**，同一局面下
   各着法排序完全不变。这正是它和"随手加将军加分"的本质区别（后者会诱发乱冲）。

**边界项**：终局常量也必须平移 `finalOutcome' = finalOutcome − Φ(落子后局面)`。漏掉它时
"塑形 − 不塑形"会差一个 `−Φ(s_n)`（实测 −0.02187 vs 正确的 0.00000）—— 这条是靠测试
抓出来的，不是靠读代码。

**落点**：`RL::Step` 增加 `float potential`（该步**落子后**局面的势能，由记录方在棋盘上
算好存进去 —— 轨迹里只有编码张量，事后无法反推），`PPOMCTSAgent::applyPotentialShaping()`
在 `commitEpisode` / `exploreAndTrain` / `endOnline` 三处各调用一次。RL 内核不认识"势能"，
依赖方向保持 "agent 依赖 RL 内核"。

### 4.3 效果（同一个诊断，改动前后）

| 指标 | Phase 1 后 | Phase 2 后 |
|---|---|---|
| `\|value target\| > 0.1` 的样本占比 | 0.0% | **55–63%** |
| `\|target\|` 均值 / 中位 / 最大 | 0.013 / 0.011 / 0.020 | 0.126 / 0.092 / 0.633 |
| 安静着法改变势能 | — | **6/6 手**（最大 ΔΦ 0.023） |

## 5. Phase 5 — 棋盘局面价值评估（与 Phase 2 配套）

`Chess::evaluate()` 原来只有**材质 + PST**，没有任何攻击/将安全/空间项。新增
`positionalScore()`：

| 项 | 权重 | 说明 |
|---|---|---|
| 被将军 | ±0.50 | 将所在格被攻击（最便宜也最关键的一项） |
| 士象完整度 | 每个 0.04 | 象棋里"士象全"是防守完整度的标准项 |
| **空间 / 机动性** | 每可达格 0.004，伸进对方半场再 +0.006 | **不吃子的着法也能改变局面价值** |

空间项的做法：逐子几何地数"可达格数"与"伸进对方半场的格数"（车/炮走射线、马查马腿），
不用 `isAttacked`；只算车与炮（长程子，空间优势最明显），马的"蹩腿"只给一个粗信号。

**一个必须记录的工程决策 —— 两档评估**：
第一版把局面项并进了 `evaluate()`，实测一次评估从 **0.100 µs 涨到 0.650 µs（6.5 倍）**，
而 `ABAgent` 的 depth-4 一步要调约 170 万个叶子 ⇒ 单步从 **107 ms 涨到 1269 ms（12 倍）**。
在等时间对局里这等于把搜索深度吃回去 —— 是"评估更准"换"搜得更浅"。
所以最终拆成两档：

```
Chess::evaluate()            0.100 us/次   给 ABAgent / EVAB 的**叶子评估**（保持不变）
Chess::evaluatePositional()  0.600 us/次   给 RL 的**势能 Φ**（每手只算 2 次）
```

于是 AB 的基准与耗时完全不变，而局面信息照样进了训练信号。开关
`Chess::setPositionalEvalEnabled()` 供 A/B 归因。

## 6. Phase 4.1 — 搜索侧：先验第一次参与"展开哪个孩子"

三个搜索入口（`selectMove` / `trainSelfPlay` / `warmupFromCurrent`）原来都是
`std::rand() % untried.size()` **随机**挑未展开着法 —— 先验只在孩子建好之后才用于 PUCT。
中局约 40 个合法着法、一次决策 80 次模拟，于是**前 ~40 次模拟全花在随机铺开 40 个孩子
上**（每次还都要跑一遍 actor + critic 前向）。

改成 `pickUntriedByPrior()`：先求父节点策略，再取 `pi(s_parent)[a]` 最大的那个。
顺带把 `std::rand()` 从搜索里清除，于是 `RL::Random::setSeed()` 能真正控制整条搜索的
可复现性（多线程分身训练也受益）。

## 7. 棋力层验证（本轮补做）

信号层的验证在 §4.3 已经成立；**棋力层的验证是另一次实验**，做法与结果如下。

### 7.1 协议

1. 用 `bench_ppo_mt --save=<prefix>` 各训练 **300 局**（4 worker、80 模拟/步、batch=64、
   epochs=2、镜像增广开；塑形开 / 关各一份权重）。实测 300 局约 372–376 s（**0.81 局/s**），
   每组约 6.2 万样本、280 轮学习。
2. 用 `bench_ppo_vs_ab --games=20 --budget=140 --depth=4 --opening=4` 与 ABAgent 等时间对局，
   **两个种子各跑一遍**（`--seed=20240901` / `20250101`），用来量这个协议的噪声带。

### 7.2 结果

| 配置 | seed 20240901 | seed 20250101 | 平均手数 |
|---|---|---|---|
| **未训练**（随机权重） | 0 胜 18 负 2 和（**5.0%**） | 0 胜 18 负 2 和（**5.0%**） | 48.8 / 40.8 |
| **塑形开**，训练 300 局 | 0 胜 20 负 0 和（0.0%） | 0 胜 19 负 1 和（2.5%） | 28.1 / 43.1 |
| **塑形关**，训练 300 局 | 0 胜 19 负 1 和（2.5%） | 0 胜 19 负 1 和（2.5%） | 43.2 / 34.5 |

### 7.3 结论（老实说）

* **300 局训练没有带来可测的棋力提升**：三组都仍然 0 胜，得分率 0.0–5.0%。
* **差异幅度与协议噪声同量级**：20 局、每局 ±1 ⇒ 噪声带约 ±5%（≈±1 局）。未训练那一组
  在两个种子下都恰好是 5.0%，而训练过的两组是 0.0–2.5%，**但"5% vs 0%"就是 1 局之差**，
  所以只能说**"没有可测提升"，不能说"塑形有害"**。
* 唯一方向一致的现象：训练过的两组平均手数更短（37.2 手 vs 未训练 44.8 手），
  也就是**更快被将死，而不是被拖到判和**。这与下面的机制假设相容。
* **机制假设（未证实，但可检验）**：300 局只有容量分析（`docs/xiangqi_capacity.md`）要求量级的
  约 0.03%，critic 学不到超过 Φ 的东西 —— 而塑形让它的估值趋近 Φ，于是搜索变成"评估函数与
  AB 同源、但搜得比 AB 浅"的玩家；又因为 Φ 含将安全/空间项（偏进攻），它会更主动地进攻而
  更早被将死。若这个假设成立，**塑形的收益要在训练量足够（critic 超过 Φ）之后才出现**。
* **这次验证的真正收获是协议本身**：20 局等时间对局**测不出 ≤5% 的差别**，所以任何"改动是否
  提升棋力"的问题都必须先换协议（见 §7.4），否则得到的只是噪声。

### 7.4 下一步该怎么验证（按性价比）

1. **换更灵敏的指标** ✅**已做**：`bench_policy_agreement`（选点一致率，SE≈1–2%），见 §7.6。
   下一步是把它当成常规尺子用（任何改动前后都跑一次）。
2. **加局数 + 配对**：至少 100 局 × 3 个种子，或同一组开局下换色配对，把噪声带压到 ±2% 以内。
3. **训练量**：本机 0.81 局/s ⇒ 10⁴ 局约 3.5 小时、10⁵ 局约 1.5 天。中途按对数间隔存档
   （`--save`）各测一次棋力，画出"训练量 → 棋力"曲线 —— 这才是能回答"塑形/自举有没有用"
   的实验，而不是单点比较。
4. 小预算下的替代：先在小规模上做消融（例如把隐藏层压到 32、只训 2000 局）看**趋势方向**，
   再决定要不要投入大预算。

### 7.6 更灵敏的协议：选点一致率探针（已实现，§7.4 的第 1 条）

20 局对局的噪声带是 ±5%，测不出小改动。新增 `test/bench_policy_agreement_main.cpp`
（目标 `bench_policy_agreement`，不进 ctest）：在**同一批固定局面**上比较 PPO+MCTS 与
`ABAgent(深度 D)` 的选点，每个局面一个二值样本 ⇒ 200 个样本的标准误约 1–2%，比 20 局
胜负灵敏一个量级；局面集由种子固定（**与权重无关**），所以换 `--load` 是**配对比较**。

实测（200 个局面、随机开局 6 手、AB 深度 4 作参照）：

| 配置 | 完整着法一致率 | 起点一致率 |
|---|---|---|
| 未训练（80 模拟） | **3.0%** ±1.2 | 25.5% |
| 塑形开，训练 300 局 | **2.0%** ±1.0 | **9.0%** |
| 塑形关，训练 300 局 | **2.0%** ±1.0 | **12.0%** |
| 未训练（8 模拟，功效检验） | 8.5% ±2.0 | 27.0% |
| 随机走法的机会水平 | 3.5% | — |

读法（比 §7.3 的"不可分辨"锐利得多）：

* **未训练网络 3.0% ≈ 机会水平 3.5%** ⇒ 随机初始化的策略就是在乱走（符合预期，也是探针
  的有效性锚点）。
* **训练 300 局后完整一致率仍只有 2.0%**（机会水平附近），而**起点一致率从 25.5% 掉到
  9–12%** —— 这个跌幅远大于它的标准误（约 3%）⇒ **统计上显著**：这 300 局自对弈让策略
  **离 AB 的选择更远了**，而不是更近。这与 §7.3 里"平均手数从 45 手降到 37 手（更快被
  将死）"是两个独立指标指向同一方向。
* **功效检验**：同一权重把模拟次数从 80 降到 8，一致率 3.0%→8.5%（差 5.5%，2.7 倍标准误）
  ⇒ 探针**确实能分辨出真实变化**，不是死数。
* 一个必须记住的边界：这个指标测的是"**策略是否朝更强玩家的选择靠**"，是**代理指标**，
  不是棋力；而且若用 AB 的着法做蒸馏，它会因构造而上升（失去独立性）—— 那时要把参照换成
  更深的 AB（`--depth=5`，实测约 10.9 s/步，只适合少量局面）。

复现：

```bat
<build>\bench_policy_agreement.exe --positions=200 --sims=80 --depth=4
<build>\bench_policy_agreement.exe --positions=200 --sims=80 --depth=4 --load=weights/verify_on
```

### 7.7 Step 2：价值头蒸馏 —— 它成功了，但**没有让选点变好**（一个反直觉的实测）

做法（新增 `bench_ppo_distill`）：先给 `ABAgent` 加了只读的**根搜索分**访问器
（`getLastScore()`，口径是黑方视角 —— 黑是 MAX、红是 MIN），然后

1. 随机开局造 1500 个局面，用 AB **深度 3** 的根分值打标签（1500 局面 25.2 s，16.8 ms/局面）；
2. 把标签换算成 critic 的规范视角：`target = (sideToMove==BLACK ? +1 : -1)·tanh(score/2.0)`；
3. **只训练 critic**（forward → MSE → backward → RMSProp），actor 一个字不动。

结果：

```
符号校验: AB 分值与 evaluatePositional() 的相关系数 = +0.493   (>0 => 视角没搞反)
蒸馏前 MSE: 训练 0.032345, 留出 0.029354
蒸馏后 MSE: 训练 0.005587, 留出 0.006914      (留出 4.2x 下降 => 真泛化, 不是记忆)
```

**价值头确实被蒸馏成功了**（留出 MSE 降 4.2 倍），但用探针量"这有没有让选点朝 AB 靠"：

| 探针（200 局面，AB 深度 4） | 完整着法一致率 | 起点一致率 |
|---|---|---|
| 未训练（80 模拟） | 3.0% ±1.2 | 25.5% |
| **只蒸馏价值头**（80 模拟） | 2.0% ±1.0 | 30.5% |
| 未训练（200 模拟） | 3.0% ±1.2 | 25.5% |
| 只蒸馏价值头（200 模拟） | 1.5% ±0.9 | 26.0% |

**结论：价值头变准了（4.2×），选点几乎没动**（差别都在两倍标准误内，且方向不一致）。
这不是"蒸馏没用"，而是把瓶颈定位清楚了：

* 蒸馏出的目标本身**量程很小** —— 随机开局 8 手的局面大多是均势，标签 ≈ ±0.1~0.3，
  于是 V 的差异只有 0.1 量级，而 PUCT 里它要跟**随机的先验**产生的探索项竞争；
* 更关键的是**先验（actor）还是随机的**：中局约 40 个合法着法、80~200 次模拟，
  树仍然主要靠（随机）先验铺开 ⇒ **搜索无法聚焦，好价值头无从发挥**。
* 顺带一个佐证：未训练网络把模拟从 80 提到 200，探针数字**一动不动**（3.0%/25.5%）
  —— 说明在这个先验质量下，**多搜索完全无效**。这比任何论证都更直接地指出瓶颈在哪。

**因此 Step 3 的优先级要改**：不是继续加强 Φ/价值那一侧（那已经是我这几轮一直在做的），
而是**先验/actor 那一侧** —— 让 MCTS 的访问分布先有意义（更多模拟/更长的自对弈训练量，
或者让 actor 先通过"模仿 AB 的着法"得到一个非随机的起点）。价值头已经把"AB 搜三层"
的信息搬进来了，只要先验不再是噪声，这份信息才会体现到选点上。

### 7.8 Step 3：行为克隆预训练 actor —— **当前最有效的杠杆**（端到端 5.3×）

Step 2 的结论是"价值头变准了但选点没动，瓶颈在先验"。于是这一步把 actor 从随机起点拉到
"像 AB 一样选点"：用 `bench_ppo_distill --actor=1` 生成 AB 深度 3 的选点当标签
（`test_reward_diag` 同款的 `stepToActionIdx` 换取规范视角下的动作下标），再做交叉熵训练
（只更新 actor）。

信号层（1500 局面 / 1200 训练 + 300 留出）：

```
克隆前: prior top-1 0.0%, P(AB 着法) 0.00012 (= 8100 维均匀分布), CE 8.99
克隆后: prior top-1 4.8%(训练)/7.0%(留出), P(AB) 0.018, CE 留出 5.96
```

**端到端（探针，200 局面，AB 深度 4 参照）—— 这是关键**：

| 配置 | 完整着法一致率 | 起点一致率 |
|---|---|---|
| 未训练 | 3.0% ±1.2 | 25.5% |
| 只蒸馏价值头（Step 2） | 2.0% ±1.0 | 30.5% |
| **行为克隆(8 epoch) + 价值头蒸馏** | **16.0% ±2.6** | 32.5% |
| 行为克隆(40 epoch, lr 0.008) + 价值头蒸馏 | 10.5% ±2.2 | 19.0% |
| 行为克隆(40 epoch) @8 模拟 | 11.5% ±2.3 | 24.0% |
| 随机走法机会水平 | 3.5% | — |

三条读数：

1. **BC 把选点一致率从 3.0% 拉到 16.0%（5.3 倍，差 13% ≫ 2.6% 的标准误）** —— 端到端、
   统计上压倒性。它**证实了 Step 2 的诊断**：只换价值头（3.0%→2.0%）几乎没用，而把先验
   从随机变成"有点像 AB"就让选点一致率翻了几倍。
2. **注意放大效应**：先验本身的 top-1 只有 **4.8%**（几乎还在随机水平 2.5% 附近），但
   MCTS 把它放大成了 **16%** 的选点一致率 —— 搜索确实在"放大先验"。这也补上了前面
   "多搜索无效"那句的边界：**先验一变，搜索立刻就有用了**。
3. **加步数/加学习率反而更差**（40 epoch、lr 0.008：一致率 16.0%→10.5%，prior top-1
   4.8%→3.8%，留出 CE 5.96→6.31，而训练 CE 只有 4.885）—— **train/留出 CE 差 1.43 nats
   就是过拟合的量化证据**：训练集只有 1200 条、每 epoch 18 步，40 epoch 全在同一批数据上转。
   所以 BC 的瓶颈**不是步数，是数据量**（标注 1 个局面只要 18 ms，10⁴~10⁵ 局面只需 5~30 分钟，
   完全可负担）。"加步数"这个显而易见的杠杆被实测排除了。

**边界（必须记住）**：一致率上升 = "更像 AB"，不是"棋力更强"；而且 BC 的上限就是被模仿者
的水平（AB 深度 3）。它是**课程的起点**，不是终点。用它之后"与 AB 的一致率"不再是独立的
棋力证据 —— 那时参照要换成更深的 AB（`--depth=5`）。

### 7.9 Step 3b：加数据 —— BC 的 scaling 被证实，"加步数"被排除

§7.8 的读数指向"瓶颈是数据量而不是步数"，于是把标注局面从 1500 加到 **20000**（标注
371.8 s，18.6 ms/局面；训练 680.6 s）：

| 配置 | prior top-1（留出） | P(AB 着法) | CE 留出 | 探针一致率（对 AB 深度 4） | 起点一致率 |
|---|---|---|---|---|---|
| 克隆前 | 0.0% | 0.00012 | 8.995 | 3.0% ±1.2 | 25.5% |
| BC 1500 局面（8 epoch） | 7.0% | 0.018 | 5.960 | 16.0% ±2.6 | 32.5% |
| BC 40 epoch（1500 局面，lr 0.008） | 3.3% | 0.020 | 6.312 | 10.5% ±2.2 | 19.0% |
| **BC 20000 局面（8 epoch）** | **33.6%** | **0.192** | **3.492** | **28.0% ±3.2** | **52.5%** |
| 随机走法机会水平 | — | — | — | 3.5% | — |

三条结论：

1. **数据 ×13 ⇒ prior top-1 ×4.8（7.0%→33.6%）、CE 5.96→3.49、探针一致率 16.0%→28.0%。**
   而"加步数"那一行（40 epoch）**更差** —— 两个方向对照，把"步数"这个杠杆干净地排除了。
2. **过拟合消失了**：1500 局面时 train/留出 CE 差 **1.43 nats**（明显过拟合），20000 局面时
   只差 **0.37 nats** ⇒ 现在落在**数据受限**区间，继续加数据应当还能涨（10⁵ 局面约 31 分钟标注，
   完全可负担）。这条是本轮唯一一个"有明确 scaling 曲线、且下一个杠杆已知"的结果。
3. **一个必须小心的口径**：prior top-1 33.6% 是**对 AB 深度 3**（BC 的训练目标）量的，而探针
   28.0% 是**对 AB 深度 4**（更深、且不是训练目标）量的。也就是说：策略头在"较易的参照"
   上命中 33.6%，而"先验 + 搜索"在**更难的参照**上命中 28.0% —— 搜索没有把克隆到的先验弄坏，
   而且它**迁移到了更深的参照**上。

### 7.10 代理指标 vs 目标：一致率 9 倍，胜率没动（本轮最重要的一个负面结果）

用 BC20k 的权重打了一场等时间对局：

```
BC20k vs ABAgent(深度 4), 等时间 20 局 (每步 565 次模拟, 140 ms):
  PPO 0 胜 / AB 19 胜 / 1 和 = 得分率 2.5%, 平均 33.9 手
```

对照未训练时的 5.0%（0 胜 18 负 2 和）—— **2.5% 与 5.0% 同在 ±5% 的噪声带内**。

也就是说：

| | 未训练 | BC 1500 | BC 20000 |
|---|---|---|---|
| 探针一致率（代理指标） | 3.0% | 16.0% | **28.0%** |
| 对 AB 深度 4 的得分率（目标） | 5.0% | — | **2.5%** |

**代理指标涨了 9 倍，目标一动没动。** 这正是 §7.6 里那条边界警告的实证 —— 而且它的解释
是清楚的、可操作的：

1. **28% 的一致率意味着 72% 的着法与 AB 不同**。象棋是尖锐的战术博弈，一手棋下错就掉子/
   被杀，所以"三成时候像强手"远远不等于"像强手那样下棋"。
2. **BC 的上限就是被模仿者**：模仿的是 AB **深度 3**，而要战胜的是 AB **深度 4** ——
   目标本身就比对手弱，再加上模仿只有 33% 的命中率。
3. 蒸馏来的价值头（也是 depth 3 的分数）**补不上剩下的六七成着法**。

**因此下一步的杠杆不再是"把先验变得更像 AB"，而是"让整个系统的上限高于 AB 深度 4"。**
三条具体路径（按可负担程度排）：

1. **换更强的老师做 BC**：AB 深度 4（就是对手本身）。代价是"与深度 4 的一致率"再次失去
   独立性 —— 届时的验证必须换成**深度 5 的小样本**（10.9 s/步，只够跑几十个局面）或
   长局数的对局。AB 深度 5 直接做 2 万局面的标注不现实（约 60 小时）。
2. **让搜索超过先验**：现在搜索基本在"复现先验"（28% vs 33.6%）。要让 MCTS 真的改进
   策略，需要更准的**价值**（现在的价值头只是 depth 3 的复制品）+ 更多模拟（带宽受限，
   见 §17.6 的访存瓶颈）。
3. **投入 RL 自对弈预算**：以 BC 权重为起点，跑 10⁴~10⁵ 局（本机 0.81 局/s ⇒ 3.5 小时～
   1.5 天），并用探针按对数间隔监测 —— 这是唯一可能超过"老师上限"的路径。

### 7.11 Step 3c：换更强的老师（路径 1）—— 受控对照

§7.10 的结论是"BC 的上限就是被模仿者"，所以这一步换老师：**AB 深度 4**（就是对手本身）。
为了让"老师更强"这个变量可控，同时跑一个**同数据量、同超参**的深度 3 对照 —— 否则分不清
是"老师变强"还是"数据变多"。

代价上的取舍（如实记录）：深度 4 的标注成本约是深度 3 的 9 倍（15.1 ms/局面 → 约 170 ms/局面），
所以 2 万局面在深度 4 上要接近一小时，本次把规模降到 **8000 局面**，用"同数据量对照"来隔离
老师强度这一个变量。

| 配置（8000 局面，8 epoch，lr 0.002） | prior top-1（留出） | P(AB 着法) | CE 留出 |
|---|---|---|---|
| 老师 = AB 深度 3（对照） | **32.0%** | 0.1702 | 3.893 |
| 老师 = AB 深度 4（处理） | **28.4%** | 0.1358 | 3.805 |

**受控对照的结论是反直觉的：换更强的老师并没有提升"克隆精度"**（32.0% → 28.4%，差 3.6%，
约 3 倍标准误 ⇒ 显著）。解释：深度 4 的选点分布更"尖锐"（搜索找到了更多不显眼的好着），
在同样容量/数据量下更难被拟合 —— "模仿更强的棋手在监督学习意义上是更难的任务"。

端到端（**用非老师参照**，避免循环）：

| 参照 | 未训练 | bc8k_d3（老师 d3） | bc8k_d4（老师 d4） |
|---|---|---|---|
| 探针对 **AB 深度 5**（25 局面）完整一致率 | 8.0% ±5.4 | — | **32.0% ±9.3** |
| 同上，起点一致率 | 28.0% | — | **48.0%** |
| 对 **AB 深度 4** 等时间 20 局得分率 | 5.0% | 0.0% | **5.0%** |
| 同上，平均手数 | 48.8 / 40.8 | 28.0 | **43.0** |

两条读数：

1. **独立参照（深度 5）上，换老师的版本确实最好**：完整一致率 8.0% → **32.0%**（4 倍；
   25 个局面样本的标准误 ±9.3%，属于"方向明确但样本偏少"），起点一致率 28% → 48%。
   也就是说**"更强的老师"确实提升了模仿的可迁移性**。
2. **但仍然没有转化成胜率**：对 AB 深度 4 的等时间 20 局里 0 胜、得分率 5.0%（与未训练
   同分，都落在 ±5% 噪声带内）。唯一方向一致的改善是**平均手数**：bc8k_d4 能撑到
   **43.0 手**，而 bc8k_d3 只有 28.0 手、BC20k@d3 是 33.9 手 —— 至少它不再"更快被将死"。

**综合 7.8–7.11 的结论**：这一整条"把先验做得更像 AB"的路线，在**代理指标**上一路走高
（一致率 3% → 16% → 28% → 对更深参照 32%），但**目标指标（胜率）一次都没动**。原因在
§7.10 已经定性：模仿精度三成左右 + 老师上限就是对手水平 ⇒ 不可能越过对手。所以下一步的
杠杆只剩两条，且都需要**小时级**而不是分钟级的预算：

* **让搜索超过先验**（Path 2）：现在搜索基本在复现先验；要它改进策略，需要更准的价值
  （现在的价值头只是老师的复制品）与更多模拟（后者受访存带宽限制，见 `agents_design.md` §17.6）。
* **投入 RL 自对弈预算**（Path 3）：以 BC 权重为起点，跑 10⁴~10⁵ 局（本机 0.81 局/s ⇒
  3.5 小时~1.5 天），用探针按对数间隔监测 —— **这是唯一可能超过"老师上限"的路径**。

### 7.13 clipGrad 的实验：**它既不害也不帮忙，我的假设被否掉**

**问题**：`Optimize::RMSProp` 在 `clipGrad=true`（默认）时做的是 `dw /= ‖dw‖₂ + 1e-8` ——
这是**把每层梯度归一化成单位长度**，不是"超过阈值才缩"。于是每参数位移与梯度量级无关
（≈ lr），整层位移 ∝ lr·√n，等价于"signSGD + RMSProp 缩放"。它在 snakeAI（稠密奖励 +
bootstrap 尖峰）里是有效的信赖域。我据此提出假设：**在平稳的监督/AlphaZero 交叉熵上，
梯度变小时步长仍是满幅 ⇒ 会在最优点附近来回撞**，并引用了 BC 那一轮"留出 CE 先降后升"
（5.492 → 5.959）作为迹象。

**实验**（`--no-clip` 开关；1500 局面、8 epoch、只训 actor；2×2 网格排除"其实是 lr 太大"）：

| 组 | lr | clipGrad | 留出 CE | prior top-1（留出） | P(AB) | 耗时 |
|---|---|---|---|---|---|---|
| A | 0.002 | **on** | 5.545 | 12.7% | 0.0225 | 39.2 s |
| B | 0.0005 | **on** | 5.480 | 5.7% | 0.0166 | 39.0 s |
| C | 0.002 | **off** | 5.550 | 13.7% | 0.0249 | 40.1 s |
| D | 0.0005 | **off** | 5.488 | 5.7% | 0.0171 | 40.1 s |

**结论（老实说）**：

1. **clipGrad 在平稳的监督任务上影响微乎其微**：A vs C（同 lr）CE 5.545 vs 5.550、
   top-1 12.7% vs 13.7%、P(AB) 0.0225 vs 0.0249；B vs D 几乎完全一致。差别都在 300 个
   留出样本的标准误（约 2%）以内。**我的"它有害"假设没有被证实，予以撤回。**
2. **"CE 先降后升"那个迹象另有原因**：这一轮（`--epochs=0`，不先做 critic 蒸馏）的 CE
   是**单调下降**（5.862 → 5.484），而上一轮是"先蒸馏 critic、再 BC actor"。两轮唯一
   差别是**批次顺序**（同一个 `std::mt19937` 的 shuffle 状态被前一段推进了）——
   144 次更新（18 步/epoch × 8）本来就短，轨迹形状对批序极敏感。所以那条曲线是噪声，
   不是优化器不收敛的证据。
3. **顺带撤回另一个估计**："`norm2()` 多跑一遍参数、clipGrad 会多花 15~20% 单步时间"
   —— 实测 39.2 s(ON) vs 40.1 s(OFF)，**没有差别**（在含前向/反向的整轮里被淹没）。
4. **这一轮真正的杠杆是 lr 与数据量，不是 clipGrad**：lr 0.002 的 top-1 12.7% 明显高于
   lr 0.0005 的 5.7%（低 lr 更稳但学得慢）；而数据量的影响更大（2 万局面那一轮
   CE 3.49 / top-1 33.6%，见 §7.9）。

**决定：保留默认（`clipGrad=true`）不改。** 理由：(a) 本实验证明它在平稳任务上无害；
(b) snakeAI 的那条理由（对 bootstrap 尖峰的信赖域）在我们的 **critic** 上依然成立 ——
而且历史上我们的价值目标确实出现过 ±100 量级的尖峰（Phase 1 之前）；
(c) 没有可测的收益也没有可测的代价，改默认值属于没有证据支持的改动。

## 8. Phase 6 — 按外部建议补的四项（本轮的收尾）

参考一份外部的奖励函数设计建议（AlphaZero vs 纯 RL 两条路线 + PBRS + 特征表 + 防崩细节），
逐条评估后执行了其中最对症的四项。**建议里整体正确的部分**（PBRS 定理、势能尺度纪律、
self-play 视角翻转、规则终止进环境）我们已经在做；下面只记**新做的**与**纠正的**。

### 8.1 终局口径统一（建议里最对症的一条）

建议说"三次重复判和要给 `done=True, reward=0`"。我们引擎里 `Chess::isDraw()` /
`getResult()` **已经实现了**三次重复与 60 回合判和，但 **rollout 不用它** ——
`agentrollout.hpp` 用的是 `isGameOver()`，而它**只认"将不在了"**。诊断当场量出这个差别：

```
60 回合无吃子: getResult=3 (DRAW), isGameOver=2 (NONE)
```

也就是"判和"在 rollout 里根本不终止；加上"被将死"也不终止，两者合起来就是"截断处一律
给 0 ⇒ 价值目标没有信号"（实测占比一度 **0.0%**）。已修：

* `chess.h` 新增 `outcomeForMover(chessResult, moverColor)` —— 把 `getResult()` 的结果换算成
  走子方视角的 ±1/0（与 `REWARD_TERMINAL` 同源），终局口径**只有这一处**；
* `agentrollout.hpp` 与 `trainSelfPlay` / `warmupFromCurrent` 的终局判定全部改走
  `chess.getResult(chess.sideToMove)`，替掉 `isGameOver()`。
  工程里原先并存的**三套终局定义**（isGameOver / getResult / "没有合法走法"分支）就此统一。

### 8.2 势能强度 α（退火钩子）

`PPOMCTSAgent::shapingAlpha`：实际加进奖励的是 `α·(Φ(s_i) + γ·Φ(s_{i+1}))`。因为 `αΦ`
仍然是**状态函数**，**任何 α 都保持策略不变性**，所以"先弱塑形、后强塑形"可以连续过渡 ——
这比外部建议里的"先只给材质 → 再换 PST → 最后切纯终端"三段硬切稳得多（换奖励函数会让已经
拟合好的价值函数瞬间失效）。边界项也按 α 缩放（否则 α<1 时平移性又被破坏）。
诊断断言：**α=0 时塑形是恒等变换**。

### 8.3 材质去重账（外部建议的精神指向了我们自己的一个真实缺陷）

建议说"永远只传差分，不把 φ(s) 当 reward 累加"。而我们的实现里材质**同时出现在两处**：
`stepReward()` 显式给 `0.1×value`，而 `Φ = tanh(evaluatePositional/2)` 里也含材质。
PBRS 的不变性**只覆盖势能那一半**，显式材质项是不受保护的额外稠密奖励，会实打实把策略推向
"吃子优先"。新增 `PPOMCTSAgent::materialRewardEnabled` 作为对照开关（关掉后显式奖励只剩
每步代价，材质完全交给 Φ）。诊断断言：`吃子奖励 0.0290 → -0.0010（= 每步代价）`。

### 8.4 威胁项加回，但只进 Φ 这一路

外部建议里的"被攻击的敌子价值 × 攻击次数 / 己方被盯子减分"是有用的项，但我在 Phase 5 为了
**AB 的搜索深度**把它们砍掉了（实测并进 `evaluate()` 会让一次评估 0.100→0.650 µs、depth-4
单步 107→1269 ms）。现在明确了分工：`evaluate()` 只给 AB/EVAB 的叶子评估（保持廉价），
`evaluatePositional()` 只给 RL 的势能 Φ（**每手只算 2 次，成本无关**），于是把两项加回后者：

* **多重攻击将**（第二个攻击者权重更高，0.09/个）；
* **悬子**（被对方攻击且无己方子保护 → 按 `0.25 × value` 扣分）。**这才是"送子狂魔"的正解**：
  送子在象棋里是**合法**的（照面/自将才是非法的，引擎已经禁掉），只能靠评估函数把它标出来。

实测：`evaluatePositional = -0.1490` vs `evaluate = -0.0900`（局面项贡献 −0.0590），
而 **AB 的 depth-4 单步仍是 101 ms** —— 威胁项没有碰到 AB 的热路径。

### 8.5 外部建议里被纠正的三处

1. **"有 MCTS 就只给终端奖励（中间 step reward = 0）"**：我们有直接实测反例 —— 量纲摆正后
   截断 rollout 的目标 `|target|>0.1` 占比是 **0.0%**。AlphaZero 的中途 0 奖励成立的前提是
   **回合打到终局**，而我们的 rollout 截断在 64 手、自对弈截断在 120 手。需要的是**自举**，
   不是"把中间奖励设成 0"（加上自举+Φ 后占比升到 55–63%）。
2. **"PBRS 会让 PPO 学会左右横跳刷差分"**：定理上说反了 —— `γΦ'−Φ` 在任意闭环上望远镜相消
   （实测一局随机棋里 Quiet 着法 6/6 改变势能，但"远离再回来"净额为 0），**刷不出来**。
   重复局面必须进环境的真正理由是"该局确实判和、回合该结束"，以及"截断给 0 是错的"。
3. **公式缺边界项、符号也要按口径改**：建议写的 `r_terminal + γΦ(s') − Φ(s)` 在单一视角下对，
   但我们是 **negamax 逐手翻号**口径，要写成 `r + Φ(s_i) + γΦ(s_{i+1})`，而且终局常量必须平移
   `finalOutcome' = finalOutcome − Φ(落子后局面)`。漏掉边界项时"塑形 − 不塑形"会差一个
   `−Φ(s_n)`（实测 −0.02187 而正确值 0.00000）—— 这条靠数值测试抓出来，读代码看不出来。

### 8.6 验证

`test_reward_diag` 现在 **22 项检查全过**（新增 8 项覆盖本节四项改动）；全部测试可执行文件
回归通过；`evaluate()` 的单价与 `ABAgent` 的 depth-4 单步耗时**未变**（0.100 µs / 101 ms）。

## 9. 一页总结：问题 / 优化方法 / 剩余优化项

### 9.1 修掉的问题（按影响排序，都带实测数字）

| # | 问题 | 根因 | 修法 | 实测 |
|---|---|---|---|---|
| 1 | 奖励把"赢"变成次要目标 | 终局 ±1 而吃子 ×10：一方全材质 = 35.0，「吃一个車 = 赢五盘棋」 | 尺度集中到 `stone.h`：材质 0.1 / 终局 ±1 / 每步代价 −0.001 | 终局/全材质 **0.029 → 2.86**；随机棋 Σ材质/终局 **32 → 0.32** |
| 2 | 价值目标几乎全是 0（安静局面没信号） | 截断 rollout 一律传 `finalOutcome = 0`，材质是唯一稠密信号 | 自举 + 势能塑形（PBRS） | `\|target\|>0.1` 占比 **0.0% → 55–63%** |
| 3 | 训练损失曲线像低占空比脉冲 | 逐步 `trainStep`（每步 batch=1），只剩最后一条样本的损失 | 整条轨迹累积后一次 `applyGradients`，上报批平均 | 最后一条/批平均 **1.5×**；每样本便宜 **2.9×** |
| 4 | 判和/被将死**不终止** rollout | `agentrollout` 用 `isGameOver()`，它只认"将不在了" | 统一走 `getResult()` + `outcomeForMover()`（终局口径只有一处） | 实测 `getResult=DRAW` vs `isGameOver=NONE` |
| 5 | 先验没参与"展开哪个孩子" | 三个搜索入口都是 `std::rand() % untried` | `pickUntriedByPrior()` | 顺带去掉搜索里的 `std::rand()`，恢复播种可复现 |
| 6 | 局面价值并进 `evaluate()` 会把 AB 的深度吃回去 | 一次评估 0.100→0.650 µs，AB depth-4 **107→1269 ms** | 拆两档：`evaluate()`（AB 叶子）/ `evaluatePositional()`（只给 Φ） | AB depth-4 **回到 101 ms** |
| 7 | 材质**重复计账**（显式奖励 + Φ 里都有） | PBRS 的不变性只覆盖势能那一半 | `materialRewardEnabled` 开关 | 吃子奖励 **0.0290 → −0.0010** |
| 8 | 势能塑形漏了**边界项** | 终局常量没跟着平移 | `finalOutcome' = finalOutcome − Φ(末局面)`，α 也参与缩放 | 平移性差 **−0.02187 → 0.00000** |
| 9 | 对局协议分辨力不足（±5%） | 20 局、每局 ±1 的二值结果 | 选点一致率探针（SE≈1–2%，局面集固定 ⇒ 配对比较） | 功效检验能分辨 **5.5%** 的变化 |

### 9.2 用到的优化方法（可复用清单）

* **奖励**：PBRS（本工程是 negamax 翻号口径，形式为 `r + Φ(s_i) + γΦ(s_{i+1})`）+ 自举 + 每步代价 + **尺度不变量断言**
* **学习**：批平均损失上报、梯度累积、回放池 + 稀疏策略目标、α 退火钩子
* **评估**：**两档评估**（按调用频率分工：叶子路径要廉价、势能路径可以贵）、威胁/空间/悬子项
* **搜索**：展开按先验；并量化了"代理指标"与"目标指标"的差别
* **特征**：左右镜像增广（精确验证到 0 格不一致）
* **造尺子**（这一轮最重要的方法论产出）：诊断 bench + 配对探针 + **功效检验**（先证明尺子能分辨变化，再用它下结论）；以及"先量噪声带再比差异"

### 9.3 剩余优化项（按**实测出的瓶颈**排序，而不是按直觉）

**A. 唯一可能越过"老师上限"的路径（小时级预算）**
1. **投入 RL 自对弈预算**：以 BC 权重为起点跑 10⁴~10⁵ 局（本机 0.81 局/s ⇒ **3.5 小时~1.5 天**），用探针按对数间隔监测。§7.10/7.11 已证明"继续改进先验的模仿度"到顶了。

**B. 让搜索真正超过先验（现在搜索基本在复现先验）**
2. 更准的**价值**：现在的价值头只是老师的复制品（Step 2 实测：MSE 降 4.2 倍但选点没动）
3. 更多**模拟**：受访存带宽限制（策略头 2.07 MB/模拟，聚合 ~15 GB/s 饱和，见 `agents_design.md` §17.6）
4. **策略头只算合法列**：估算每模拟权重流量 3.0 MB → ~0.9 MB（约 3×），推理语义等价、不重训
5. **置换表 + 子树复用**：PPO+MCTS 至今没有 TT，而且每 ply `nodes.clear()`
6. 静止搜索、top-K/渐进放宽、预算调度

**C. 训练流程工程化**
7. 三条训练路径统一（`trainSelfPlay` / `exploreAndTrain` / MT worker 仍是三份近似重复实现）
8. **评测/训练分离**：对弈时默认开着在线训练，会污染"谁更强"的结论
9. 优势加权：在线路径的 one-hot 目标在模仿自己的探索噪声（自对弈路径用访问分布，不受影响）
10. α 退火的**判据**要用可测指标（held-out 上 critic vs MC 回报的拟合质量），而不是拍步数

**D. 特征 / 评估（实测收益最小，放最后）**
11. "我攻击的格"平面（编码里有"被对方攻击"却没有"我攻击的格"）
12. 相位相关 PST（开局/中局/残局插值）、子力比例校准（車相对被低估约 35%）

**E. 明确不建议做（已给理由）**
* 外部引擎蒸馏（Stockfish/Pikafish）：全仓**无 FEN 接口**，要另写局面交换桥，且 GPL；本地 AB 蒸馏已实现，实测收益有限
* 常驻 aux loss：我们的 actor 损失**不含 V**，加它只是把 Φ 的影子拉长
